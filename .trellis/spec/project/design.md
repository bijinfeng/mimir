# mimir 设计规范

本文件是当前界面的视觉与交互契约。颜色、字体和断点以 `packages/renderer/src/theme/tokens.ts`、`customToken.ts` 的实现为准；改动契约时同时更新本文件。改版前的详细理由留在 `.trellis/tasks/archive/2026-10/10-10-visual-redesign/research/design-before-redesign.md`，不再作为现行规范。

## 0. 原则

### 0.1 内容是主角

工作区采用用户于 2026-10-17 批准的语雀风格适配：白灰表面、中性选中、绿色主操作，阅读和编辑区把空间给内容。本次视觉方向取代此前 Obsidian 冷灰蓝方案；Obsidian 保留为连续工作区的布局对照。知识库仍是文件工作台，不用无关统计或装饰卡片填补留白。研究和批准稿见 `.trellis/tasks/10-16-yuque-design-research/`；无法访问的语雀登录态、编辑器和深色界面属于 Mimir 适配，不能宣称精确复刻。

### 0.2 状态必须可见

保存、检索、模型连接、备份和失败都要给出真实状态与可执行的下一步。状态色承载信息，不承担装饰。失败类型有各自的出路，用户主动停止对话不显示为错误。

### 0.3 文案服务用户任务

界面面向普通用户。编辑意图优先通过选择、当前值、按钮状态、上下文工具和即时画布反馈表达，不在常态界面放操作教程段落。设置页隐藏 RRF、分词器、数据库类型、路径、环境变量和调试输出等实现细节。必要的风险提示与操作结果要保留。文档助手以可点击的快捷提问引导空态，不常驻快速上手清单；工具就绪时不展示工具数量或完整清单，AI 修订保留操作控件；模型缺失或能力读取失败时给出设置或重试入口。

### 0.4 全局紧凑密度

整个产品采用紧凑的工作台密度。页面、侧栏、列表、菜单、工具栏、设置和弹窗都应让相关信息与操作靠近，减少无意义留白、重复说明和多层容器。紧凑不靠缩小文字或挤压可点击区域实现：名称、状态、当前值和主操作必须容易扫读、辨认与使用。长篇阅读和编辑画布按内容本身需要保留舒适行距与工作空间。

## 1. 组件基础

Ant Design 6 承担按钮、表单、菜单、弹窗、反馈等控件的键盘、焦点、校验和状态；`antd-style` 承担项目布局和视觉规则。导航与产品操作图标用 `lucide-react`；知识库中的文件类型图标使用本地 Material Symbols Rounded 素材，品牌标识及被编辑文档自身的图像不受此约束。Office 包通过 `EditorShell` 和现有命令槽组织界面，不能为了仿 Ribbon 画不可用命令。

主题只由 `MimirProvider` 注入。Chat 通过 `ChatThemeBridge`、Office 通过 `editor-theme-bridge` 继承宿主 token，不各建一套主题。

## 2. 字体与形状

字体栈只在 `tokens.ts` 的 `FONT_SANS` / `FONT_MONO` 定义；中文用 PingFang SC、Hiragino Sans GB、Microsoft YaHei 兜底。UI 与连续阅读分开：UI 14px，阅读 15px、行高 1.9（28.5px）。

### 2.1 字号语义阶梯

`FONT_SIZE` 定义语义阶梯，每一档对应一个**明确的角色**，不是「差不多大就用它」：

| 档位 | 值 | 语义角色 | 适用场景 |
| --- | --- | --- | --- |
| `display` | 28px | 文档与知识库标题 | 阅读画布 H1、知识库身份标题 |
| `settingsTitle` | 22px | 设置标题 | 设置页与供应商表单 H1 |
| `pageTitle` | 19px | 页面标题 | 正文 H2、其他页面标题 |
| `section` | 16px | 小节标题 | 正文 H3、空态标题 |
| `body` | 14px | 界面正文 | 按钮、输入、对话正文 |
| `reading` | 15px | 连续阅读正文 | Markdown 阅读与笔记编辑正文，配合 `READING_LINE_HEIGHT` |
| `item` | 13.5px | 列表项标题 | 导航项、列表项标题（被扫读的内容） |
| `excerpt` | 13px | 摘要内容 | 列表摘要、表格、代码 |
| `note` | 12.5px | 次级说明 | 引用片段、检索过程、辅助说明 |
| `meta` | 12px | 元信息 | 时间戳、路径、命令行、计数 |
| `badge` | 11.5px | 徽标文字 | 状态徽标、标签（有底色衬托，允许更小） |

**使用原则**：
- 加新样式时先找角色，找不到再考虑要不要加档
- 同一个角色在不同地方必须使用同一档字号（如：所有元信息统一用 `meta` 12px）
- 最小档（`badge` 11.5px）只用于有底色辅助的徽标，不放连续阅读内容
- 字号不随外观变：深色下不是「字变大」，只是底色变了

**半档差值的理由**：
采用 0.5px 级差而非整数档（12/14/16），是因为界面信息密度高（列表项里同时有标题、摘要、徽标、计数）。整数档在相邻层级之间跳得太大——摘要用 13px、元信息用 12px 时，二者的视觉层级在扫读时更清晰。

全局圆角种子为 6px。大面积工作面主要靠表面明度和细边界分隔；圆角重点留给控件、选中行和浮层。Office 纸张有轻微层级，但不能成为多层嵌套卡片。

## 3. 颜色

### 3.1 品牌与表面

浅深主按钮填充均为 `#00834d`，hover `#007846`、pressed `#006b3e`；强调文字浅色 `#007a45`、深色 `#6bdaa5`，深色由 `darkCalibration` 校准。绿色用于主操作、链接、焦点及真实语义状态；导航当前位置用中性灰底、正文色与字重。成功、警告、错误、信息维持各自色对。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 布局 / 主内容底 | `#ffffff` | `#18191a` |
| 导航 / 列表 / 大纲底 | `#f7f8f8` | `#1f2022` |
| 卡片 / 输入底 | `#ffffff` | `#202225` |
| 浮层底 | `#ffffff` | `#26282b` |
| 导航选中底 | `#eff0f0` | `#303235` |
| 主文字 | `#262626` | `#eceeef` |
| 次文字 | `#595959` | `#b3b6bb` |
| 元信息 | `#6b6b6b` | `#969ba2` |
| 装饰性分隔线 | `#e8e8e8` | `#3b3e43` |
| 未选复选 / 单选等关键边界 | `#8a8a8a` | `#686e76` |
| 字段默认边界 | `#e7e9e8` | `#454b47` |
| 字段悬停边界 | `#bfc5c1` | `#66736c` |
| 字段聚焦边界 | `#00a35f` | `#50c28f` |
| 字段警告边界（含 hover / focus） | `#c47a00` | 保留 antd 深色语义值 |

`customToken.ts` 定义导航、列表、悬停、代码与热力图色阶；`navSelectedBg` / `navSelectedText` 表达导航当前位置，`surfaceContent` 表达主工作面，`focusRing` 表达键盘焦点。不能为导航改灰而覆盖绿色 `colorPrimaryBg`：引用、Office 按下态等仍需品牌语义浅底。Office 的 `--me-*` 缺失时回退到当前主题，不能残留旧蓝紫品牌色；用户文档内容色不随应用换色。

### 3.2 文字与填充

`colorPrimary` 用于填充与选中背景，强调文字用 `colorLink` / `colorPrimaryText`。悬停和按下的链接文字都需保持可读。浅深外观均以 antd 实际派生 token 为准，由 `theme/design.test.ts` 守护文本、选中态、hover 与焦点的对比度。

### 3.3 文字阶

正文、次要说明、元信息、占位/禁用依次取 `colorText`、`colorTextSecondary`、`colorTextTertiary`、`colorTextQuaternary`。占位不能承载完成任务所必需的信息。

### 3.4 语义色

状态文字与同语义浅底成对使用；不要把种子色直接当状态文字。源于 antd 的种子色保持派生规则，必要时覆盖最终叶子 token。

### 3.5 强调色

按钮填充与可点击文字分属不同角色。导航当前项从 `navSelected*` 取中性色，Tabs、编辑器按下态和引用从各自强调角色取色；不能靠颜色变化独自表达选中。

### 3.6 表面与热力图

布局、辅助面、卡片和浮层按角色分层。浅色主面、卡片和浮层可以同为白色，通过边界与实际浮起的阴影区别；导航和列表可共用辅助面。不再要求五层颜色各异。悬停底在对应表面必须可见，具体组合由实际 token 测试守护。

**表面层级**（从低到高）：
1. **布局底** (`colorBgLayout`) — 最底层的工作区背景
2. **导航底** (`tintNav`) — 左侧导航栏
3. **列表底** (`tintList`) — 中栏列表、目录树
4. **容器底** (`colorBgContainer`) — 卡片和输入；主内容使用 `surfaceContent`
5. **浮层底** (`colorBgElevated`) — 弹窗、下拉菜单、工具提示

**悬停反馈**：
- `tintHover` 用于列表项/引用块的悬停底色
- 必须与所在表面（如 `tintList`）拉开可见的对比度差异（≥1.08:1）
- 受 `design.test.ts` 守护，不把前一版冷灰蓝的比值作为新配色的证据

**热力图色阶**：
热力图的四档色阶取 `customToken`（`heatL1` ~ `heatL4`），空格与第一档要有可见差异（≥1.1:1）；”未上报”不能画作零用量。浅色取绿色四档由浅到深，深色取绿色四档由暗到亮（与空格子的方向一致）。

### 3.7 徽标

次要按钮边界使用装饰角色；字段默认边界使用轻灰，字段聚焦与独立关键控件边界按 §3.8 守护。来源类型是文档属性，不以高饱和徽标填满列表。状态徽标只标识偏离常态或需要用户关注的状态。

### 3.8 深色

深色是独立校准的值，不是浅色取反。两套外观分别守住普通文字 ≥4.5:1、正文 ≥7:1、字段聚焦与独立关键控件边界 ≥3:1；不以深浅每一项比值必须相同作为设计目标。导航选中文字、链接、焦点环、Office 工具栏及编辑画布需逐项检查；`design.test.ts` 以真实 provider 的派生结果验证。

## 4. 内容排版

### 4.1 字体栈

界面与编辑器共享系统 UI 字体和中文兜底；代码及文件路径使用 `FONT_MONO`。

### 4.2 字号

页面标题、分区标题、正文、元信息按 `FONT_SIZE` 角色取值。窄屏先调整空间与折行，不靠缩小正文解决布局问题。

### 4.3 正文

Markdown 正文行宽上限 `CONTENT_WIDTH = 760px`，是阅读 measure，不是所有页面的统一容器宽度。Office 编辑器工具区横贯顶部，纸张或画布位于其下；各格式保留本身的页面/网格/幻灯片结构。

## 5. 布局

### 5.1 间距

以 4 / 8 / 16 / 24 / 32px 为基本节奏。标题、操作、内容分组要靠位置与空白建立层级，不靠重复边框。所有工作台区域优先使用满足识别与操作的最小合理间距；加大间距必须有明确的阅读、触控或分组理由。少量操作不应被大面积留白撑成卡片。

### 5.2 圆角

控件继承 antd 6px 基础圆角；大区块保持平整。选中行、输入区和浮层可有明确圆角。

### 5.3 阴影

层级优先靠底色与细边界。阴影用于确实浮在内容之上的菜单、弹窗和画布纸张；文档纸张比浮层更轻。

### 5.4 尺寸

| 区域 | 当前约束 |
| --- | --- |
| 工作区导航 | 展开约 256px 单一侧栏；折叠 / 窄屏约 52px；窄屏展开约 280px 覆盖层 |
| 设置分区栏 | 宽屏 176px，内容列最大 760px；内容容器 ≤620px 时字段与模型行堆叠 |
| 知识库工作台 | 最多约 1080px，文件列表优先 |
| 文档正文 | 阅读 measure 最多 760px；可选大纲 196px |
| 对话列 | 内容上限约 850px；文档阅读助手 400px |
| 桌面标题栏 | 44px，真实窗口控件只由桌面壳绘制 |

应用外壳在 `_app.tsx`；设置分区布局在 `settings.style.ts`。编辑器的工具区与正文滚动区由 Office shell 管理。

### 5.5 断点

`NAV_NARROW_QUERY` 唯一定义 880px 窄屏断点，CSS 与 `matchMedia` 共用。窄屏保留 52px 功能栏，当前任务侧栏改为按需覆盖；设置分区改 Select，文档大纲让出正文，阅读助手占满可用主区。宽屏上阅读助手展开时也收起大纲，避免 400px 助手与 196px 大纲并排挤窄正文。移动端在此阶段只保证现有任务可达与无横向溢出。

## 6. 动效

动效按反馈层级使用短时长，并尊重 `prefers-reduced-motion`。位移和透明度优先；不要通过动画掩盖控件延迟或保存状态。

## 7. 组件约定

### 7.1 图标

Lucide 线性图标：常规按钮 16px，导航/列表约 18px，独立入口约 20px；同层级保持一致描边。纯图标按钮有可见焦点、Tooltip 与 `aria-label`，装饰图标 `aria-hidden`。不用 emoji 当产品操作图标。

### 7.2 焦点

键盘路径在浅深外观均需可见。Outlined 字段（Input、Password、Search、TextArea、InputNumber、Select / Cascader）以单层 1px 聚焦边界表达焦点，不叠加外扩阴影；hover / focus / 输入中不改变盒尺寸。错误 / 警告保持语义边界与文字；浅色字段警告边界的默认 / hover / focus 局部校准为 `#c47a00`，输入底上 ≥3:1，深色沿用原语义值。此校准不改变全局警告文字 / 背景，禁用保持原有不可交互状态。无边框字段保留 antd 的 `:focus-visible` 轮廓，自定义按钮及密码眼睛等独立操作保留自身焦点环，不全局清除 outline。Office 和 Chat 子包继承宿主的焦点色。

用户于 2026-10-17 批准的语雀字段适配采用轻默认边界，浅色白底约 1.22:1；这是从旧“全部字段边界 ≥3:1”中分离出的明确外观取舍，不宣称默认字段边界满足非文本 AA。聚焦边界在输入底上仍 ≥3:1（浅色约 3.28:1、深色约 7.18:1），复选 / 单选等独立关键边界及文字原有门槛保持。语雀公开登录页的单层细边机制有实测依据，hover、深色及语义态是 Mimir 适配；证据见 `.trellis/tasks/10-17-form-controls-polish/research/form-controls-study.md`。

### 7.3 可点击元素

按语义使用 button/link，确保 hover、按下、禁用和键盘状态真实。禁用的 Office 命令说明原因，不显示假操作。

### 7.4 禁用态

禁用态不能是唯一的状态说明；若用户需要知道如何启用，给出短说明或可操作入口。

### 7.5 Ant Design 6

组件使用当前 v6 API；定制优先走全局/组件 token 与语义部位。避免页面散写 `.ant-*` 字面色。内层 `ConfigProvider` 不传另一套 theme。

### 7.6 高度链

`AntApp` 与应用壳都需维持 `height: 100%` / `min-height: 0`，浏览器无桌面标题栏时主区也必须填满视口。

## 8. 页面形态

### 8.1 导航

展开态为单一约 256px 侧栏，品牌、搜索、新对话、知识库、收集、历史、库树、最近笔记和账号 / 设置沿同一列组织。折叠态约 52px，保留主要图标入口和折叠偏好。窄屏展开约 280px 覆盖层，X、遮罩、Escape 可关闭，焦点进入并在关闭后回到触发点，关闭后无残留滚动锁或焦点陷阱。临时窄屏状态不覆盖用户持久化折叠偏好。
展开导航的账号与设置各占一行，普通导航行高36px；窄屏或粗指针目标至少44px，图标不随之放大。搜索显示平台快捷键提示。未保存离开确认获准后才关闭导航，取消时保留抽屉和原操作焦点。功能栏底部的账号菜单以约 212px 宽、32px 操作行为基准；账号身份占一条紧凑信息行，身份头像、常用操作与登出图标沿同一左侧对齐线，分组不增加横向缩进。主题保留二级选择，登出与其他操作以细分隔线区分。窄屏时菜单宽度不超过视口。

### 8.2 知识库

知识库标题使用28px，描述与卡片名称使用14px、卡片名称约500字重；窄屏长知识库名称允许折行。就绪状态可用12px绿色文字，失败等异常保留徽标。页面标题、操作行、可扫读文件列表为主体；保留卡片/列表能力、目录树、拖放目标及真实状态。上传件的列表与卡片共用文件类型图形：PDF、文档、表格、演示、代码和媒体等有独立轮廓，图标内用少量主题语义色辅助识别，周围界面仍保持低对比。文件名展示当前原件后缀，长名称省略时后缀保持可见；文件卡片不再重复显示格式徽标，笔记和网页等非上传内容保留来源徽标。缺失摘要要如实显示。

### 8.3 文档

阅读面居中；笔记的唯一可编辑28px文档标题位于阅读滚动区、与正文共用760px对齐线，旁随真实更新时间。头部保留紧凑路径与真实保存状态；未保存、保存中、失败分别来自编辑与写入事实。多标题且空间足够时显示大纲。原件自带导航的格式不重复加大纲。文档助手保留范围提示、快捷提问和引用跳转，空态不显示教程式指南。

### 8.4 工具条

六种编辑器的顶部工具栏参考 Office 网页版的可见分类与命令组，具体可执行命令对照项目固定的 GenOffice 版本。常用命令在所属组内可直接发现；编辑区变窄或打开问 AI 时，分类保持可见，命令组按实际编辑区宽度从右侧逐组压缩为各自具名菜单，保留直接可见的高频控件，不把所有命令塞进总“更多”，390px窄屏下命令带不横向滚动。窄区的组按钮按实际可用宽度压缩至44–72px，并在自身范围内折行标签，命令带保持单行；若极端可用宽度小于44px×分组数，保留命令区局部滚动以确保触控与命令可达。该规则依据 2026-10-16 用户追加的样式门槛及真实 690px 中栏中长命令带裁切问题，取代旧的命令区横滚方案。组内变体可用明确命名的菜单。选择单元格、文字、对象或元素时出现对应操作和当前值；禁用命令在控件处说明原因。查找、工作表、幻灯片与单元格编辑等独立区域按格式保留。保存、撤销、重做位于分类标签左侧的固定快捷操作区，标签独立横向滚动；仅有真实编辑历史的格式启用撤销与重做。底部状态行只承载短状态、位置、数量及与当前操作相关的反馈。

所有文档共用 Markdown 笔记的头部组件和布局：48px 单行，左侧无边框的返回入口与紧凑标题，右侧为“问 AI”和更多操作；按能力增加下载原件。笔记改名入口位于阅读画布唯一标题处，头部标题仅作紧凑路径；其他格式保持紧凑标题。三栏布局中的工作区侧栏和问 AI 侧栏头部也使用同一 48px 高度，三处下边框处于同一水平线。常态不在头部铺来源、格式和日期；失败状态可显示徽标。长标题收缩，窄屏仍保持返回和动作可达。标题就地编辑使用 Ant Design `Input` 的 `underlined` 形态。头部、格式工具栏、内容区域仍为独立区域且顺序不变。笔记工具栏保留紧凑观感，但命令分类与组名可见。正文、大纲与问 AI 侧栏的列布局不随头部调整。

### 8.4.1 Office 外壳

六种格式用顶部工具区、下方画布与底部状态行。各格式命令仅展示实际支持的能力；狭窄宽度下固定快捷操作区保持可达，分类可独立滚动，命令按组压缩为具名菜单。未实现完整手动历史的格式将撤销、重做显示为禁用并在控件处说明原因，不把 Agent 单轮回退称作通用撤销。无选中状态不出现“点一个格子”等常驻教程；可能覆盖公式、原件保真受限或写入失败时，在相关上下文提示。

PDF 与 PPTX 的左侧缩略图列显示页面真实内容和页码，选中页使用清楚的边框、背景与可读的强调文字。列表与主画布分别滚动；窄编辑区可收起列表且展开入口保留。顶部保留新增入口，逐页复制、删除、上移、下移放在缩略图右键菜单，不常显逐页“更多”按钮；键盘可聚焦页面并用菜单键或 Shift+F10 打开同一菜单。菜单项提供禁用原因，拖拽排序不能是唯一排序路径。

### 8.5–8.8 对话

主对话是独立视图。用户问题、真实 reasoning/工具、回答与引用按阅读顺序排列，移除自定义检索过程盒；引用与对应回答相邻，点击能跳回原文。空态聚焦提问，标题、说明与输入框左缘对齐，整体居中成组，组宽上限 768px（含 gutter）；22px 图标与标题同行、不加底框，标题采用 28px，600px 及以下采用 19px，说明采用 14px。说明与输入框间保留约 24px，表单下右侧显示 12px 的 Enter / Shift+Enter 键位提示。内容超高时可滚动到标题和输入工具栏。主消息列上限 808px、输入区域上限 856px，主视图 gutter 24px、侧栏 16px。输入框内保留模型、实际推理等级和范围入口；模型菜单按供应商分组，支持直接选择模型并另设管理入口。失败时给具体可用出路。

### 8.9–8.11 全局反馈

搜索、收集、上传、命令面板和未保存确认沿用同一表面、字号与边界。未保存离开需保留既有三选项；保存状态常驻。

### 8.12–8.15 设置

宽屏分区栏与窄屏 Select 共享同一 `?section=` 状态；切换分区回到该分区顶部，保留导航焦点。供应商、能力、统计与账号布局按 `settings-content` 的实际宽度适配；≤620px 堆叠或收为两列统计。供应商动作保持轻量文字形式，模型披露入口具备独立展开状态、关联内容区和至少30px稳定命中高度。设置页优先展示用户能理解的当前状态、可执行操作与结果，避免重复说明。设置与供应商标题使用22px；供应商连接、模型以留白分组，保留外框与字段边界、去除重复逐字段装饰线。新建预设支持搜索选择；密钥草稿显示待保存，仅持久化凭据显示已配置。重复添加空模型时返回并聚焦已有输入。模型配置保留供应商、任务分配、连接测试；检索保留搜索测试与维护操作。实现参数、日志、数据库/文件路径和环境变量不进入普通用户设置页。
账号分区默认显示当前头像或姓名首字母；悬停或键盘聚焦时，灰色圆形遮罩和相机图标覆盖头像，提示可更换。选图后仍先裁切再上传；产品不提供删除头像操作。

## 9. 品牌

`BrandMark` 使用绿色渡鸦：圆润头部、厚喙、小眼点与开放弧形翼线构成简化侧身，不加独立方框、突出的肚子或尾部。主轮廓固定为 64×64 viewBox，眼点与翼线为真正的透明留白；16px 主要依靠整体轮廓，不以眼点清晰为识别前提。组件继续继承 `currentColor`，保留 size/title 与装饰/命名图像的无障碍语义。

唯一矢量源为 `assets/brand/mimir-mark.svg`，色彩元数据为 `assets/brand/brand.json`；通过 `pnpm --filter @mimir/desktop icons` 派生 renderer 几何、两端 favicon、桌面 PNG/ICO/ICNS、fnOS 包根与启动器 PNG、小程序界面图和头像导出。禁止独立手改生成文件或为小尺寸另画一套轮廓；修改源后重新生成并验证同形与幂等。品牌主绿为 `#00834d`，反白为 `#FFFFFF`，深色导航/标签采用现行强调绿 `#6bdaa5`；不据此改变页面主题 token。

桌面与 fnOS 使用绿底白鸟，平台只调整底板、透明外缘及外部留白，不拉伸主形。小程序后台头像交付为 1024px 铺满正方形，不预裁圆角，并检查系统圆形遮罩安全区；界面使用本地 PNG 和原生 Image，不用字体 m 充当标记。浏览器侧栏、登录页、桌面标题栏、favicon 和四端应用资源共享同一几何。

登录页宽屏为品牌区与聚焦表单，窄屏为单列；品牌区用低对比的斜置纸页线稿填补中段留白，图案仅作装饰，不干扰产品名与底部的用途短句。短句应具体说明笔记和资料可检索、可提问，不用抽象分类词；窄屏隐藏线稿与短句，不填虚构统计或功能卖点。

## 10. 落地

跨包主题值从 renderer 向 Chat / Office 桥接。浏览器与桌面端共用 renderer，桌面标题栏由桌面壳独立实现。现有 URL、会话、库树、文件操作与服务端契约保持可用。

## 11. 避免

不做假窗口按钮、假 Ribbon 命令、装饰性统计、高饱和来源标签、技术参数说明或三层嵌套卡片。不要为了“更满”添加产品当前没有的数据。

## 12. 交付前检查

`pnpm check`、`git diff --check` 必须通过。界面改动在内置浏览器查看浅深两套外观与 1440 / 1100 / 880 / 600px 的关键页面；确认主动作可达、没有横向溢出、文档阅读/编辑与对话滚动各归其位。设置文案逐项检查是否仍泄露技术实现。
