# mimir 设计规范

本文件是当前界面的视觉与交互契约。颜色、字体和断点以 `packages/renderer/src/theme/tokens.ts`、`customToken.ts` 的实现为准；改动契约时同时更新本文件。改版前的详细理由留在 `.trellis/tasks/archive/2026-10/10-10-visual-redesign/research/design-before-redesign.md`，不再作为现行规范。

## 0. 原则

### 0.1 内容是主角

工作区借鉴 Obsidian 的连续分栏、低对比表面、轻边界与紫色焦点。阅读和编辑区应把空间给内容。知识库默认是文件工作台，不用无关统计或装饰卡片填补留白。

### 0.2 状态必须可见

保存、检索、模型连接、备份和失败都要给出真实状态与可执行的下一步。状态色承载信息，不承担装饰。失败类型有各自的出路，用户主动停止对话不显示为错误。

### 0.3 文案服务用户任务

界面面向普通用户，说明“现在能做什么、发生了什么、下一步是什么”。设置页隐藏 RRF、分词器、数据库类型、路径、环境变量和调试输出等实现细节。必要的风险提示与操作结果要保留。文档助手的四项快速上手指南完整保留。

## 1. 组件基础

Ant Design 6 承担按钮、表单、菜单、弹窗、反馈等控件的键盘、焦点、校验和状态；`antd-style` 承担项目布局和视觉规则。导航与产品操作图标用 `lucide-react`；品牌标识及被编辑文档自身的图像不受此约束。Office 包通过 `EditorShell` 和现有命令槽组织界面，不能为了仿 Ribbon 画不可用命令。

主题只由 `MimirProvider` 注入。Chat 通过 `ChatThemeBridge`、Office 通过 `editor-theme-bridge` 继承宿主 token，不各建一套主题。

## 2. 字体与形状

字体栈只在 `tokens.ts` 的 `FONT_SANS` / `FONT_MONO` 定义；中文用 PingFang SC、Hiragino Sans GB、Microsoft YaHei 兜底。正文阅读行高约 1.75。`FONT_SIZE` 定义 28 / 19 / 16 / 14 / 13.5 / 13 / 12.5 / 12 / 11.5px 的语义阶梯；最小档只用于有底色辅助的徽标，不放连续阅读内容。

全局圆角种子为 8px。大面积工作面主要靠表面明度和细边界分隔；圆角重点留给控件、选中行和浮层。Office 纸张有轻微层级，但不能成为多层嵌套卡片。

## 3. 颜色

### 3.1 品牌与表面

浅色主色 `#6e50b9`，浅色强调文字 `#543b9a`；深色主色和强调文字分别由 `darkCalibration` 校准。紫色只用于主操作、当前项、焦点与引用。语义成功、警告、错误、信息维持独立色对。

| 角色 | 浅色 | 深色 |
| --- | --- | --- |
| 布局底 | `#e7e7ea` | `#141416` |
| 导航底 | `#f4f4f5` | `#222226` |
| 列表底 | `#f8f8fa` | `#252529` |
| 主内容底 | `#ffffff` | `#29292d` |
| 浮层底 | `#ffffff` | `#34343a` |

`customToken.ts` 定义导航、列表、悬停、代码与热力图色阶；组件不要再散写一套蓝色或紫色。Office 的 `--me-*` 缺失时也回退到当前紫色主题。

### 3.2 文字与填充

`colorPrimary` 用于填充与选中背景，强调文字用 `colorLink` / `colorPrimaryText`。悬停和按下的链接文字都需保持可读。浅深外观均以 antd 实际派生 token 为准，由 `theme/design.test.ts` 守护文本、选中态、hover 与焦点的对比度。

### 3.3 文字阶

正文、次要说明、元信息、占位/禁用依次取 `colorText`、`colorTextSecondary`、`colorTextTertiary`、`colorTextQuaternary`。占位不能承载完成任务所必需的信息。

### 3.4 语义色

状态文字与同语义浅底成对使用；不要把种子色直接当状态文字。源于 antd 的种子色保持派生规则，必要时覆盖最终叶子 token。

### 3.5 强调色

按钮填充与可点击文字分属不同角色。选中菜单和 Tabs 的文字从 `colorLink` 取，焦点边界从 `colorPrimaryBorder` 取，不能靠颜色变化独自表达选中。

### 3.6 表面与热力图

布局、导航、列表、容器、浮层形成连续但可辨的阶。悬停底在对应表面必须看得见。热力图的四档色阶取 `customToken`，空格与第一档要有可见差异；“未上报”不能画作零用量。

### 3.7 徽标

来源类型是文档属性，不以高饱和徽标填满列表。状态徽标只标识偏离常态或需要用户关注的状态。

### 3.8 深色

深色是独立校准的值，不是浅色取反。菜单选中文字、链接、焦点环、Office 工具栏及编辑画布需逐项检查；`design.test.ts` 以真实 provider 的派生结果验证。

## 4. 内容排版

### 4.1 字体栈

界面与编辑器共享系统 UI 字体和中文兜底；代码及文件路径使用 `FONT_MONO`。

### 4.2 字号

页面标题、分区标题、正文、元信息按 `FONT_SIZE` 角色取值。窄屏先调整空间与折行，不靠缩小正文解决布局问题。

### 4.3 正文

Markdown 正文行宽上限 `CONTENT_WIDTH = 760px`，是阅读 measure，不是所有页面的统一容器宽度。Office 编辑器工具区横贯顶部，纸张或画布位于其下；各格式保留本身的页面/网格/幻灯片结构。

## 5. 布局

### 5.1 间距

以 4 / 8 / 16 / 24 / 32px 为基本节奏。标题、操作、内容分组要靠位置与空白建立层级，不靠重复边框。

### 5.2 圆角

控件继承 antd 8px 基础圆角；大区块保持平整。选中行、输入区和浮层可有明确圆角。

### 5.3 阴影

层级优先靠底色与细边界。阴影用于确实浮在内容之上的菜单、弹窗和画布纸张；文档纸张比浮层更轻。

### 5.4 尺寸

| 区域 | 当前约束 |
| --- | --- |
| 工作区导航 | 展开 294px；≤1100px 为 266px；折叠/窄屏为 52px 功能栏 |
| 设置分区栏 | 宽屏 246px，内容列最大 730px |
| 知识库工作台 | 最多约 1080px，文件列表优先 |
| 文档正文 | 阅读 measure 最多 760px；可选大纲 196px |
| 对话列 | 内容上限约 850px；文档阅读助手 400px |
| 桌面标题栏 | 44px，真实窗口控件只由桌面壳绘制 |

应用外壳在 `_app.tsx`；设置分区布局在 `settings.style.ts`。编辑器的工具区与正文滚动区由 Office shell 管理。

### 5.5 断点

`NAV_NARROW_QUERY` 唯一定义 880px 窄屏断点，CSS 与 `matchMedia` 共用。窄屏保留 52px 功能栏，当前任务侧栏改为按需覆盖；设置分区改 Select，文档大纲让出正文，阅读助手占满可用主区。宽屏上阅读助手展开时也收起大纲，避免 400px 助手与 196px 大纲并排挤窄正文。移动端在此阶段只保证现有任务可达与无横向溢出。

## 6. 动效

动效按反馈层级使用短时长，并尊重 `prefers-reduced-motion`。位移和透明度优先；不要通过动画掩盖控件延迟或保存状态。

## 7. 组件约定

### 7.1 图标

Lucide 线性图标：常规按钮 16px，导航/列表约 18px，独立入口约 20px；同层级保持一致描边。纯图标按钮有可见焦点、Tooltip 与 `aria-label`，装饰图标 `aria-hidden`。不用 emoji 当产品操作图标。

### 7.2 焦点

不能移除焦点环。键盘路径在浅深外观均需可见；自定义按钮使用 `:focus-visible`。Office 和 Chat 子包继承宿主的焦点色。

### 7.3 可点击元素

按语义使用 button/link，确保 hover、按下、禁用和键盘状态真实。禁用的 Office 命令说明原因，不显示假操作。

### 7.4 禁用态

禁用态不能是唯一的状态说明；若用户需要知道如何启用，给出短说明或可操作入口。

### 7.5 Ant Design 6

组件使用当前 v6 API；定制优先走全局/组件 token 与语义部位。避免页面散写 `.ant-*` 字面色。内层 `ConfigProvider` 不传另一套 theme。

### 7.6 高度链

`AntApp` 与应用壳都需维持 `height: 100%` / `min-height: 0`，浏览器无桌面标题栏时主区也必须填满视口。

## 8. 页面形态

### 8.1 导航

52px 功能栏放对话、知识库、搜索、收集、设置；展开的任务侧栏放新对话、历史与库树。图标栏不重复绘制同一个功能的第二个主按钮。设置打开时使用独立分区栏。

### 8.2 知识库

页面标题、操作行、可扫读文件列表为主体；保留卡片/列表能力、目录树、拖放目标及真实状态。文件格式是元信息，缺失摘要要如实显示。

### 8.3 文档

阅读面居中；多标题且空间足够时显示大纲。原件自带导航的格式不重复加大纲。文档助手完整保留四项指南、范围提示、快捷提问和引用跳转。

### 8.4 工具条

操作按格式、段落、插入、查找与保存分组。溢出菜单承载低频命令，保存入口和状态常驻。

Markdown 笔记保留头部、工具栏、内容区域三个独立区域及其顺序，标题仍在头部。笔记头部以标题为主、返回和元信息为辅；长标题收缩，动作保持可达。笔记工具栏可采用独立于 Office 的紧凑外观：单行展示现有命令，组名保留无障碍名称但不常显；命令区横向滚动，保存入口固定在右端。正文、大纲与问 AI 侧栏的列布局不随头部调整。

### 8.4.1 Office 外壳

六种格式用顶部工具区、下方画布与底部状态行。各格式命令仅展示实际支持的能力；狭窄宽度下工具区可独立滚动，保存仍可达。

### 8.5–8.8 对话

主对话是独立视图。用户问题、回答、引用、检索过程和输入区按阅读顺序排列；引用与对应回答相邻，点击能跳回原文。空态聚焦提问，输入区展示当前范围与回答强度；模型入口指向全局模型设置。失败时给具体可用出路。

### 8.9–8.11 全局反馈

搜索、收集、上传、命令面板和未保存确认沿用同一表面、字号与边界。未保存离开需保留既有三选项；保存状态常驻。

### 8.12–8.15 设置

宽屏分区栏与窄屏 Select 共享同一 `?section=` 状态。设置页优先展示用户能理解的当前状态、可执行操作与结果，避免重复说明。模型配置保留供应商、任务分配、连接测试；检索保留搜索测试与维护操作。实现参数、日志、数据库/文件路径和环境变量不进入普通用户设置页。

## 9. 品牌

保留 `BrandMark`，桌面标题栏与浏览器侧栏使用同一品牌资产。登录页宽屏为品牌区与聚焦表单，窄屏为单列；品牌区只展示产品名与定位，不填虚构统计或功能卖点。

## 10. 落地

跨包主题值从 renderer 向 Chat / Office 桥接。浏览器与桌面端共用 renderer，桌面标题栏由桌面壳独立实现。现有 URL、会话、库树、文件操作与服务端契约保持可用。

## 11. 避免

不做假窗口按钮、假 Ribbon 命令、装饰性统计、高饱和来源标签、技术参数说明或三层嵌套卡片。不要为了“更满”添加产品当前没有的数据。

## 12. 交付前检查

`pnpm check`、`git diff --check` 必须通过。界面改动在内置浏览器查看浅深两套外观与 1440 / 1100 / 880 / 600px 的关键页面；确认主动作可达、没有横向溢出、文档阅读/编辑与对话滚动各归其位。设置文案逐项检查是否仍泄露技术实现。
