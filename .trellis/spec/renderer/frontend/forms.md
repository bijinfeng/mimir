# Frontend form pattern

- Shared product UI lives in `packages/renderer`; `apps/web` is the browser shell. The form examples here are from the shared renderer, so they apply to browser and desktop UI.
- There is no single form library pattern. Login and signup use antd `Form` with `Form.Item` rules and `onFinish` ([`login.tsx`](../../../../packages/renderer/src/routes/login.tsx#L332-L417)). Signup's password confirmation uses `dependencies` and a validator in that same example.
- Feature forms also use controlled antd inputs. [`KnowledgeBaseModal`](../../../../packages/renderer/src/components/KnowledgeBaseCreateModal.tsx) shares name/description fields between create and edit; the `KnowledgeBaseCreateModal` wrapper keeps existing create callers compatible. It trims and validates on submit, associates inline validation with the field, focuses an invalid name, and retains the complete draft on request failure. Its pending state prevents duplicate submits and dismissal; a viewport-limited body scrolls while the footer remains reachable. Success invalidates the relevant query and returns focus to the trigger. Existing descriptions over the UI's 500-character limit may be saved unchanged without truncation; new edits must meet that limit. Update failures reconcile the folder by stable code before retry, following the [folder update contract](../../shared/contract/folder-update.md). [`FeedsSection`](../../../../packages/renderer/src/components/settings/FeedsSection.tsx) uses the same query/mutation shape for a compact input action.
- Menu portals inside clickable rows still bubble through React's component tree. `FolderSection` stops menu `domEvent` propagation and rejects row events whose target is outside its DOM subtree, so opening edit/delete does not navigate or trigger an unsaved-content guard. Keep the modal mounted through `afterClose` to restore focus after renamed rows reconcile.
- Settings that require persistence show an explicit Save action. [`SettingControl`](../../../../packages/renderer/src/components/settings/SettingControl.tsx) documents the failed blur-save approach: text/number drafts commit on Save or Enter, excluding IME composition. Boolean switches save immediately, roll back to the persisted value on failure, and offer a retry of the attempted value. Inline status reports actual pending/success/failure; editing alone must not report success.
- Keep server errors visible and text/number/secret drafts editable after failure. A failed clear request must also retain the secret draft; only successful clear/save may discard it. Query refreshes must not overwrite an unsaved draft. API calls go through [`lib/api.ts`](../../../../packages/renderer/src/lib/api.ts), and mutations invalidate affected query keys after success. See the [setting behavior tests](../../../../packages/renderer/src/components/settings/SettingControl.test.tsx).
- Destructive asynchronous confirmations use [`confirmDanger`](../../../../packages/renderer/src/components/confirm-danger.tsx): cancel receives initial focus, pending prevents dismissal, and rejection keeps the same object and consequence text visible with an inline retry. Callers must propagate rejection and avoid a duplicate global error toast. AntD hook-modal promise mode must be consumed so a handled rejection does not escape as an unhandled promise rejection.
- Upload feedback reflects each real request: saved originals count as success even without searchable text; unsaved files show their full failure reason. Preserve filename extensions under truncation, report success/failure counts, and allow a new batch after all failures. A synchronous batch guard complements the disabled UI; do not invent upload percentages or backend retry/undo capabilities. See [`UploadPanel`](../../../../packages/renderer/src/components/UploadPanel.tsx) and the [capture/import state and approved visual contract](./capture-parity.md).

Choose the closest existing form example for the next task instead of forcing all forms into `Form` or all forms into manual state.
