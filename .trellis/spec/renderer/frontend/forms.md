# Frontend form pattern

- Shared product UI lives in `packages/renderer`; `apps/web` is the browser shell. The form examples here are from the shared renderer, so they apply to browser and desktop UI.
- There is no single form library pattern. Login and signup use antd `Form` with `Form.Item` rules and `onFinish` ([`login.tsx`](../../../../packages/renderer/src/routes/login.tsx#L332-L417)). Signup's password confirmation uses `dependencies` and a validator in that same example.
- Feature forms also use controlled antd inputs. [`KnowledgeBaseCreateModal`](../../../../packages/renderer/src/components/KnowledgeBaseCreateModal.tsx#L73-L143) keeps draft fields in state, trims and validates on submit, uses a React Query mutation, shows an error message, and invalidates the relevant query after success. [`FeedsSection`](../../../../packages/renderer/src/components/settings/FeedsSection.tsx#L33-L60) uses the same query/mutation shape for a compact input action.
- Settings that require persistence show an explicit Save action. [`SettingControl`](../../../../packages/renderer/src/components/settings/SettingControl.tsx#L18-L41) documents the failed blur-save approach; its text/number draft commits on Save or Enter, while its boolean switch saves immediately ([`SettingControl.tsx`](../../../../packages/renderer/src/components/settings/SettingControl.tsx#L103-L161)). The [component test](../../../../packages/renderer/src/components/settings/SettingControl.test.tsx#L89-L125) verifies the visible Save action and actual request.
- Keep server errors visible to the user and the draft editable after failure, as [`SettingControl`](../../../../packages/renderer/src/components/settings/SettingControl.tsx#L86-L101) does. API calls go through [`lib/api.ts`](../../../../packages/renderer/src/lib/api.ts#L99-L126), and mutations invalidate query keys affected by the result, as [`FeedsSection`](../../../../packages/renderer/src/components/settings/FeedsSection.tsx#L39-L60) does.

Choose the closest existing form example for the next task instead of forcing all forms into `Form` or all forms into manual state.
