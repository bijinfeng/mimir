# UI 交互细节审查

## Goal

在已完成的视觉审查之外，逐项验证网页版主要操作的行为、反馈和恢复路径，给出可复现、按影响排序的交互问题清单。

## Requirements

- R1：沿登录后主路径检查导航、知识库、文档、搜索、收集、对话与设置中的可见交互；覆盖按钮、菜单、切换器、输入、弹窗、空态和状态提示。
- R2：对每类可达操作检查鼠标与键盘行为、焦点去向、禁用与校验、关闭与取消、未保存保护、成功或失败反馈，以及窄窗口的操作可达性。
- R3：每条问题必须有本轮实际操作记录，并区分页面实测、代码辅助定位和无法覆盖的状态。关键状态需保存并检查截图。
- R4：只使用隔离审查账号及可逆测试状态；不调用收费模型、不抓取外部网址、不上传私人文件、不删除用户数据。
- R5：报告按流程列出覆盖项、健康度、问题复现步骤、影响、优先级与建议；说明未测试场景。
- R6：新增以 Obsidian 高频笔记任务为参照的走查：快速打开与切换笔记、文件夹与侧栏操作、搜索命中定位、命令入口、编辑时的焦点与格式操作。分别记录本产品实测行为、Obsidian 参照来源、操作成本和改进建议；不得将官方资料描述当作 Obsidian 本机实测。
- R7：单独审查 Markdown 笔记编辑页头部的视觉层级、控件密度、标题呈现、保存反馈与 Obsidian 风格笔记流程的匹配度；以实际截图支撑视觉判断，窄窗口未复测时明确标注边界。

## Acceptance Criteria

- [x] 建立覆盖主要页面与交互状态的操作矩阵，逐项标明通过、问题或未测试。
- [x] 对键盘焦点、弹窗关闭、表单校验、未保存保护、反馈和窄窗口操作做实际验证。
- [x] 关键问题有本轮截图及可复现步骤；截图可打开且报告链接有效。
- [x] 审查报告把已确认行为与推断分开，并给出按优先级排序的修复清单。
- [x] 完成时恢复测试界面中可逆的设置和草稿，不留下不必要的产品数据。
- [x] 新增 Obsidian 对标操作矩阵与证据截图，覆盖上述高频任务并标明未覆盖项。
- [x] 对编辑页头部给出截图支持的具体设计问题和可执行的收敛方向，并说明当前会话失效造成的复测限制。

## Out of Scope

- 直接修改产品代码。
- 真实模型付费调用、外部抓取、上传私人文件及不可逆删除。
- 完整屏幕阅读器认证、全部 Office 格式及桌面客户端验收。
