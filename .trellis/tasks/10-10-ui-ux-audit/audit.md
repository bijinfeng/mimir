# 页面审计 · 2026-10-10

## 范围与方法

在隔离的本地开发数据目录中，从首次登录后依次查看知识库、文档、搜索、对话、收集入口及设置全部九个分区；知识库另外检查 900、760、600 像素宽度，设置检查 760 像素。以下截图均取自本次实际交互，保存于 audit/。状态结论只针对所见场景。

## 步骤与发现

1. **登录｜基本健康。** 已有账号状态的表单标签和单一主按钮清晰。见 [截图](audit/01-login.jpg)。没有测试错误输入与密码恢复。
2. **知识库｜可用，操作层级待改善。** 库身份、文档数、卡片与列表切换都清楚；1152 像素下操作集中在同一行，600 像素时“添加文档”换到第二行并排在次要操作之后，主操作的可见性下降。见 [标准宽度](audit/02-library.jpg)、[窄窗口](audit/13-library-600.jpg)。
3. **文档｜基本健康。** 返回库、标题、保存状态和大纲可见；顶部格式工具密集，图标依赖提示理解。见 [截图](audit/03-document.jpg)。未测试长文键盘编辑与保存失败。
4. **搜索｜高优先级。** 输入“产品”后，结果列表高亮第一项，底部写“Enter 打开”，上方却写“按 Enter 直接提问”。实际代码有命中时 Enter 运行高亮项、仅无结果时才提问，页面提示误导用户。六条结果都来自同一文档，却以文档 ID 作为 React key，运行时发出重复 key 警告；点击结果只打开文档，没有传入命中位置。见 [截图](audit/04-search.jpg)。
5. **对话｜空态清楚，检索回答难读。** 空态引导用户直接提问，发送后在未配置模型时明确告知未调用模型；回答把原文截成大段编号列表，标题、加粗和代码片段混杂，下面又展示同一来源的引用卡，阅读负担大。见 [空态](audit/05-chat-empty.jpg)、[检索回答](audit/06-chat-answer.jpg)。有模型流式回答未测试。
6. **设置｜结构可用，文案偏技术化。** 九个平铺标签在当前宽度可访问，760 像素下切为有标签的分区下拉。模型页操作较重；外观页较简洁。订阅、存储、插件、统计和数据页有长篇解释、内部术语或重复状态。见 [模型](audit/07-settings-models.jpg)、[外观](audit/08-settings-appearance.jpg)、[检索](audit/14-settings-retrieval.jpg)、[订阅](audit/15-settings-feeds.jpg)、[存储](audit/16-settings-storage.jpg)、[插件](audit/17-settings-plugins.jpg)、[统计](audit/18-settings-stats.jpg)、[数据](audit/19-settings-data.jpg)、[账号](audit/20-settings-account.jpg)、[窄窗口](audit/21-settings-760.jpg)。
7. **收集｜路径可发现，表单名称需补。** “添加文档”列出上传、抓取与直接编辑；抓取弹窗会说明收进哪个知识库并识别链接来源。链接输入仅有 https://… 占位提示，缺少明确的可访问名称。见 [入口](audit/09-add-menu.jpg)、[抓取表单](audit/10-capture.jpg)。未向外部网站发起抓取。

## 建议顺序

1. 修正搜索 Enter 语义，给“提问”单独可见动作；结果片段保留可辨的标题与命中位置。
2. 让“只用检索”回答用简短状态行加引用卡呈现，避免正文重复罗列同一原文；仍明确说明无模型、无调用费用。
3. 调整知识库操作栏的分组和窄宽顺序，使主操作优先可见；保留现有内容宽度与主题体系。
4. 为收集链接输入加可访问名称，并复查焦点、错误提示和键盘操作。
5. 清理各页面文案及设置默认信息层，保持九个设置分区和原有能力。

## 证据限制

截图能证明当前视觉状态，不能证明完整无障碍合规。键盘焦点、屏幕阅读器、所有错误路径、深色模式、桌面载体、外部抓取、上传和真实大数据量仍需在实施验证时分别检查。

- 搜索命中与无命中两条路径的 Enter、独立提问、同文档不同命中定位已在隔离数据中实测；文档定位在浏览器不支持 Custom Highlight API 时仍会滚动到片段。
