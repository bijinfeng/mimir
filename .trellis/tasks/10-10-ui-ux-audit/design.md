# 技术设计

## 边界与结构

- 页面改动集中在 `packages/renderer`：搜索面板、知识库操作栏、收集弹窗、对话/引用呈现、各设置分区及其共用样式。维持现有路由、`?section=`、服务端配置来源、主题 token 和平台共用组件。
- 只检索回答的正文由 `apps/server/src/services/assistant.ts` 与 `assistant-stream.ts` 生成，两条路径应使用相同的短状态文案；引用仍从已有 `Citation[]` 契约传递。历史消息读取应能正常显示，不依赖临时 UI 状态。
- 搜索命中已有 `documentId`、`snippet` 与偏移；文档面板已有 `openCitation`、`highlightSnippet` 机制。搜索结果复用这条打开与定位链路。结果 key 用文档 ID 加命中标识/稳定序号，不能仅用文档 ID。

## 交互设计

1. **搜索**：列表项只负责打开结果；有搜索词时提供独立“提问”按钮。Enter 对当前高亮项执行打开；没有可选项且输入非空时执行提问。页脚按状态显示准确快捷键。命中多处同文档时，每个片段为独立结果，选中后在文档里滚动并高亮；若片段无法匹配正文，仍打开文档并显示标题。
2. **只检索回答**：服务端只保存简短状态（含未调用模型与无命中时的恢复建议），不再把引用原文拼进回答正文；前端使用已有引用卡展示命中原文与来源。模型回答的正文、流式协议、引用编号和失败重试保持原契约。
3. **知识库**：将添加文档留在主操作区，次要显示/排序控件在窄宽度时换行或归组。用当前 token 控制密度和间距，避免新增平行样式系统。
4. **设置**：保留九个分区。每个分区默认层按“当前状态 → 可执行动作 → 必要后果”排列；长篇原理、内部路径、`seam` 和源码位置从默认层移除。插件分区保留注册表与状态，技术标识放入可展开详情。存储与数据页必须把切换和备份边界放在动作附近，不能因精简而隐藏风险。
5. **文案**：以 `audit.md` 清单为基线，按 `design.md` §8.15 判断静态 JSX、服务端 `description`/`reason`、提示和空态。无操作价值的文字删除；动态错误保留能执行的下一步。对完整备份、数据迁移、费用、未知统计量做事实核对。

## 兼容性与权衡

- 不改 `GET /api/config` 的注册表契约，不新增设置键或数据库迁移。文案变化不应影响配置读写；服务端动态描述若修改，需确保原本用于解释缺项的状态原因仍点名用户能找到的字段。
- 只检索历史回答会保留旧文本；新回答采用短状态加引用卡。若需要处理旧记录，前端仅在能够可靠识别旧格式时做兼容显示，不做批量迁移。
- 搜索定位先复用现有文本匹配和高亮机制，不新增搜索端点。片段因正文变化而定位失败时，打开文档作为可预期降级。
- 不将开发调试数据完全移除：明确的“技术详情”保留定位故障能力，同时减少普通使用者的认知负担。

## 验证与回退

- 在隔离 SQLite 数据目录复查各截图对应状态；测 1152、900、760、600 像素与浅色/深色。使用可控示例文档验证同文档多命中、Enter/点击、引用定位、只检索回答及设置技术详情。
- 运行 `pnpm check`，并针对搜索、对话、设置的行为补充必要测试。失败时按模块回退 UI 改动；无数据迁移或不可逆部署步骤。
