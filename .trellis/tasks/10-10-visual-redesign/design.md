# Obsidian 启发的 mimir 工作区：设计与技术方案

## 视觉方向与证据

用户指定 Obsidian 为工作区参照，并指定 GenOffice 为编辑体验参照。前者提供分栏与阅读面的空间气质，后者提供“上方功能工具区、下方内容画布”的编辑秩序；都不复制品牌或增加不存在的功能。旧版截图见归档任务 `10-10-ui-ux-audit/audit/`；工作区方向稿见 `research/visual-direction.html`、`research/visual-expansion.html`，入口、设置与浮层方向稿见 `research/visual-full-surface.html` 和 `research/full-surface-direction.md`。方向稿只表达结构和视觉语言，不代表要加入其中任何当前不存在的操作。

视觉重点：连续的工作区壳、紧凑而安静的导航、清楚的表面阶、深色与浅色等价、长文阅读居中。避免整页同质卡片、装饰渐变和信息无关的营销插画。品牌继续使用 mimir 标记，紫色只标识主操作、选中态和引用。

## 版式

```text
知识库 / 对话 / 文档（宽屏）
┌────────────── 标题栏：桌面壳使用原有窗口控件；浏览器不画假控件 ──────────────┐
│ 52 功能栏 │ 约 242 当前任务侧栏 │              主工作区                │
│          │ 新对话/历史先于库树    │ 顶部 48 位置与操作栏             │
│          │                       │ 库：最多约 1080 的文件工作台     │
│          │                       │ 阅读：正文约 760 + 可折叠大纲    │
│          │                       │ 编辑：通栏工具区 + 格式画布      │
└──────────────────────────────────────────────────────────────────────────┘

设置（宽屏）
┌─────────┬──────────────────┬─────────────────────────────────────┐
│ 功能栏  │ 设置分区 约 246  │ 当前设置内容，最大约 730           │
└─────────┴──────────────────┴─────────────────────────────────────┘
```

- 功能栏承载对话、知识库、搜索、收集、设置等已有入口；对话优先于知识库。图标必须有 tooltip/无障碍名称。当前任务侧栏把新建对话和会话历史放在知识库入口之前，保留现有库树、会话和折叠状态，避免添加假的“多工作区/多标签”。同一功能不在两栏重复成两个主按钮。
- 图标栏与侧栏可做一体组件或分层组件，但 URL、会话和库树数据仍沿现有路由/查询。设置打开时，当前任务侧栏换成设置分区栏；`?section=`、九个分区和桌面专属客户端分区仍按现有契约。
- 知识库主区使用页面标题、操作行、可扫读的文件列表作为默认视觉形态；卡片/列表能力都保留。仅有一个文档时承认真实留白，不填充虚假统计或说明。文件夹、文档的当前操作与拖放目标必须保留。
- 文档主区分阅读与编辑。阅读态让正文成为焦点；编辑态的 `EditorShell` 工具栏横贯编辑区顶部，下面才是可滚动的纸张、网格、幻灯片、HTML 分栏、Markdown 正文或 PDF 画布，底部是状态行。现有命令按格式/段落/插入/查找与保存分组，次工具栏只在当前格式需要时出现；不画出未实现的功能页签。保持保存状态、原件预览、下载、问答与引用跳转。大纲在空间足够时是右侧辅助栏；窄宽时可折叠或使用现有入口。阅读助手指南完整保留。
- 主对话以消息列和输入区为主，空态不做空白营销页；回答态的可折叠检索过程和引用贴在具体回答附近。输入区保留本轮范围与标准/深入，模型菜单只显示全局角色绑定并跳转模型设置。文档阅读助手是 400px 侧栏，锁定本篇，完整指南在上、快捷提问贴近输入区。搜索与收集浮层使用同一边框、表面与排版体系。
- 模型设置是供应商列表/同页编辑表单与四类任务分配的组合；没有供应商时突出添加入口，配置态展示真实角色状态、测试和选择器，不画会话级换模型开关。方向稿用示例配置时显著标注示例。
- 桌面端原有 `useTitleBar` 负责真实窗口控件；浏览器不添加装饰性的红黄绿圆点。方向稿中的顶栏代表桌面壳，浏览器版本从主区位置栏开始。
- 登录和首次建号作为工作区入口单独构图：宽屏用品牌区与聚焦表单形成清晰比例，窄屏收为单列；品牌区只放产品名与“知识工作区”定位，表单只保留解释当前动作所需的信息，不加入营销口号、虚构统计或功能列表。两种表单由现有 `/api/auth/setup/state` 决定，保留加载、请求失败、本地模式、持续错误提示、校验与密码确认；桌面端仍使用真实标题栏。
- 设置每个分区共用标题、行距、字段标签、状态反馈和操作基线，但按真实内容调整密度：模型的供应商与任务分配、检索/订阅/存储/插件的配置和状态、统计/数据备份的阅读与操作、外观/账号/客户端的个人与设备设置。不能只重画设置首页而留下旧式分区内容。
- 设置只呈现用户能理解并采取行动的状态。检索页隐藏融合调参和通道内部信息，保留语义搜索就绪状态、补全/重新整理与搜索测试；其他分区不展示“技术详情”、代码路径、数据库驱动、环境变量或内部目录。备份限制、迁移风险和模型用量仍直接说明。
- 全局浮层形成一套与工作区相连的层级：命令搜索重视输入与结果扫描，收集/上传重视任务选择与进度，新建知识库及删除/未保存确认重视清楚的主次操作，加载失败/空态重视可恢复路径。保持现有数据与操作语义。
- 1100px 以下压缩当前任务侧栏并隐藏非必要右大纲；880px 以下仅保留功能栏，侧栏通过现有展开机制按需出现；600px 下主操作、正文和设置分区选择仍完整。所有断点需与 `NAV_NARROW_QUERY` 保持一致，避免 CSS 与 `matchMedia` 分叉。

600px 窄窗口打开文档阅读助手时，将其作为可关闭的右侧覆盖面板呈现，正文保持在背后；不能仅用 CSS 隐藏助手而让指南和输入区不可达。主对话输入区在窄窗口允许控件换行，范围、强度和发送动作持续可见。补充方向稿的窄窗口截图已核对这两点。

| 紫色填充 | `#6e50b9` | `#7655bf` 候选 | 主按钮、品牌重点 |
| 紫色文字 | `#543b9a` | `#c5adf4` 候选 | 选中、链接和引用 |

方向稿关键文字色对已计算：浅色次文字/白底 4.58:1，浅色紫色按钮白字 5.98:1，深色候选按钮白字 5.49:1，浅色选中文字/底 6.43:1，深色候选紫字/工作面 7.35:1。最终 token 仍需对实际 antd 派生结果、hover/focus 和所有表面重复计算。

## 组件、图标与样式技术契约

技术底座固定为仓库 catalog 的 Ant Design 6（当前 `^6.6.4`）、`antd-style` 4 和 `lucide-react` 1。Obsidian 只作为视觉参照：三栏空间关系、哑光中性色、轻边界、紫色选中态和聚焦阅读面由本项目主题实现；不引入 Obsidian 样式包、另一套组件库或全局皮肤 CSS。

| 场景 | 实现边界 |
| --- | --- |
| 应用壳、阅读页、Office 画布 | CSS grid/flex 与 `createStyles`（Office 包沿现有 `shell.css`/`--me-*`）；这些是布局，不为了使用组件库而套多层 antd `Card`/`Layout` |
| 导航、表单与设置 | 现有 antd `Menu`/`Select`/`Form`/`Input`/`Segmented`/`Button` 等承载键盘、校验、状态；侧栏容器、行距与信息层级由主题样式组织 |
| 浮层、结果与反馈 | antd `Modal`/`Dropdown`/`Popover`/`Tooltip`/`Alert`/`Skeleton`/`Empty`/`Table` 等继续承担焦点、遮罩、状态与数据呈现；仅按语义 token 调整形态 |
| 编辑工具区 | `EditorShell` 保留既有 antd 控件及少数确有技术理由的原语（就地弹层、网格选择、工具分组）；不仿制尚无命令的 Ribbon |

主题只在 `MimirProvider` / `theme/tokens.ts` / `customToken.ts` 里定义和注入：共同形状、字体、间距与控件尺寸，两套独立校准的色值。优先用 antd 全局与组件 token 调整 Button、Menu、Input、Modal、Tabs、Table、Tooltip 的共享形态；组件内部确需覆写时用 antd v6 的语义部位 API 或 `createStyles` 的 `${prefixCls}` 作用域选择器，不到页面上散写 `.ant-*` 与字面色。保留 `ConfigProvider` 单一主题来源；Office 内层只传 `componentSize="small"`，不可再次传 `theme`。Chat 通过现有 `ChatThemeBridge` 取得字号/栏宽，Office 通过 `editor-theme-bridge` 取得 `--me-*` 色值，不反向 import renderer 内部模块。

图标规则：导航与操作默认 `lucide-react` 的线性图标，以 `currentColor` 跟随 token。常规按钮 16px、导航/列表 18px、独立入口 20px；同一层级保持相同大小与约 1.8–2 的描边宽度。图标按钮保留可见焦点、Tooltip 与 `aria-label`，装饰性图标 `aria-hidden`，选中态不能只靠颜色。不要把方向稿的 Unicode 占位符、emoji 或字形符号带进产品。品牌 `BrandMark` 和被编辑/预览的文档自带 SVG 属于内容/标识，不作为 Lucide 操作图标替代。

当前 renderer/chat/desktop 已大量使用 Lucide，`@ant-design/icons` 在产品源码中无直接 import，但 renderer 仍声明该依赖；Office 的 `shell/icons.tsx` 自绘约 60 个工具图标并对外导出。实施时先建立现有名称到 Lucide 语义图标的映射：通用动作从 Lucide 导入，保持 Office 既有导出名称作为兼容适配层，避免六格式编辑器同时改命令调用；没有准确图标语义的命令改用短文字标签，不再增加手绘 UI 图标。将 `lucide-react` 加入 Office 的运行依赖，完成全仓引用检查后移除无用的 `@ant-design/icons` 声明。旧 `.trellis/spec/project/design.md` §7.1 的 `@ant-design/icons` 规则与用户当前决定冲突，以本任务 PRD 为准，实施验证后同步更新规范。

统一验收对象不只是颜色：1440/1100/880/600px 下的壳宽、滚动归属、主动作可达；浅深两套 antd **实际派生** token 的正文/选中/焦点/hover 对比度；按钮、输入、弹窗、菜单的状态和键盘路径；Lucide 尺寸、描边、对齐与无障碍名称。`design.test.ts` 要守真实 provider 的结果，而不是仅测方向稿十六进制值。

## 技术边界与兼容

- 统一 token 仍由 `packages/renderer/src/theme/tokens.ts` 与 `customToken.ts` 管理；外观两套值并列。antd 的 seed/叶子 token 和对比度守卫需按现有 theme spec 处理。跨 `@mimir/chat` 使用既有 `ChatThemeBridge`，不在 chat 包引入 renderer 内部代码。
- 应用壳在 `routes/_app.tsx`，导航组件在 `NavSidebar`；页面分别位于 library、document、chat、settings 与登录、搜索/收集浮层。优先调整这些容器和共享规则，不改数据/服务端契约。桌面标题栏从共享的 titlebar kit 获取品牌视觉，避免 Web/Electron 各自一套。
- 设置由横向 Tabs 改为宽屏分区栏时，保持 `resolveSection`、`sectionsFor`、`goSection` 及 URL 行为。窄窗口保留带名称的 Select。不能为了视觉稿添加假的开关。
- 现行 `.trellis/spec/project/design.md` 的蓝色主色、200px 单侧栏、所有页面共用 760px 内容列等旧值将在实现质量验证后改为新契约；必要的产品行为仍以 `product.md` 为准。视觉回退可以按阶段撤销样式与容器改动，无数据库迁移。
- 页面清单以路由和共享组件为准：`/login` 是认证入口，`/` 直接跳 `/docs`；应用内路由为 `/docs`、`/chat`、`/settings`。全局浮层来自应用壳及库页，包括 `CommandPalette`、`CaptureDialog`、`UploadPanel`、`KnowledgeBaseCreateModal`、`UnsavedGuard` 和确认/错误态。扩展方案将覆盖这些现有界面，不虚构额外页面。

## 取舍与风险

- Obsidian 式双左栏比旧版占宽更多，因此必须按断点折叠，且不能把文档正文挤窄。右大纲优先让位。
- 新紫色主题与现有 antd 派生语义色、Office 编辑器可能不一致；先校准共享 token，再逐页落地并实测两种外观。第三方 Office/PDF 内部 UI 不重写。
- 旧设计规范指定 `@ant-design/icons`，而用户本轮指定 Lucide；实施 agent 必须按本任务的新图标契约工作，不能让旧规范把已统一的页面改回 Ant 图标。Office 的导出图标名称要保留，视觉实现可替换。
- GenOffice 官网展示的 Ribbon 比 mimir 当前工具栏承载更多命令。实施以仓库现有能力和 `EditorShell` 槽位为边界，重点改善分组、密度、悬停/键盘反馈及画布关系；不能把尚未支持的格式能力画成可点按钮。
- 方向稿的窗口控制、状态文本与图标是静态示意，真实产品只能显示现有功能和服务端事实。
