## 架构与边界

1. **文档页宿主**：`OfficeSourceEditor` 为当前 `DocxEditor` 提供按文档 ID 绑定的 agent 句柄；句柄只暴露读取上下文、冻结选区、执行工具、捕获/回退快照、获取编辑版本与保存状态，不把 Tiptap 对象暴露给服务端。切文档或卸载立即使句柄失效并取消未完成工具。
2. **TanStack AI 编排**：以仓库当前 `@tanstack/ai@0.55.0` 的 `chat({ tools, agentLoopStrategy, resume })` 作为唯一模型工具循环；不引入 GenOffice 的 `AgentLoop` 作为第二套循环。服务端用有验证模式的工具定义注册白名单：纯联网检索工具可由 TanStack server tool 执行；需要当前画布的 DOCX 工具由 client tool 请求交给浏览器。显式设置模型轮数、工具调用数和运行时长预算，避免默认五轮截断完整编辑。详细依据见 `research/tanstack-ai-capabilities.md`。
3. **侧栏与续轮**：同一 `DocChatSidebar`/`ChatPanel` 显示问答与编辑轮。先以现有 assistant-ui 消息运行时实现 TanStack client-tool interrupt 协议桥：按统一工具合同执行画布操作，回传真实结果，提交覆盖全部待处理 `client_tool_<toolCallId>` 的 AG-UI `resume`，并由受控服务端状态关联、核验 `parentRunId`。`useAssistantTool`/`addToolResult` 只负责其已验证的工具展示与结果路径，不能误当成 TanStack interrupt 的自动续轮。当前 `assistant-stream.ts` 会剥掉 TanStack 的 `RUN_FINISHED`；DOCX agent 路径须保留 `outcome`/中断 ID，并保证 AG-UI 每个 run 只有合法的一组生命周期事件。旧问答的外层生命周期不能直接套在 agent 路径上。
   浏览器消息/UI 运行时先保留 assistant-ui；首个垂直实验若不能保证不重复执行、正确续轮和停止语义，应迁到与当前核心兼容的 TanStack React 客户端，并重做 D-099 的历史/实时消息关联与队列草稿行为。`@tanstack/ai-react` 兼容版本具备工具、续轮和队列能力，但其 `CUSTOM` 仍通过回调而非通用消息 part 进入 Mimir。对照、版本约束和判断门见 `research/chat-runtime-assessment.md`。不并行维护第二套浏览器消息引擎。
4. **模型服务与权限**：只在已鉴权的当前 DOCX 单篇上下文提供 36 工具白名单与 DOCX prompt；忽略请求中未经许可的额外工具定义，主视图和非 DOCX 文档维持原问答权限。DOCX 问答上下文取发送时画布快照或实时读取工具，不再把数据库已保存正文当成唯一真相；引用仍指向当前文档的可定位内容。扩展 `services/model.ts` 统一入口以承载 TanStack 的工具、续轮、线程 ID 与循环策略；通过 `onUsage` 对多轮模型调用逐次记账。`plugins/provider` 仍构造适配器。模型是否真正支持 function calling 需能力探测，不能依赖 OpenAI 兼容适配器的乐观默认类型。
5. **DOCX 工具层**：以固定上游 36 工具和 15 个 `apply_ops` 操作为合同，复用已 vendored 的引擎与 ProseMirror 原语。缺失的上游 AI 模块按 `UPSTREAM.json` 固定版本引入或在 `packages/office/src/agent/` 保留来源映射与适配，遵守 vendor 文件不得手改的规则。上游硬编码 `window.desktop` 的操作通过 Mimir 注入的宿主服务接口适配，不在产品浏览器中伪装全局 Electron 对象。GenOffice 是工具语义、文档编辑实现及文件编辑交互的参考；不引入其完整办公外壳或第二套 Agent 循环。
6. **附加结构保存**：扩展 `DocxSession` 的编辑状态和 `save` 参数，覆盖样式、节/页面设置、水印、页眉页脚、批注、脚注/尾注、图表与媒体等工具会改的结构。以原件和原始块为补丁基底；保存成功才提交新基线，保存失败维持 dirty。每类工具用 DOCX 保存后重新解析，检查 OOXML 与画布一致；未改动的 ZIP 部件仍原样保留。
7. **服务设置与外部能力**：服务端新增可配置的服务适配器与健康状态。首个可实施组合为 Brave Search 的文本/图片检索、TanStack AI `generateImage()` 的 OpenAI 图像适配、经 TanStack AI `chat()` 多模态模型适配的媒体分析；音频/视频若适配器不直接支持，先在服务端转录/抽帧，再把结果交给 TanStack 模型调用。`web_search`/`image_search` 可是 server tool；`generate_image`/`analyze_media` 需结合当前画布插图或读取文档媒体，因此由 client tool 调用受控服务端能力并完成画布动作。图片适配器经 `plugins/provider` 构造，调用在 `model.ts` 统一记账。凭据使用现有加密设置存储，前端只见可用状态与可读错误，不见密钥。无配置时对应工具从本轮模型可用列表移除并给出配置提示；服务执行失败时返回失败结果，不伪造空结果。设置按通用能力而非文件类型分区：聊天、图片生成、视觉输入、转录归“模型”，Brave 文本/图片搜索归“网络搜索”；DOCX 侧栏只显示消费侧能力状态。将已保存的 `docx.*` 标量键无损迁移到通用键，兼容旧键但只允许新键成为可编辑真相源。依据见 `research/settings-competitor-research.md`。
8. **新文件**：`create_document` 在浏览器或服务端生成 DOCX/PDF/Markdown/HTML 字节，复用知识库文件上传与解析索引通路，成功后打开新文档页。新文件独立于当前 DOCX 的整轮回退；创建结果须明确告知文件位置与已保存状态。
9. **统一文档头部**：`DocumentPanel` 对所有文档种类渲染同一头部组件，以现有 Markdown 笔记的单行视觉为准。返回、标题和右侧操作共享布局与样式；笔记改名和文件下载作为能力差异插入，不复制整套头部。元信息不能把标题或操作挤出可见区域。保留 `runGuarded` 的离开保护，不改变正文编辑器和格式工具栏。
10. **保存入口位置**：`EditorShell` 统一把六种编辑器传入的保存动作放在底部常驻状态行右端，不再占顶部工具栏的固定列。各编辑器保留现有保存回调、按钮名称、禁用原因与状态文案；状态内容和保存操作分组排版，窄屏允许状态内容换行但保存不可被挤出视口。不通过宿主头部转发保存函数，以免复制六种格式的保存状态机。
11. **三栏头部高度**：工作区侧栏、共用文档头部和问 AI 侧栏以同一尺寸令牌确定 48px 高度；三栏各自保留组件结构和能力操作，只共享几何约束。头部以固定 flex 基础尺寸防止内容把下边界推开，窄屏仍须保留标题收缩与关闭动作。
12. **DOCX 紧凑工具栏**：只给 DOCX 工具栏增加单行布局与宽度自适应，不修改其余格式依赖的共用换行/滚动规则。以编辑区容器实际宽度（包括问 AI 侧栏打开时的中栏）决定整组命令的显示层级，而非只看全局视口。直接可见的优先顺序为段落样式、加粗/倾斜/下划线、字号、撤销/重做、查找；空间充分时再展开中文/西文字体、对齐、列表、插入等。窄栏保留样式、基础格式和具名“更多”入口；若实测宽度仍不足，继续将最低优先级的整组收进“更多”，避免裁切与纵向滚动。具名菜单按用户任务组织：**字体**（中文/西文字体、字号、增减字号、颜色/突出显示、删除线、上下标、清除格式、格式刷）、**段落**（对齐、倍数/固定行距、底纹、文字方向、间距、列表、缩进、段落移动）、**插入**（图片、链接、分页符、插入表格）、**表格**（原表格菜单全部操作）、**审阅**（修订、拼写检查）；“更多”在窄栏提供这些类别入口与当前隐藏的撤销/重做、查找，不删除任何命令。直接控件与菜单项调用同一命令和状态来源，菜单不得出现点击后无动作的占位项。

    单行的目标是稳定的工具栏高度，具体折叠阈值以实际控件尺寸和浏览器量测确定，不写死等同于视口断点的数值。菜单中的当前值/选中态、禁用原因和快捷键说明沿用现有原语；打开菜单、选择命令、关闭后焦点和编辑选区都应正确。不要复制一套会与可见按钮漂移的处理函数。图标按钮保留可读名称，具名菜单显示文字。此项依据 `research/toolbar-competitors.md`：Word 网页版的单行功能区、Google Docs 的菜单和快捷键可发现性、GenOffice 的办公命令分类与上下文工具。WeKnora 在这份调研中只作相关性核对；其 Markdown 编辑器不决定 DOCX 工具栏形态。Obsidian 仍用于整体布局与视觉风格。

    浏览器实测发现 `DocumentPanel` 在视口 ≤1250px 时把 400px 问 AI 侧栏绝对定位覆盖文档，而工具栏容器仍报告未遮盖前的宽度，导致右端“更多”被盖住。文档面板实际宽度足以容纳约 480px 编辑区与 400px 侧栏时，让两列参与 flex 分配；仅空间不足时才覆盖。断点依据文档面板容器自身宽度，不依据整页视口。这样工具栏量到的宽度就是可见中栏宽度，头部 48px 对齐和窄屏覆盖行为仍保留。
13. **六格式工具栏的一致适配**：在 DOCX 完成后，把同一“常用命令直接可见、低频命令有名可达、依据编辑区宽度折叠”的规则应用到 Markdown、XLSX、PPTX、HTML、PDF。优先采用各编辑器主动选择的响应式工具栏包装与局部样式，避免更改 `EditorShell` 的通用工具区行为（它被六种格式同时使用）；若抽共用适配原语，原语只负责测量/折叠和菜单承载，不知道各编辑器的编辑命令。直接按钮和收纳菜单必须共享回调、状态与禁用原因；一个命令在当前布局只出现一次可聚焦入口，避免重复的无障碍名称与弹层状态。

    - **Markdown**：常显段落样式、基础字形和链接；列表、缩进、插入、校对与表格/代码块上下文动作收入明确菜单。保留方言缺失时的禁用/隐藏规则和笔记现有的轻量视觉。
    - **XLSX**：工作表切换和当前格定位优先；查找、公式格导航、单元格复制/清空与十字高亮分组。多工作表名称在窄栏使用可读的工作表选择入口，不让 tabs 撑宽整栏；查找结果和单元格编辑反馈仍独立可见。
    - **PPTX**：选中文字/文本框后常用的字号与基础字形优先；字体、颜色、上下标和清除字形归入“文字格式”，查找保留可发现入口。无文本目标时仍显示禁用原因，不画虚假的当前值。
    - **HTML**：视图模式与查找优先；预览设备、缩放及其他辅助操作归入“预览”或“更多”，保留源码/预览分栏、预览唤起和独立查找栏。
    - **PDF**：当前页/翻页与缩放优先；旋转、页面顺序、纸型/裁剪、插入/导入及查找分组。删除页保持原有确认与“无撤销”的后果说明，不能因收纳进菜单而变成一步删除。

    格式间共享 48px 文档头部和底部保存入口，但各格式只展示实际支持的能力。现有次工具栏、footer 和状态行不为压缩顶部而挪位。具体折叠阈值按真实控件宽度和中栏浏览器量测设定；验收不只看视口宽度。竞品分工与代码盘点见 `research/all-editor-toolbar-inventory.md`。
14. **知识库文件类型识别**：上传件的 `title` 是不带后缀的展示标题，当前原件的存储键保留上传或替换时的文件后缀。文档摘要响应增加可空后缀字段，服务端在同一摘要映射中从当前原件键提取；笔记、网页等非文件返回空值。列表和卡片共用一个展示名与图标分类函数，避免一处改动造成两种视图不一致。展示名只在末尾缺少同后缀时附加后缀；未知格式保留中性回退，不根据 MIME 猜测成错误的“真实后缀”。用户否定了折角纸加微型扩展名字条；按 `research/file-icon-competitors.md` 中 Google Drive/Fluent 的独立类型图形与克制类别色做法，采用许可明确的通用图标素材，不嵌入竞品品牌标志。原有标题、原件和打开/下载操作的存储语义不变。

## 关键数据流

```text
DOCX 画布当前状态 + 冻结选区
  → 侧栏发送用户消息、文档/会话/编辑版本
  → 已鉴权 AG-UI 服务端调用 TanStack AI agent loop（仅当前文档的工具白名单）
  → server tool 在服务端执行；client tool 中断由侧栏注册工具执行
  → TOOL_CALL_* 状态 / 画布更新 / 真实结果 → AG-UI resume → TanStack AI 续轮
  → 最终回答 + 整轮快照回退入口
  → 用户点现有“保存到库” → DOCX 补丁式字节 → PUT /api/documents/:id/file
  → 服务端重算正文、哈希、索引
```

`write_document` 走独立的流式写作请求，模型仍经 `model.ts` 记账。草稿事务不进入普通 undo/AI 修订；生成完成后作为一次正式修改落地。中断时显示部分内容的保留/丢弃选择；不把截断内容伪称完整。

## 一致性与回退

- 发送时记录选区与编辑版本；每次按块索引写入前重新核对文档身份、版本及目标。下载、搜索或生成图片等异步工具在网络返回后再次核对；不匹配时拒绝落地并提示模型重新读取。
- 每轮首次真实修改前捕获正文及附加结构快照，记录该轮完成版本；整轮回退仅在此后无额外手动/其他轮编辑且原文档仍打开时可执行。否则禁用并说明原因，避免上游直接 `setContent(snapshot)` 覆盖后续编辑。
- 服务端会话与工具事件保留真实成功/失败/停止状态。断流后已经落地的编辑仍是未保存改动，侧栏明确列出；用户可回退或手动保存。停止请求不能在后台继续把迟到结果落画布。
- AI 修订开关只决定正式 AI 编辑是否进入修订扩展，默认关闭。读工具与写作草稿不制造修订。
- 对外媒体抓取只接受 HTTP(S) 并做私网/回环地址防护、重定向逐跳检查、体积与 MIME 限制、超时；本地媒体通过用户选择文件上传到受控临时存储，分析后按既有清理策略释放。禁止模型传本机路径直接读服务器文件。

## 兼容与迁移

- `EditorIo` 的字节 `load/save` 保持原用途；另加可选 DOCX agent 句柄/宿主服务接缝，不影响 XLSX、PPTX、HTML、PDF 编辑器。
- 主视图对话与非 DOCX 侧栏不注册写工具。已有单篇检索、引用、历史消息和失败卡仍用当前 AG-UI 消息 part 路径。
- 不新增文档真相存储。DOCX 原件及既有知识库记录仍是持久化来源；未保存的画布状态只存在当前编辑会话。
- 若用户未配置外部服务，本地 DOCX 工具照常使用；界面标出相关外部能力不可用的原因，不能宣称“完整工具已可用”。

## 重要取舍与实施风险

- **完整范围一次交付**：本任务不能以“先接文本工具”为完成标准。实施可按垂直切片递进，但最终需通过 36 工具与 15 子操作矩阵。
- **上游同步**：工具层的功能依赖比现有 vendor 多，先用固定 commit 建立来源映射和差异检查，禁止手工修改 vendor 或让保存退化成全量重建。
- **TanStack AI 接缝**：安装包源码提供内建 agent loop、client tool 中断/续轮、`generateImage` 与多模态输入，但 Mimir 的模型包装尚未暴露工具参数，问答流还会剥掉 `RUN_FINISHED.outcome`。将读取/写入/续轮及多轮用量的端到端实验放在实施第一步，实验结果决定具体适配位置，产品行为与工具范围不变。
- **浏览器运行时选择**：现有 assistant-ui + AG-UI 对检索问答合理，对 TanStack client-tool interrupt 尚不完整。首个实验必须覆盖 `outcome`/`resume`/`parentRunId`、工具只执行一次、结果/错误续轮、停止、排队和历史重载；协议桥失败时迁到 TanStack React 并补齐既有交互。36 工具的输入/输出合同须单一来源，避免两端定义漂移。
- **外部供应商**：参考供应商与模型可能有地区、额度或输入格式限制。配置页应检测各能力，给出明确状态；测试要区分适配器契约测试与真实凭据的效果验证。

### PDF 保留结构的手动页面工作副本

旧单页裁剪/纸型、复制和导入的页面引用已能预览，但在含AcroForm/Outlines的原件上回落整体重建。新增严格`apply_page_layout`本地合同：现有页引用或空白尺寸、绝对旋转、相对源CropBox的四边内缩和目标纸型；服务保留Catalog和原页面对象，重复页复制控件并绑定同一个原字段。水印/页码按新页面重绘。自有绘图保留既有图层与复制后的独立ID；含可编辑绘图页面的裁剪/纸型/旋转组合须明确拒绝，直到缓存能表达该几何变换。标签树迁移、签名、活动动作继续拒绝；来源含AcroForm的导入沿既有明确拒绝，不复制悬空Widget。

Office统一工作副本物化函数先按用户已选来源追加导入页，再以layout恢复最终页序/几何；只返回临时字节，操作成功或手动保存后才发布。当前未保存页面变更可供本地工具继续操作，不隐式持久化。源选择/失败/取消/版本过期不得改变dirty/history。旧纸型和裁剪菜单保持幂等档位，保存后undo/redo保留历史。输出置于300px Inspector顶部并随生成结果回到可见位置。

### 2026-10-16 PPTX 文稿视图与新 Inspector 集成边界

PPTX当前仅有普通编辑画布与全屏放映，补齐固定GenOffice的普通/大纲/幻灯片浏览/阅读四种工作区视图。新增PptxWorkspaceViews及局部CSS；PptxViewControls提供四个短标签当前态入口，Editor只持有文档绑定模式及整合原编辑stage。大纲按真实文本提取标题/正文并导航，旁边仍为原可编辑画布；≤650px编辑容器将大纲置顶保留画布。浏览采用持久slide.path多选、Shift范围、Ctrl/Cmd全选、拖拽边界及前后移动，双击/Enter回普通编辑。阅读在应用内按可用宽高与原件比例适配，局部方向键/Home/End/PageUp/PageDown翻页，Escape回普通并恢复真实可见入口（折叠时回来源组）。视图/导航不写session、不dirty。
