# 在当前文档中通过对话修改 DOCX

## 当前扩展范围（2026-10-17）

以下初始DOCX需求和验收保留；用户后续已明确要求对标固定GenOffice补齐六格式Agent及手动工具，着重工具栏，并要求样式与交互可用。此授权扩展原有范围，覆盖Markdown/DOCX/XLSX/PPTX/HTML/PDF的实际可执行工具及子参数；不能只注册工具名或加禁用按钮。当前逐项依据为 `research/editor-all-tools-final-parameter-audit-20261017.md`、`research/all-tools-completion-ledger-20261017.md` 及各格式矩阵与原生/浏览器报告。

用户另明确批准当前PDF内本地临时OCR供复制与搜索，不写原件/知识库索引，不新增付费模型；该窄例外已记入product.md。界面遵循紧凑Ribbon、320px Inspector、内部滚动/固定单一主动作、1280×800与420×500浏览器验收；Desktop由用户自行验收，当前先完成代码和界面，无配置provider不得声称真实模型成功。新建/更改密码需用户亲自输入、确认并提交。所有工具完成仍须当前源码的独立检查、相应原生与浏览器证据和最终原样pnpm check；历史已绿窗口不能替代新代码门禁。

## Goal

用户在 DOCX 文档页的“问 AI”侧栏用自然语言提问或提出修改要求。Agent 读取当前画布，调用 GenOffice 完整 DOCX 工具集修改画布，用户能看到执行过程、回退整轮修改，并沿用 Mimir 的手动保存把结果写回知识库原件。

## Background and confirmed facts

- 文档侧栏目前复用 `ChatPanel`，按 `documentId` 做单篇检索问答；正文取自已保存的知识库记录，不能读取未保存的编辑状态（`packages/renderer/src/components/document/DocChatSidebar.tsx`、`apps/server/src/services/assistant-stream.ts`）。
- DOCX 画布由 `DocxEditor` 持有；宿主 `EditorIo` 只有字节 `load/save`，未暴露工具执行所需的编辑器句柄与附加结构（`packages/office/src/editors/DocxEditor.tsx`、`types.ts`）。
- DOCX 通过补丁式保存保留未改动的 OOXML；当前 `DocxSession.save(edited)` 只接收正文模型。完整工具集还会修改样式、页眉页脚、批注等附加结构，保存契约需要扩展（`packages/office/src/docx.ts`、`.trellis/spec/office/engine/index.md`）。
- 固定的 GenOffice 上游版本 `480548fd55f1be3593ee0d8e316a734751d58309` 有 36 个 DOCX 顶层工具：29 个内联定义、7 个导入定义。上游 `AgentLoop` 负责工具轮询与首次修改前快照；格式工具负责实际编辑。现有 vendor 清单跳过了 agent 层（`packages/office/vendor/UPSTREAM.json`）。逐项清单与接缝见 `research/docx-agent-inventory.md`。
- 上游网页/图片搜索、图片生成、媒体分析经 Electron `window.desktop` 调用；Mimir 尚无等价服务。用户同意首版由使用者在设置中配置第三方服务凭据，服务未配置时如实告知。
- Mimir 已使用 `@tanstack/ai@0.55.0`。该版本内建工具循环、客户端工具续轮与 `generateImage()`；方案应以 TanStack AI 为 agent 编排核心，能力与现有包装层差距见 `research/tanstack-ai-capabilities.md`。
- 当前浏览器对话包使用 assistant-ui + AG-UI。与当前 TanStack 核心兼容的 React 客户端也已有工具与队列能力，但 Mimir 的实时/历史引用、检索过程和失败按消息 part 统一的契约仍由 assistant-ui 承载。TanStack client-tool interrupt 与 assistant-ui 普通工具结果续轮并不直接等价；本任务先验证协议桥，若不能可靠续轮则迁移浏览器运行时并恢复既有交互，见 `research/chat-runtime-assessment.md`。
- 用户指定竞品分工：知识库 Agent 参考 WeKnora；页面布局和视觉风格参考 Obsidian；文件编辑参考 Office 网页版、Google Docs 和 GenOffice。每次调研仍核对 WeKnora，但 DOCX 工具栏不以其 Markdown 编辑器为主要依据。

## Requirements

- **R1 入口与对话**：DOCX 文档页沿用现有“问 AI”侧栏，一个对话入口同时支持针对当前文档的问答与修改；保留原有流式回答、检索、引用、停止和会话行为。主视图的库级对话不获得文档写入权限。
- **R2 完整工具能力**：首版覆盖上述固定版本全部 36 个 DOCX 顶层工具及 `apply_ops` 的受支持操作。覆盖正文读取/写入与格式、修订、批注、脚注/尾注、图片与图表、页面与节、样式、水印、文本框、页眉页脚、网页/图片搜索、图片生成、媒体分析和 `create_document`。工具必须真实执行，不能仅注册名称或返回成功占位结果。
- **R3 新文件**：`create_document` 按上游支持 DOCX、PDF、Markdown、HTML 四种新文件的创建，并将新文件加入 Mimir 知识库、打开相应文档页；这不等于开放 PDF/Markdown/HTML 现有文档的对话编辑。
- **R4 当前状态与定位**：Agent 读取当前画布，包括未保存的手动编辑；用户可针对选中文字或整篇发指令。选区在发送时冻结。使用块索引的工具在文档被用户另行修改后须重新读取或拒绝过期操作，不得覆盖新内容。
- **R5 GenOffice 交互**：工具执行时直接更新画布，在侧栏显示逐步状态和真实结果；每轮首次修改前留快照，完成后提供整轮回退。长文写作在画布中流式展示草稿，中断时明确处理保留或丢弃部分草稿。可选“AI 修订”默认关闭；开启后 AI 改动可在修订流程中接受或拒绝。
- **R6 保存与失败**：AI 改动进入现有未保存状态、保存按钮和离开守卫；首版不因 AI 修改自动保存。保存须覆盖工具修改的 DOCX 附加结构，并经保存后重开验证。工具失败、停止、切文档、保存冲突时必须报告实际结果，不能声称已完成未落地的修改。整轮回退不能静默撤销其后发生的手动编辑。
- **R7 通用外部能力**：模型、图片生成、视觉输入和音频转录由通用“模型”设置管理；网页/图片搜索由通用“网络搜索”设置管理。DOCX Agent 按需使用已配置能力，侧栏只展示当前可用性并链接到相应设置，不另设“DOCX AI”分区或 DOCX 专属凭据。已有 `docx.*` 配置须无损迁移，尤其保留加密密钥。配置后工具可真实使用；未配置或服务失败时显示明确原因，不把服务失败伪装成空结果。外部图片下载与媒体输入受大小、类型、超时和地址安全限制；本地媒体经用户选文件上传，不要求浏览器读取任意本机路径。竞品与设计依据见 `research/settings-competitor-research.md`。
- **R8 来源与权限**：DOCX 工具只作用于当前已打开且有权限的文档；新文件创建沿用知识库上传/解析/索引路径。模型调用继续经 TanStack AI 与 `plugins/provider` 接缝，并进入用量记账；第三方密钥只存于服务端现有加密设置，不下发浏览器。
- **R9 文档头部一致性**：笔记、DOCX 及其他上传文件和只读资料共用用户指定的笔记头部组件与布局；保留各格式按能力显示的下载、笔记改名和更多操作，以及离开时的未保存保护。
- **R10 编辑器保存布局**：六种编辑器共用外壳不再在顶部工具栏右侧为保存按钮预留整列；保存入口放在始终可见的底部状态行右侧，保留各格式原有的保存、禁用原因、状态反馈和未保存保护。
- **R11 三栏头部对齐**：工作区侧栏、文档区和问 AI 侧栏的头部高度与下边框统一；窄屏侧栏覆盖文档时，当前可见头部的标题和关闭操作仍可用，文档返回入口仍可达。
- **R12 DOCX 工具栏整理**：以 Office 网页版、Google Docs 和 GenOffice 的文件编辑交互为依据，DOCX 格式工具栏使用稳定的紧凑单行布局，当前段落样式和高频文字格式应易于识别与操作；低频命令按字体、段落、插入、表格、审阅等任务归入具名菜单，并始终有可发现的“更多”入口。折叠取决于文档编辑区可用宽度，包括问 AI 侧栏打开后的中栏，不得以纵向滚动命令区作为主要窄屏方案。保留全部现有 DOCX 手动编辑命令、状态、禁用原因与已实现快捷键；不改变六格式共用的底部保存位置。竞品证据与适用边界见 `research/toolbar-competitors.md`。
- **R13 其余格式工具栏整理**：项目现有六种编辑器为 Markdown、DOCX、XLSX、PPTX、HTML、PDF；DOCX 之外的五种也按各自任务和宽度整理工具栏。直接展示当前格式高频操作，低频或上下文命令用有名称的菜单或清晰入口收纳；工具栏优先保持单行，查找栏、工作表/幻灯片导航、单元格编辑等已有独立区域按功能保留。以编辑区实际宽度响应三栏与窄屏，不再依赖被截断的纵向命令滚动。每种格式的原命令、当前状态、禁用原因、危险操作确认、快捷键和底部保存行为都必须保留；不增加引擎尚不支持的编辑能力。格式逐项清单见 `research/all-editor-toolbar-inventory.md`。
- **R14 知识库文件识别**：知识库列表和卡片中的上传文件显示当前原件的真实后缀，文件类型图标应能单独区分常见文档与媒体格式。后缀和图标来自同一当前文件类型，不因上传时生成的无后缀标题或替换原件而误导用户；笔记、网页等非上传文件保持原有标题。长文件名与窄栏仍可读，打开和文件操作不回退。

## Acceptance criteria

- [ ] **A1（R1、R4）**：在有未保存手动改动的 DOCX 中提问，回答或编辑依据画布最新内容；选区修改只影响发送时所选文字。原单篇问答、引用与主视图库级对话回归通过。
- [ ] **A2（R2）**：36 个工具逐项有可执行契约和验证证据；代表性 `apply_ops` 批量操作在参数无效时整体拒绝、文档不被部分修改。
- [ ] **A3（R2、R5、R6）**：正文、格式、修订、批注、脚注/尾注、图表、浮动对象、页面/节、样式、页眉页脚等各类修改在画布可见；保存并重新打开后结构与内容仍正确，未修改的 OOXML 部件保持补丁式保存性质。
- [ ] **A4（R5、R6）**：侧栏显示工具开始、完成、失败和停止状态；整轮回退准确恢复该轮前的编辑状态。该轮后若用户继续手动修改，回退需拒绝或安全处理，绝不丢失后续修改。
- [ ] **A5（R5）**：长文写作可见流式草稿；中断时能明确保留或丢弃部分内容。AI 修订开/关两条路径可分别保存并重开、接受或拒绝。
- [ ] **A6（R6）**：AI 修改触发未保存提示，手动保存成功后重新打开保持结果并可检索；保存失败不清除脏状态，不允许离开守卫误报成功。
- [ ] **A7（R7）**：通用“模型”和“网络搜索”设置可配置并检查对应能力，设置导航没有“DOCX AI”；DOCX 使用同一配置且侧栏指向正确设置。升级后原 `docx.*` 凭据继续生效且不暴露给浏览器。配置服务后，网页与图片搜索返回真实结果，生成图片及外部图片可插入 DOCX，文档图片和上传的音视频可分析。未配置、超时、无结果、服务错误各有不同可见状态。
- [ ] **A8（R3、R8）**：`create_document` 的四种类型均进入知识库并能打开；创建失败不留下声称成功的对话结果或不可用记录。没有当前 DOCX 编辑上下文时不能执行写工具。
- [ ] **A9（R4、R6）**：工具下载期间人工编辑、切换文档、停止生成以及过期块索引均不会把旧操作落到错误文档或覆盖新内容。
- [ ] **A10（R2、R8）**：工具调用、续轮与图片生成经 TanStack AI；不支持 function calling 的已配置聊天模型明确显示能力错误，多轮用量逐次记账。
- [ ] **A11（R1、R2、R5）**：DOCX 客户端工具只执行一次，`outcome`、`resume` 和 `parentRunId` 连贯，结果或错误被模型续轮读到；停止、排队、历史重载后仍能正确关联工具状态与所在消息，原单篇问答的引用/失败展示无回归。
- [x] **A12（R9）**：笔记、DOCX、其他文件与只读资料的头部使用同一组件、尺寸、返回按钮与标题布局；长标题和窄屏下关键操作仍可达，下载、改名、问 AI、更多操作和未保存离开守卫正常。
- [x] **A13（R10）**：笔记与 DOCX、XLSX、PPTX、HTML、PDF 的顶部工具栏不再出现固定保存列；底部状态行可见且可操作保存入口，窄屏仍可达，保存成功/失败和未保存离开行为不回退。
- [x] **A14（R11）**：三栏同时可见时工作区、文档和问 AI 头部的下边界处于同一水平线；窄屏侧栏覆盖文档时，侧栏标题、关闭与文档返回操作仍可达。
- [ ] **A15（R12）**：DOCX 工具栏在宽文档区、问 AI 打开后的实际中栏宽度和约 420px 窄屏下保持单行且操作可达，不出现命令被裁切或依赖内部纵向滚动查找的情况；撤销/重做、样式、中文/西文字体、字号、字符效果、颜色、对齐、行距、列表/缩进、表格、图片/链接/分页符、段落移动、查找替换、修订和拼写检查均可找到并真实生效。当前值、按下态、禁用原因、键盘操作与快捷键保持正确；原有文档头部、底部保存、其余格式工具栏不回退。
- [ ] **A16（R13）**：Markdown、XLSX、PPTX、HTML、PDF 五种工具栏在宽编辑区、问 AI 打开后的中栏和约 420px 窄屏下不会因折行或内部纵向滚动挤占画布；每个现有命令可见或可从具名入口找到并真实生效。Markdown 的方言相关命令与上下文表格/代码语言、XLSX 的工作表/单元格/公式/查找、PPTX 的整段文字格式与导航、HTML 的视图/设备/缩放/查找、PDF 的页面/裁剪/纸型/导入/删除确认/查找/缩放均按各自语义保留。键盘、菜单焦点、禁用原因、底部保存与独立次工具栏回归通过；六种格式之间不出现控件密度和状态样式漂移。
- [ ] **A17（R14）**：真实知识库的列表和卡片视图中，PDF、DOCX、XLSX、PPTX、HTML、文本及常见媒体文件凭图标可区分，上传文件名显示当前原件后缀且不重复；笔记等非上传内容不被附加后缀。替换原件或未知格式时如实显示已知类型并安全回退；长标题、窄栏、打开与操作按钮正常。

## Out of scope

- 初始阶段曾排除XLSX、PPTX、PDF、HTML、Markdown现有文件的对话编辑；该限制已被上方用户后续六格式授权取代。
- 由 Mimir 运营的免配置付费搜索、图片或媒体云服务。
- AI 修改后自动保存原件，或绕开用户现有保存流程。
- 在本轮新增全局命令搜索/斜杠菜单，或增加六种编辑器尚不支持的文件编辑命令。
