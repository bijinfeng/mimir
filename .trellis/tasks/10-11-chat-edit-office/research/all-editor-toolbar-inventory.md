# Six-editor toolbar inventory and reference scope

- Date: 2026-10-12
- Question: After the DOCX toolbar, which existing Mimir editor commands and state must remain reachable when all six toolbars are made compact?
- Scope: repository source and pinned competitor source / official product documentation; no claim of live competitor editor measurements.

## Reference roles

The user assigned WeKnora to knowledge-base Agent work, Obsidian to page layout and visual style, and Office for the web, Google Docs and GenOffice to file editing. The required WeKnora check is already recorded with version and source in [toolbar-competitors.md](toolbar-competitors.md#weknora-required-applicability-check-not-the-docx-toolbar-model); its Markdown editor has too few DOCX commands to set the toolbar structure. Obsidian's role in this pass is the quiet, content-first workspace surface already documented in the [project design spec](../../../spec/project/design.md); it does not supply Office or PDF command semantics.

Office for the web documents a compact single-line ribbon, and Google Docs documents menu categories and menu search; both sources and evidence limits are in [toolbar-competitors.md](toolbar-competitors.md). The pinned [GenOffice DOCX Ribbon](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/docs/src/renderer/components/Ribbon.tsx#L316-L400) uses task tabs and contextual table/picture tabs. Its [Markdown ribbon](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/markdown/src/renderer/components/Ribbon.tsx#L260-L385) groups formatting, lists and insertion beneath a quick-access row; its [HTML ribbon](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/html/src/renderer/components/Ribbon.tsx#L201-L270) separates quick access and command groups, with [preview/view controls](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/html/src/renderer/components/Ribbon.tsx#L514-L540). The [slides ribbon](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/slides/src/renderer/components/Ribbon.tsx#L146-L173) defines main and contextual tabs; [sheets command dispatch](https://github.com/genspark-ai/genoffice/blob/480548fd55f1be3593ee0d8e316a734751d58309/apps/sheets/src/renderer/ribbon-actions.ts#L195-L220) is separate from the DOCX code. This pinned-source check establishes format-specific command semantics; detailed pixels and responsive behavior were not measured in a running GenOffice instance. Mimir should use the separation while keeping its own narrower three-column shell.

## Mimir inventory from code

The current `EditorShell` is used by exactly six editor components. Its shared `.mimir-editor__tools` rule wraps all controls, and the ≤880px rule limits height to 128px and adds vertical scrolling. This is a cross-format source of narrow-pane command hiding; DOCX was measured in the browser, while the other five below are code inventory until their own browser pass.

| Editor and source | Current toolbar commands / related area | Compact-layout priority and preservation risk |
| --- | --- | --- |
| [Markdown](../../../../packages/office/src/editors/MarkdownEditor.tsx#L735-L1075) | Undo/redo; paragraph style; bold/italic/underline/strike/code/clear; link; bullet/number/task lists; indent; table/image/rule insertion; contextual table and code language; spellcheck. `variant="note"` already creates a horizontal single row. | Keep style/basic character format/link visible. Use named overflow for list, insert and context actions; preserve dialect-aware availability, code-language and table context, non-GFM underline explanation, note styling and bottom save. Do not hide commands only by offscreen horizontal scroll. |
| [XLSX](../../../../packages/office/src/editors/XlsxEditor.tsx#L403-L524) | Multiple-workbook-sheet tabs; in-sheet find with count and previous/next; formula-cell navigation; copy/clear selected cell; cross highlight. ## Implementation constraints and verification

- `EditorShell` and `shell.css` are shared across all six formats. GitNexus reports `EditorShell` as CRITICAL impact; prefer opt-in editor wrappers and scoped styling, then test every editor if a shared primitive changes.
- Fold based on the editor pane's actual width. The AI sidebar can make the center pane narrow while the viewport remains wide, so a viewport-only media query is insufficient.
- Avoid two active copies of the same command in direct and overflow surfaces. Use the same callbacks/state/disabled explanations for either presentation, and ensure keyboard focus returns sensibly after a menu action.
- Browser acceptance requires wide, AI-sidebar-open and approximately 420px views for **each** editor. Source review alone cannot establish final control heights, overflow or popup placement.
