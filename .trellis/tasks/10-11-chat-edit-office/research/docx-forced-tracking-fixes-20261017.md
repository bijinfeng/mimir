## Scope and changed files

Read the formal checker report and retained its seven added rows unchanged. Three confirmed defects were fixed in the original T owner files. No W2 UI, shared specs, vendor/server/XLSX, uploads/deletions, stage/commit/archive changed in this fix. `docx.ts` was explicitly released to the privacy owner before these changes; its private protection assertions/readback comparator remain unchanged by me.

- `packages/office/src/editors/docx-forced-tracking.ts`
  - Filter tracks prior step output ranges in the next step's coordinate space. Any later edit inside a previous replacement/insertion, or across a previous deletion boundary, refuses the complete transaction through the normal blocked reason before state/history/version publication. The single-transaction `insertText('abc',1).delete(2,3)` repro now refuses atomically without an appendTransaction exception. Disjoint and adjacent non-overlapping replacements remain supported.
  - A single forward deletion originating at the caret restores retained deleted text and places the caret after that retained span; backward deletion/replacement retain their prior placement. Consecutive forward Delete now reaches `Alp`, while the original Backspace regression still passes.
  - A transaction consisting only of re-deleting retained `del` text is refused before publication, so unchanged tracked state does not create history/version updates.
  - New styled inserted text now publishes the exact fresh raw rPr generated by existing vendor `inlineToRuns` + `mergeRPrModel`, when the text did not already carry a raw representation. This repairs an additional native-save defect exposed by the retained-supported-inline-style regression. It does not loosen the final full native/PM comparator or rewrite existing original run properties.
- `packages/office/src/agent/docx-agent.ts`
  - Mandatory `forcedText` accepts a default plain paragraph and supported inline elements. Raw paragraph attributes and unsupported elements are refused before schema parsing can silently discard them. The parsed block must also have the exact default paragraph type/attrs.
  - Both `<h1>…</h1>` and `<p style="text-align:right">…</p>` now refuse with the forced-tracking boundary and leave doc/version/history/dirty exact. Ordinary `<p>…</p>`, `<strong>` and `<em>` remain usable and savable.
- `packages/office/src/docx-forced-tracking.ts`
  - Native eligibility accepts bCs/iCs/szCs only when the corresponding b/i/sz property is present and semantically equal in the same rPr. This is necessary for reopening the exact modeled output generated for new bold/italic/size text. A lone or conflicting complex-script twin remains readonly; unknown properties/structures remain refused.
- `packages/office/src/docx-forced-tracking.test.ts`
  - Checker rows preserved. Added four meaningful rows: overlap has zero publication while disjoint steps save; re-deleting already-deleted text has zero publication; adjacent non-overlapping replacements save; supported bold/italic Agent text saves/reopens and accepts another tracked edit.
  - Extended native qualification refusal table with conflicting/lone bCs/iCs/szCs properties.
