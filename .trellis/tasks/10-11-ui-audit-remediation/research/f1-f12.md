### F1 · 自动保存期间“丢弃”失真 · P1

- 路径：`packages/office/src/editors/MarkdownEditor.tsx:329-370` 在更新后 900ms 防抖自动保存；`packages/renderer/src/components/NoteEditor.tsx:65-79,171-172` 连接脏标记和保存句柄；`packages/renderer/src/lib/unsaved.tsx:61-91` 持有离开确认，`discard` 只设 `false` 并执行导航；`packages/renderer/src/components/UnsavedGuard.tsx:37-72` 固定呈现三按钮。异步保存与弹窗状态各自演进，确认框打开后可继续完成保存。
- 最小正确修法：由离开守卫与 Markdown 编辑器共享当前未保存版本/保存进行中状态；确认框中一旦该版本已持久化，就不再声称可“丢弃”它。真正的“丢弃”要取消尚未发出的定时器并处理已在途写入；若保留已写入版本的回滚能力，需要持久化前快照并通过服务端版本控制避免晚到写覆盖。不能只改按钮文案或清 `isDirty`。还需检查 Office 编辑器的同一守卫契约，避免改动只适用于笔记。
- 验证：编辑后立即离开，分别在防抖前、请求进行中、已成功、保存失败阶段选择三项；重开文档比较**服务端实际正文**。模拟延迟/失败，确认丢弃后不会有迟到写入，保存失败不放行；测试切换另一篇、返回库、侧栏导航三种离开入口。

### F2 · 快捷键提示不符 · P2

- 路径：`packages/office/src/editors/MarkdownEditor.tsx:609-680` 及后续工具按钮的 `label` 写死 `Ctrl+...`；渲染器共享 Web/Electron。
- 修法：集中按平台生成 Mac `⌘` 与其他平台 `Ctrl` 的操作提示，所有编辑命令的 tooltip 与可及名称共用；只显示 Tiptap/浏览器实际上接受的组合。不要改全局键盘绑定来迁就错误标签。
- 验证：macOS 上 `⌘Z/⌘⇧Z/⌘B` 和 Windows/Linux 对应 Ctrl 组合，工具提示/可及名称逐项一致；已有命令功能保持有效。

### F3 · 账号主题子菜单跨页残留 · P2

- 路径：`packages/renderer/src/components/NavSidebar.tsx:256-268,299-311,340-384` 已受控 `themeOpen`，并在 Dropdown `onOpenChange(false)` 收起子菜单；但父 Dropdown 的 `open` 未受控。导航动作在 `NavSidebar.tsx:73-98`，账号入口 `:380-382` 调这些动作；页面切换时侧栏继续挂载。
- 修法：父菜单也受控，并在导航/route location 变更时同步关闭父子两层；菜单项选择、Esc、外点击统一清理子菜单状态并恢复焦点到仍存在的触发按钮。需实测 portal 卸载时机，保留已有 `flushSync` 处理主题选中路径。
- 验证：展开主题后点设置/知识库、按 Esc、外点击、选择主题；DOM 无孤立子菜单，重新打开从收起态开始，焦点回账号按钮。

### F4 · RSS URL 反馈笼统 · P2

- 路径：`packages/renderer/src/components/settings/FeedsSection.tsx:38-61,101-129` 仅检查非空，输入直接交 `api.feeds.create`，错误走全局 toast。服务端 schema/抓取路径需一并看（`apps/server/src/routes/feeds.ts`、服务端 feed/capture 实现）。
- 修法：前端在提交前用 `URL` 校验绝对 `http:`/`https:` 地址，给输入旁可读错误并以 `aria-describedby`/`aria-invalid` 关联；服务端错误具体原因仍展示，保留草稿。按钮和 Enter 共用同一校验/提交函数。
- 验证：空、`bad url`、`ftp://...`、合法 https 地址；无效值不发请求，错误可定位；真实服务端失败仍能更正输入。

### F5 · 设置草稿卸载丢失 · P2

- 路径：`packages/renderer/src/components/settings/AccountSection.tsx:218-280` 的 `NameField` 本地 `draft`；`StorageSection.tsx:106-129` 条件渲染 S3 字段；`SettingControl.tsx:65-84` 本地 `draft`。切设置分区或收起时会卸载，草稿丢失。`SettingControl.tsx:81-84` 服务端值更新时还会覆盖未保存输入，需决定冲突语义。
- 修法：账号与 S3 配置的草稿提升到设置页会话级/持久挂载层，按设置键保存；明确保存成功、主动丢弃、服务端值变更后的更新规则。若用离开提示，分区切换与 S3 收起都必须覆盖，且应能保留草稿继续编辑。Secret 不宜写 localStorage/sessionStorage。
- 验证：输入名称/S3 Access Key 后切分区或收起再回来，草稿仍在或出现明确确认；保存后重载显示服务端值；取消与失败不丢输入，Secret 不泄漏到持久浏览器存储。

### F6 · 供应商错误无法聚焦/关联 · P2

- 路径：`packages/renderer/src/components/settings/ProviderForm.tsx:270-283,329-411` 设置 `errors`、toast、字段旁 `<div>`，但名称、接口地址、密钥均无 `aria-invalid`/`aria-describedby` 与错误焦点。模型行在 `:456-617` 也需要沿相同逻辑检查。
- 修法：稳定字段 ID/错误 ID；无效时输入设 `aria-invalid`、`aria-describedby`，提交后聚焦首个错误（包括模型行）并将错误区域以适当 live 语义告知。编辑字段时清对应错误。避免只把焦点留在保存按钮。
- 验证：空表单、错误 URL、缺密钥与模型 ID；首个错误获焦，DOM 关联准确，键盘逐项修正；用屏幕阅读器复核读出。

### F7 · 关闭后的焦点回退 · P2

- 路径：文件夹重命名 `packages/renderer/src/components/library/LibraryView.tsx:290-292,704-729` 使用 antd Modal，但触发项在 `FolderRowMenu` portal (`:862-894`)；文档问 AI `DocumentPanel.tsx:545-548,846-860` 关闭只是折叠并设 `inert`，按钮在 `document/DocChatSidebar.tsx:99-108`；窄屏侧栏开关及关闭在 `NavSidebar.tsx:167-198`；从知识库打开收集通过 `LibraryView.tsx:188-191` → `_app.tsx:132-135,338-345` 的常驻 Dialog。
- 修法：打开时捕获实际触发元素引用；关闭后 `requestAnimationFrame`/布局提交后恢复到仍连接 DOM 的触发元素，若卸载则聚焦当前视图标题/主操作。DocChat 折叠前务必先转移焦点，避免把焦点留在 `inert` 子树。收集浮层应由全局壳统一管理 origin，而不能只让全局侧栏入口恢复焦点。
- 验证：四种报告中的路径逐个用键盘打开、Esc/取消/关闭，检查 `document.activeElement`、可见焦点环、Tab 顺序；若触发器卸载，落到明确备用控件。

### F8 · 窄屏侧栏与背景同时可操作 · P2

- 路径：`packages/renderer/src/routes/_app.tsx:170-186,286-303` 仅把 `overlayOpen` 交给 NavSidebar，主区 `<Outlet />` 未 inert；`NavSidebar.tsx:128-130,186-198` 只显示绝对定位的浮动 panel；`NavSidebar.style.ts:67-75` panel 从 52px rail 向右覆盖 242px，没有遮罩或背景点击处理。
- 修法：明确按模态浮层处理：给主内容遮罩/`inert`，管理 Esc、焦点围栏和关闭后焦点恢复；或按非模态处理：背景点击即收起且主内容操作不被遮挡。报告里用户点击背景却仍保留浮层，建议模态方案更符合浮动遮盖现状。
- 验证：600px 打开后鼠标点击背景、Tab/Shift+Tab 不进入背景；Esc 和关闭按钮复位到开关，窗口放宽/路由切换时不残留 `inert`。

### F9 · 触屏卡片操作不可发现 · P3

- 路径：`packages/renderer/src/components/library/LibraryView.style.ts:381-395` 动作区默认 `opacity:0`，只在 hover/focus-within 显示；`LibraryView.tsx:862-894` 已有“更多”操作按钮。
- 修法：在 `@media (hover: none)` 或窄视口让主要/更多操作常显，保持 focus-within 和键盘路径；检查卡片/行布局，避免可见按钮挤压标题。若只让更多常显，要确认所有原有操作能从菜单到达。
- 验证：600px 及真实触屏或触摸仿真在未触发 hover 时可看见并点到，桌面 hover/键盘路径无回归。

### F10 · 问 AI 范围文案过度承诺 · P3

- 验证：打开侧栏时显示默认范围，切换另一文档后文案不矛盾；无模型调用即可核对控件状态。

### F11 · 收录数包含回收站文档 · P3

- 路径：`apps/server/src/services/chunks.ts:306-318` 对 `chunks` 全表读出并按 documentId 去重；`documents.ts:385` 软删除；`RetrievalSection.tsx:70-74` 显示 `status.documents`；接口 `apps/server/src/routes/documents.ts:218` 调 `chunkStats`。同文件 `chunks.ts:240-251` 的待嵌入分块计数也未过滤已删除文档，可能产生相关的状态误差；`rebuildAllChunks():332-344` 只重建未删除文档，却不会主动清理旧分块。
- 修法：`chunkStats` 与待嵌入状态使用 join `documents` 且 `deletedAt IS NULL`，两个方言都要通过；适当在删除时清理分块或维护批次里清理墓碑分块，但先确保用户可见计数真实。避免把标签改成“包含回收站”掩盖不一致。
- 验证：创建含正文笔记使其产生分块，读取统计；软删除后知识库与“已收录”均减少且搜索/语义补全不处理它；恢复（若支持）后计数恢复。SQLite 必测，SQL 分支按 server/tests 规范在 Postgres 测。

### F12 · S3 字段无可访问名称 · P2

- 路径：`StorageSection.tsx:117-127` 将 `Row label={entry.label}` 与 `SettingControl entry={entry}` 分开；`settings/parts.tsx:47-64` 的 `Row` 仅渲染视觉 `<div>`；`SettingControl.tsx:127-176` 的 Input/InputNumber/Switch/Input.Password 没有 `aria-label` 或与 Row 标签的关联。
- 修法：在可复用 `SettingControl` 上为四种控件类型统一传稳定名称（`entry.label`，必要时结合 Row 的稳定 ID）。不要依赖视觉邻近；路径风格开关也要名称。`Row` 可升级语义，但避免双重名称。
- 验证：展开 S3 六个文本/秘密控件和路径开关，用 DOM/无障碍树确认名称；键盘与屏幕阅读器读出匹配行标题；SettingControl 其它使用处无回归。
