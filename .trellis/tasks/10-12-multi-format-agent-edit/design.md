# 设计：五格式 Agent 与手动编辑对齐 GenOffice

## 基线与范围

固定 `genspark-ai/genoffice@480548fd55f1be3593ee0d8e316a734751d58309`。父任务维护可机读的能力矩阵：格式、上游源码位置、顶层工具或内部操作、是否模型可调用、手动命令、Mimir 执行层、依赖、测试和浏览器/桌面实测状态。`research/genoffice-five-format-inventory.md` 是起始清单；每个子任务补齐逐项矩阵并以它决定工具目录。上游标记 `not-ai-callable` 的操作不能因“手动功能对齐”被误注册给模型。全任务只有全部子任务和跨格式验收完成才算交付。

## 边界与数据流

1. `packages/shared` 定义 `DocumentAgentFormat`、工具元数据、运行时请求/结果 schema 和按格式的能力响应。工具名允许在格式间重复，但请求必须携带服务端验证的文档 ID 与格式；不能由客户端请求传任意工具定义。
2. `apps/server` 继续以 TanStack AI 执行模型循环，按已鉴权文档选择工具与格式 prompt，保持 AG-UI 的 `RUN_FINISHED.outcome → client_tool_* → resume → parentRunId` 生命周期。DOCX 现有记录和历史按兼容迁移处理；新增记录带格式判别，重复、过期、中断集合不匹配均拒绝。外部搜索、图片生成、媒体分析、文件创建继续使用通用配置和用量记账，服务端仅将已配置的工具暴露给模型。
3. `packages/chat` 接受格式中立的当前画布句柄：`{ documentId, format, getVersion, getContext, freezeSelection, execute, undoRound, dispose }`；格式可扩展草稿、媒体读取等能力。发送时冻结选区与版本，工具返回 `{ ok, changed, version, summary, error?, data? }`。桥接层只执行当前文档、当前格式、当前轮次的工具；停用、卸载或版本变化时结果报错给模型，不把旧结果套到新画布。DOCX 的修订模式作为可选格式能力保留。
4. `packages/renderer` 将 `DocumentPanel`、`OfficeSourceEditor`、笔记编辑器和侧栏连接到该句柄；能力条由格式与服务状态驱动。手动命令和 Agent 工具调用各格式的同一编辑原语，不能产生两份相互漂移的模型。画布 dirty、离开保护、底部保存与可回退轮次沿用现有交互。
5. `packages/office` 按格式提供语义执行器与 UI 命令适配。新增上游代码须通过 `sync-upstream.mjs` 与固定 commit 的 `UPSTREAM.json` 同步；不手改 `vendor/`。浏览器安全的操作可留在客户端；需要 Node、Rust 或 PDFium 的操作走有鉴权的 `apps/server` 编辑会话，桌面本地和浏览器版调用同一 HTTP 合同。

## 需要宿主参与的编辑会话

XLSX 与 PDF 先建立短生命周期、按用户/文档/原件版本绑定的宿主编辑会话。开启时宿主从现有原件存储加载字节并预检大小与类型，返回随机会话 ID、修订号、画布投影与能力状态；所有手动和 Agent 写操作经同一会话串行化并带预期修订号。宿主返回实际变更、最新修订、可渲染投影和可回退快照/令牌；浏览器只在版本一致时应用结果。会话只保留未保存的工作状态，过期或切文档销毁，不成为新的持久化文档真相。

用户点击现有“保存到库”时，执行层先验证原件仍是会话基线，再通过现有原件替换服务提交最终字节、重算正文与索引，成功后更新基线并清除 dirty；失败保留会话和 dirty。保存、回退和并发手动修改必须串行；超时、断线和服务重启显示“未保存会话已失效/需重新打开”，不能虚报成功。XLSX/PDF 引擎若能安全地在浏览器执行某一类操作，也应通过相同版本与工具合同呈现，不在平台之间分叉功能。

## 格式执行层

- **Markdown**：活 Tiptap 文档作为真相，按上游 15 种 `MdOp` 与现有 Mimir 方言适配；笔记仍保存到正文列和 vault。图片、frontmatter、长文草稿单独验证。
- **HTML**：复用已 vendor 的 parse-map、patch 和 `HtmlOp`，13 种操作对同一源码版本整体校验、原子应用；源码和预览元素选择共享版本。保存保留 BOM/换行 envelope，预览注入不进入原件。
- **PPTX**：逐步引入 `pptx-ops` 注册与执行层，扩展现有元素锚点、媒体关系与补丁保存；浏览器安全操作在当前会话执行，Node 依赖由共享宿主服务承接并通过版本校验返回。多 run、布局、动画、图表、母版与未知 OOXML 的保真须按类验证。
- **XLSX**：沿上游 `workbook-dsl` 与 gateway 的计划/应用语义引入完整工作簿模型；公式重算与大表读写需适配 Rust 侧车或等效服务执行器，Univer/相应网格能力为手动入口。原有单格写法不能继续默默去掉 `s` 样式或公式。部分批次已应用时必须报告具体范围与撤销能力，不写“未修改”。
- **PDF**：扩展页面模型为上游内容、批注、图片、表单和页面操作所需的编辑状态；需要 PDFium/字体/OCR/图像处理的部分在共享宿主实现，浏览器保留 pdf.js 画布与可见编辑叠层。保存后用独立阅读器验证，遇到无法保全的 Catalog、签名、表单或未知结构时拒绝写回并说明原因。旧 D-057/D-063 的文字只读结论在本任务实施时更新。

## 手动入口与交互

每个子任务从上游手动编辑 UI 与命令注册表建立逐项矩阵。Mimir 可用紧凑工具栏、上下文菜单、侧面板等方式呈现，但每个目标命令都必须可发现、可聚焦、可执行，有当前值/禁用原因和必要的危险确认。人工选择范围与 Agent 发送时冻结选择为不同状态；异步 Agent 不跟随用户后续的实时选择。一次操作只更新同一画布和保存模型。长任务显示进度、失败点和实际已落地部分；回退只撤销该轮且验证其后的人工版本未变化。

### R9：用工具栏交互表达意图

六格式共用 Office 式可见分类、命名命令组和上下文工具。布局以 Office 网页版的“分类 → 命令组 → 当前选中对象”为参考；固定版 GenOffice 的已执行命令决定各格式控件的语义，未接通的上游占位项不显示为可用。窄编辑列保留分类和命令组，通过命令行横向滚动查看，不按宽度阈值把整组移入“更多”。组内的具体变体可以使用有名称的菜单。

保存、撤销、重做作为快捷操作固定在分类标签左侧，分类标签与命令组分别可横向滚动。保存按钮沿用各格式原有回调、dirty 与保存中状态，底部状态行只展示状态和计数。DOCX、HTML、Markdown 连接真实编辑历史；XLSX、PPTX、PDF 在完整手动历史落地前以禁用态和原因呈现，不把 Agent 单轮回退绑定到全局撤销。固定版 GenOffice 的 Slides、PDF、Markdown、HTML 标签行提供布局参考；不能据此声称 Mimir 已拥有相同的历史引擎。

交互状态承载原先的教程：选择单元格/对象/元素后呈现当前值、上下文操作与可编辑输入；按钮按可用条件禁用并给出原因；状态栏只显示保存、位置、数量和与当前操作相关的短消息。通用快捷键教学、能力清单和无选中时的“点这里”段落不常驻。公式覆盖、PPTX 几何回退和原件写入失败等真实风险仍在相关条件出现时提示。

本轮改动边界在 `packages/office/src/editors`、共享 `shell` 样式，以及文档页“问 AI”空态：更新工具栏布局和已有命令入口，撤下侧栏常驻“快速上手指南”，保留可点击快捷提问。不改编辑原语、Agent 工具目录、文件保存合同和固定版 vendor。当前命令保留原回调；对新入口按点击、dirty、保存、读回逐项验收。浏览器与桌面共同加载这套前端实现。

## 兼容、迁移与回退

- 保留 DOCX 当前工具目录、旧历史展示和未完成轮的错误处理；数据库迁移在 SQLite/PostgreSQL 同步增加格式字段或兼容的新表，不把既有 DOCX 历史清空。旧客户端的 DOCX 能力端点可暂留适配入口。
- 六格式外壳、底部保存、库级问答、单篇引用与普通只读资料均保留。`.md` 上传仍导入笔记，不因 Agent 接入另建文件真相。
- Rust/原生/PDFium 构建产物须覆盖浏览器宿主部署、桌面本地宿主及桌面远端宿主的目标 OS/arch；缺少产物时明确报部署错误，不能静默把工具注册为可用。
- 对已有原件优先补丁或可证明保真的写回；无法安全处理的文件以明确错误拒绝。每一子任务通过其回归后再接下一格式，失败时可关闭该格式能力而 DOCX 与其他格式继续使用。

## 验证重点

服务端鉴权、重复续轮、资源预算、私网/本地路径防护；客户端选区冻结、当前版本、停用和切文档；每种工具参数失败时的实际修改范围；手动与 Agent 交替编辑、保存两次、重新打开、重建索引；同一代表性样本在浏览器版与桌面本地模式运行，桌面远端模式按同一 HTTP 合同验证。真实模型和第三方服务需使用配置凭据单独验证，模拟测试不得记为真实服务验收。
