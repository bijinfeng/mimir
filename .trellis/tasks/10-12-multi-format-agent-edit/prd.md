# 接入五种格式的 Agent 对话编辑

## Goal

用户在当前文档页的“问 AI”侧栏中，以自然语言读取和修改已打开的 XLSX、PPTX、Markdown、HTML、PDF 文档；五种格式的手动编辑也向固定版本 GenOffice 的对应能力对齐。Agent 与手动操作共享实际编辑能力，用户在画布中核对并按现有流程保存。

## Background and confirmed facts

- 用户已确认本轮覆盖上述五种格式。此前 DOCX 任务明确将这些格式的现有文件对话编辑留到后续；这项任务承接该范围，不重复 DOCX 工具开发。
- Mimir 已有上述五种手动编辑器及统一文档页外壳；DOCX Agent 的工具循环、客户端工具续轮、当前画布句柄、未保存状态和手动保存是可复用的现有接缝。
- `.md` 上传后导入为可编辑笔记；HTML 是源码编辑加实时预览。XLSX 当前仅覆盖单元格文字和数字，覆盖会清掉该格公式与样式，不重算依赖公式（`packages/office/src/editors/XlsxEditor.tsx`、`xlsx-edit.ts`）。
- PPTX 支持改段落文字、整段字形，以及幻灯片新增、复制、删除和排序；不支持元素拖动和段落格式（`packages/office/src/editors/PptxEditor.tsx`、`pptx.ts`）。
- PDF 仅支持读取文字层和页面结构编辑，包括旋转、增删、复制、调序、导入、裁剪与纸型；内容流文字编辑未接入，并有项目决策 D-057（`packages/office/src/editors/PdfEditor.tsx`、`.trellis/spec/project/decisions.md`）。
- 用户决定扩建编辑引擎，Agent 和手动编辑都向固定 GenOffice 版本对齐；现有 Mimir 手动能力不是本任务的上限。固定上游版本 `genspark-ai/genoffice@480548fd55f1be3593ee0d8e316a734751d58309` 中，五格式均有独立 AI 工具；上游工具目录分别为 XLSX 13、PPTX 17、Markdown 8、HTML 6、PDF 45 个顶层工具。完整语义及运行依赖需逐项核对，见 `research/genoffice-five-format-inventory.md`。
- 用户明确要求浏览器版与桌面版的高级编辑能力一致。Mimir 两端共用渲染代码，桌面本地模式也运行同一服务宿主；上游 Electron/Rust/PDFium 依赖须适配两端共同可达的运行路径，不能只在桌面主进程接入，见 `research/runtime-boundary.md`。

## Requirements

- **R1 五格式入口**：只在用户有权打开的当前文档页提供该格式可执行的 Agent 编辑工具；原有问答、引用、停止和会话行为保留。库级对话不获得文件写入权限。
- **R2 当前画布**：Agent 读取尚未保存的当前编辑状态。异步工具须验证文档身份和状态，不能把旧结果写入其他文档或覆盖用户随后做的修改。
- **R3 上游能力对齐**：逐格式核对固定版本 GenOffice 的 Agent 工具、子操作和手动编辑能力，形成可追踪的能力矩阵；把目前缺少的可执行编辑能力接入 Mimir。Agent 与手动入口共享编辑原语、当前画布状态和保存结果。模型可见工具必须真实执行，失败必须如实返回，不以现有 Mimir 手动能力为上限。
- **R4 用户控制**：Agent 修改在画布可见，进入现有未保存状态；沿用手动保存和离开保护。回退或撤销不得丢失该轮之后的手动修改。
- **R5 复用接缝**：五格式继续使用当前文档的对话入口、TanStack AI 工具循环与受控客户端工具续轮；按格式限制能力，不向不支持的格式暴露工具。
- **R6 上游语义与宿主适配**：以固定 GenOffice commit 的工具合同和可观察行为为基线；涉及 Electron IPC、Rust、WASM、第三方服务或本地路径的能力，需在 Mimir 支持的运行环境中有真实且安全的适配。不能用空结果或仅有 UI 的占位项冒充对齐。
- **R7 手动编辑对齐**：逐格式盘点 GenOffice 手动编辑器的可执行命令与状态；在 Mimir 提供同等语义的用户入口。共享编辑原语不要求完全照搬上游 Ribbon 像素布局，但命令不能只有 Agent 可用、手动操作无入口。
- **R8 两端一致**：同一文档及同一服务配置下，浏览器版、桌面本地模式与桌面连接自部署服务模式的工具目录、手动编辑能力、文件结果和失败说明一致；平台底层实现可不同，但不得将高级编辑限定为 Electron IPC。
- **R9 工具栏交互**：DOCX 及本任务五种格式的手动工具栏采用 Microsoft Office 式的清晰分类和命令层级；GenOffice 固定版本作为各格式可执行命令、参数及状态的语义参考。常用命令直接出现在所属工具组，不因编辑栏变窄被移入“更多”总菜单；窄栏允许在命令区滚动或切换分类，仍能通过键盘发现并执行全部已支持命令。保存、撤销、重做放在分类标签左侧固定区域；没有完整手动历史的格式明确禁用撤销/重做，不用 Agent 单轮回退冒充。产品默认界面以选中、聚焦、当前值、禁用态和上下文操作表达用法，不常驻教程式说明段落；必要的失败及原件保真风险在相关操作时清楚出现。

## Acceptance criteria

- [ ] **A1（R1、R2）**：五种现有文件均可在对应文档页发起针对未保存画布的读取与修改；主视图和错误文档上下文不能执行写工具。
- [ ] **A2（R3、R4）**：每种格式的代表性修改直接在画布可见，触发 dirty 和离开保护，手动保存后重新打开仍准确；失败不清除 dirty 或宣称已成功。
- [ ] **A3（R2、R4）**：停止、切文档、异步期间手动编辑、过期版本及整轮回退不会覆盖后续人工修改。
- [ ] **A4（R1、R5）**：工具调用只执行一次，结果和错误进入模型续轮，原有单篇问答、引用、历史、停止与库级问答回归通过。
- [ ] **A5（R3）**：五种格式各有明确、可执行且可测试的工具范围；不支持的动作给出可见解释。
- [ ] **A6（R3、R6、R7）**：逐项能力矩阵记录上游工具、子操作、手动命令、Mimir 执行路径及验证结果。每项在上游可执行的目标能力均有实际执行证据；代表性测试用于回归，不能替代逐项核对。缺失或环境限制的能力不得被标为已完成。
- [ ] **A7（R3、R6）**：新增手动编辑命令与同类 Agent 命令在同一画布和原件上得到一致结果；代表性的公式/样式/图表、幻灯片对象、Markdown 结构、HTML 元素、PDF 内容与批注操作保存重开后仍准确。
- [ ] **A8（R7）**：五种格式的上游手动编辑命令逐项有 Mimir 入口、状态、禁用原因及操作验证；Agent 改动可继续手动调整，手动改动可被 Agent 读取，不出现两份编辑状态。
- [ ] **A9（R8）**：同一组代表性 XLSX 公式/格式、PPTX 对象、Markdown 块、HTML 元素、PDF 文字/批注/页面操作，在浏览器版和桌面本地模式都可执行、保存并重开；桌面连接自部署服务时使用同一服务能力合同，环境差异只改变可读的配置/运行错误，不改变已宣称的功能集合。
- [ ] **A10（R7、R9）**：六种文档编辑器在正常与窄栏、问 AI 打开及桌面窗口下显示 Office 式分类和可见命令；XLSX 不再只剩查找与“更多”，其余格式不把整组常用命令折入总“更多”。保存、撤销、重做固定在分类标签左侧，标签和命令可独立滚动；保存沿用各格式原件写回及状态，未接通的历史按钮给出禁用原因。选择对象后相关控件和当前值出现，未选择时禁用原因可在控件处获取；空白状态区不显示“点一个格子…”等操作教程。逐项检查 GenOffice 手动命令映射，不可执行项不伪装成可用按钮。

## Child task map and order

1. `10-13-format-agent-core`：将 DOCX 专属的安全接缝抽成按格式隔离的文档 Agent 通道；此项先行，不能破坏 DOCX。
2. `10-13-markdown-agent-manual`、`10-13-html-agent-manual`：文本格式的上游操作与手动入口；依赖共用通道。
3. `10-13-pptx-agent-manual`、`10-13-xlsx-agent-manual`：Office 原件模型和保存能力；依赖共用通道，可在文本格式之后分别验收。
4. `10-13-pdf-agent-manual`：PDF 内容、批注、图片与页面操作；依赖共用通道，并先解决主进程/PDFium 在目标运行环境的适配。
5. 本父任务负责全部子任务的能力矩阵、跨格式回归和最终集成验收；不替代子任务的逐格式验收。

## Out of scope

- AI 自动保存或绕过现有文件保存流程。
- 在本任务中重做 DOCX 工具集或扩展主视图的全库文件写入权限。
