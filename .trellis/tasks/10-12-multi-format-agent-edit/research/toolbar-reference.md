# Research: Office-style multi-format toolbars and GenOffice commands

- Query: All document toolbars should use Microsoft Office's command layout, expose routine commands without a catch-all “More”, use GenOffice for executable commands, and communicate intent through interaction rather than permanent explanatory prose.
- Scope: mixed (pinned GenOffice source, Mimir source, existing public-reference record)
- Date: 2026-10-13 (Asia/Shanghai)

## Findings

### Reference roles and version

- **Layout and interaction:** Microsoft Office's familiar ribbon pattern is a visible tab strip with named groups below it: Home for common editing; Insert; format-specific tabs (spreadsheet Data/Formulas, slides Design/Transitions/Animations, document Layout/Review, PDF Annotate/Edit/Page); View. Selection can add contextual tabs. Quick access Save/Undo/Redo, current state, and document canvas remain separate. This is a design direction, not a claim that a particular current Office web build was live inspected today.
- **Executable semantics:** fixed `genspark-ai/genoffice@480548fd55f1be3593ee0d8e316a734751d58309`, the commit recorded in `packages/office/vendor/UPSTREAM.json:18-21`. GenOffice's commands are useful as an operation inventory, not a promise that every visible upstream button works in Mimir. Its Slides ribbon explicitly uses a tab strip and grouped buttons (`apps/slides/src/renderer/components/Ribbon.tsx:1-5`, `:138-175`, `:1878-1880`); PDF has Home/Annotate/Edit/Page/View tabs (`apps/pdf/src/renderer/App.tsx:280-288`).
- **WeKnora cross-check:** the prior public-site and public-source check in `research/reference-check.md:8-15` records site HTTP 200 on 2026-10-12 and fixed public source `Tencent/WeKnora@v0.8.2` (release 2026-09-24), specifically `internal/agent/tools/definitions.go` with knowledge search/read/list and Wiki write/replace tool definitions: <https://github.com/Tencent/WeKnora/blob/v0.8.2/internal/agent/tools/definitions.go>. It informs Agent tool registration and permissions only. It has no Office document ribbon or XLSX/PPTX/PDF file-save command contract, so should not determine toolbar layout. A fresh GitHub raw request on 2026-10-13 failed DNS in this sandbox; the checked record is the versioned evidence available here.

### Why the screenshot collapses

- `packages/office/src/editors/CompactToolbar.tsx:99-142` measures editor-column width, hides each section when `width < minWidth`, then puts all hidden groups into a 320px “更多” panel. The screenshot's narrow column therefore exposes search/previous/next while routine edit commands disappear. XLSX sets formula navigation to 850px, cell commands to 940px, and row/column commands to 1010px (`XlsxEditor.tsx:493-805`). Markdown and HTML use the same component (`MarkdownEditor.tsx:1030-1408`, `HtmlEditor.tsx:988-1145`). DOCX has a separate unconditional `DocxMoreMenu` (`DocxEditor.tsx:1393-1446`, `:1954-2022`); PPTX and PDF use large format menus (`PptxEditor.tsx:1200-1320`, `PdfEditor.tsx:1112-1360`).
- A multirow/tabbed ribbon or a horizontally scrollable named group band can keep core commands discoverable in this column. It should keep frequently used commands in their tab/group at narrow width, not replace the toolbar with a single nested “更多”. Secondary variants may still live in a clearly named dropdown (for example Paste Special, chart type, line spacing, page size). The GenOffice Markdown ribbon keeps inline format, lists, insert table/image/rule and properties/outline visible as groups (`apps/markdown/src/renderer/components/Ribbon.tsx:260-326`, `:380-526`); its HTML ribbon keeps insert, view and presentation actions as groups (`apps/html/src/renderer/components/Ribbon.tsx:197-266`, `:360-579`).

### Interaction and copy

- Use the active tab, selection, enabled/disabled state, preview, and immediate canvas change to explain what an action does. Mimir's shared `EditorShell` has separate toolbar, conditional subbar, canvas, conditional footer, and status slots (`packages/office/src/shell/EditorShell.tsx:120-184`); this supports contextual controls without a permanent instructional paragraph.
- A status line should carry short, changing facts such as page/sheet number, selected object and save state. The PDF editor already renders footer only for a dismissible transient notice (`PdfEditor.tsx:1416-1445`; `.trellis/spec/office/frontend/shell/conventions.md:13-20`). Place detailed disabled reasons in tooltips/menu items, precise risks in a dialog at action time, and actionable errors as transient notices. Avoid always-visible document-like explanations of engine limits or workflow on the canvas/footer. Mimir's HTML status currently says “点一个元素可以定位到它的源码” (`HtmlEditor.tsx:1324-1331`); the selection highlight and contextual Element/Style controls can convey this intent more directly.
- Manual and Agent commands should converge on the same edit primitive and save/undo state (task `prd.md:21-25`). A visible button is not proof of parity: verify real execution, canvas state, save, reopen and, where relevant, source bytes. Source-side dependency caveats (XLSX Univer/Rust, PPTX engine, PDF Electron/PDFium/HarfBuzz) are documented in `research/genoffice-five-format-inventory.md:7-11` and `packages/office/vendor/UPSTREAM.json`.
