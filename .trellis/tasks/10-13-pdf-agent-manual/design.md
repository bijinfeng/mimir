# 设计：PDF Agent 与手动编辑

固定上游 45 个顶层工具和 26 种内部操作，其中 8 种可经 `apply_ops` 暴露给模型。现有 pdf.js 阅读/文字层与 pdf-lib 页面结构为基础；扩展可见编辑叠层与宿主编辑会话，承载上游文字、批注、图片、表单、页面及文档操作。手动 UI 与 Agent 工具调用同一 PDF 操作模型。文字编辑、字体查找/子集化、PDFium、OCR 和图片烘焙等 Node/原生能力由 Mimir 宿主服务执行，浏览器、桌面本地与远端模式通过同一鉴权 HTTP 合同调用。

页面/对象 ID 与原件版本必须在执行时验证，异步操作只能落到原文档。浏览器画布在服务端确认后展示对应结果；保存前叠层是待提交状态，保存后用实际字节重新渲染与文字索引验证。签名、表单、批注、复杂 Catalog、扫描件和不可提取文字必须区分能力与错误；无法保全的原件拒绝写回。`create_document` 走知识库新文件路径，不能凭本机默认目录或 Electron 文件对话框产生假成功。旧项目决策 D-057/D-063 的只读文字边界须在真实实现完成时修订。
