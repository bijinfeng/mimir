# GenOffice 编辑能力完备性对标

## Goal

回答 Mimir 六种文档编辑器的**工具栏命令**是否已对齐项目固定的 GenOffice 版本，重点审查手动命令的可发现性、真实执行、状态和保存；Agent 工具作为同类能力的交叉核对，并给出现有任务可承接的缺口优先级。

## Background and confirmed facts

- 项目固定 `genspark-ai/genoffice@480548fd55f1be3593ee0d8e316a734751d58309`，见 `packages/office/vendor/UPSTREAM.json`；此版本是本次文件编辑的主参考。
- `10-11-chat-edit-office` 已跟踪 DOCX；`10-12-multi-format-agent-edit` 及五个 `10-13-*-agent-manual` 子任务正跟踪其余格式。这次仅产出横向判断，不重复建立实施任务。
- 现有专项矩阵混合了目录接入、单项执行、真实原件读回、浏览器/桌面端到端验收等状态；横向报告必须分别标明，不能把任一状态等同于全部完成。
- 项目要求每次调研核查 WeKnora 公开站点和源码，并说明适用性。知识库与 Agent 权限参考 WeKnora；Office 网页版、Google Docs、GenOffice 是文件编辑参考，Obsidian 是页面视觉参考。

## Requirements

- **R1 基线**：以项目固定 GenOffice commit 为可执行命令与操作语义基线；记录核对时间、上游来源和 Mimir 代码或既有任务矩阵证据。
- **R2 六格式工具栏**：分别评估 DOCX、Markdown、HTML、XLSX、PPTX、PDF 的可见分类、命令及上下文菜单；逐类判断是否真执行、是否反映当前对象状态、禁用原因是否准确、是否能从 Agent 继续手动编辑、是否保存读回及两端验证。
- **R3 完备性分级**：明确区分已注册、可调用、代表性测试通过、逐项原件读回和浏览器/桌面实际验收；对未实现或条件性能力不作完成宣称。
- **R4 可行动结论**：给出工具栏整体结论、按格式缺口、优先级、建议归属到现有任务，不把这次分析扩大为产品代码修改。
- **R5 参考适用性**：核对 WeKnora 当前公开版本、站点与源码证据；解释其对 Agent 权限有何用处，以及为何不作为 Office 工具栏/文件写入语义基线。

## Acceptance criteria

- [x] **A1（R1、R2）**：报告以工具栏为主表覆盖六格式手动命令，引用固定上游版本、当前 Mimir 代码及至少一项当前界面观察。
- [x] **A2（R3）**：报告逐格式区分命令存在、真实可执行、画布可见、保存读回、两端实测；未把上游或 Agent 工具数直接作为工具栏完成率。
- [x] **A3（R4）**：报告给出明确“工具栏是否完备”判断、最高优先级缺口及现有任务归属。
- [x] **A4（R5）**：记录 WeKnora 公开站点、版本、源码及适用边界。

## Out of scope

- 本次不修改编辑器、Agent 宿主、工具栏或服务端实现。
- 不凭源码调查宣称已完成真实模型调用、浏览器与桌面端到端验收。

## Open questions

- 无阻塞问题；本次仅作现状评估。后续是否改变各格式产品优先级由既有实施任务决定。
