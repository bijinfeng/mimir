# 六格式编辑器工具栏对标 GenOffice

核对日期：2026-10-16（Asia/Shanghai）。主参考是项目固定的 [`genspark-ai/genoffice@480548fd55f1be3593ee0d8e316a734751d58309`](https://github.com/genspark-ai/genoffice/commit/480548fd55f1be3593ee0d8e316a734751d58309)；本地 `packages/office/vendor/UPSTREAM.json` 也固定于此版本。手动命令入口见既有 `10-12-multi-format-agent-edit/research/genoffice-manual-entrypoints.md`，DOCX 入口见 `10-11-chat-edit-office/research/toolbar-competitors.md`。Office 网页版和 Google Docs 用于分类及可发现性交叉参考；没有用 WeKnora 的 Markdown 工具栏替代 Office 基线。

## 判断标准与结论

“工具栏完备”至少要同时满足：上游目标命令有手动入口；按钮实际执行；当前值、选中、禁用及失败可理解；结果在当前画布可见；保存并重开仍成立；窄编辑列与问 AI 侧栏下可找到；浏览器和桌面真实交互经过验证。**现状未满足。** 六格式已经有 Office 式分类和固定的保存/撤销/重做区，`CompactToolbar.tsx` 通过分类标签和横向滚动避免按宽度把命令静默丢掉；但工具本身的覆盖与画布反馈差异很大。

代码与测试提供“存在/专项执行/部分保存”的证据，不等于真实浏览器或桌面端到端验收。当前运行的本地网页仅有一篇 Markdown 笔记可供可视检查：在 1280px 视口中看到“开始 / 插入 / 笔记 / 审阅”分类、保存/撤销/重做固定在左侧；切换分类后命令区随之变化；打开“问 AI”时分类仍可见。该会话没有 DOCX、XLSX、PPTX、HTML、PDF 实例，因此这些格式的可见性只按代码与既有组件测试评估，未声称完成实机视觉审查。

## 跨格式工具栏优点与风险

- **已做对的结构**：`CompactToolbar.tsx:1–166` 保留分类标签、键盘左右键切换、固定快捷操作、命令区横向滚动与边缘渐变。`CompactToolbar.test.tsx` 验证命令不因 `minWidth` 被隐藏，且切换分类后滚动归零；本地 Markdown 页面打开问 AI 后分类仍可见。
- **已做对的状态诚实性**：XLSX、PPTX、PDF 在没有完整历史时禁用撤销/重做，并给出原因；多项控件在无选中对象或不能写入时明确禁用。DOCX/HTML 等有组件测试验证禁用原因与按钮执行。
- **P0 风险：工具栏承诺与画布反馈不一致**。XLSX 加粗、列宽可以保存，却无法在当前网格看见；公式缓存不重算。用户会把按钮理解为“没有生效”或把旧公式结果理解为新结果。应先补画布呈现/计算与结果确认，再扩大这类命令。
- **P0 风险：Agent 有操作，手动工具栏没有对应命令**。DOCX 的页眉页脚/批注/图表等、PPTX 的多数对象级操作、XLSX 的部分宿主 DSL 都体现此差距。现有父任务 R7 要求两入口共享能力，不能以 Agent 工具可调用代替手动可达。
- **P1 风险：按钮级证据不均衡**。HTML 13 种操作只有部分按钮到原件保存读回；PPTX 61 种宿主可调用并非 61 种逐项验证；PDF 内容与批注没有真实 UI 路径。实际验收应逐命令记录“选择→执行→画布→保存→重开”。
- **P1 风险：多格式实机与窄栏未验证**。本次只看到了现有 Markdown 笔记正常宽度和问 AI 后的工具栏。其余格式、窄窗口、长菜单、键盘滚动、焦点与读屏顺序尚需浏览器和桌面分别检查；组件测试的 320px DOM 不证明视觉无裁切。
