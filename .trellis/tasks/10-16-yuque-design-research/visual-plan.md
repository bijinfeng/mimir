# Mimir 语雀风格页面规划

更新：2026-10-17。用户已选择整体迁移主题、基础组件、左导航和知识库 / 文档布局。本文件是可审阅的页面规划，不是最终视觉稿，也不代表实施批准。

## 设计目标

让用户首先看到知识内容、目录关系与正在进行的工作。页面使用白与中性灰，绿色集中在新建、添加、发送等关键动作；导航当前项使用浅灰背景与字重。外观更接近语雀，继续承载 Mimir 的单用户知识库、资料收集、搜索、Agent 与多格式编辑能力。

依据：`research/yuque-design-study.md` 的本次公开知识库 / 阅读页截图与测量。个人工作台与实际编辑器无登录态证据，因此下面的信息组织属于 Mimir 适配方案，不宣称是语雀个人工作台的精确复制。

## 1. 工作区与左侧导航

展开时把现有常驻功能栏与任务侧栏整合为**一条约 256px 的侧栏**。上下两部分承担全局入口与当前工作内容，避免同一个「新建对话 / 搜索」在两列重复出现。

| 区域 | 展示内容 | 行为约束 |
| --- | --- | --- |
| 顶部品牌行 | mimir 标识、折叠按钮 | 保留品牌；Desktop 的原生窗口控件与拖动区继续由平台壳负责 |
| 常用入口 | 搜索、知识库、新建对话、收集 | 复用现有路由和动作；不新增「全部文档」或独立仪表盘 |
| 知识库区 | 库名、目录树、当前文档 | 复用现有 FolderSection；目录可展开，当前项灰底加粗；长标题省略并可查看完整名称 |
| 对话区 | 最近对话与现有失败重试 | 历史与引用跳转保持现有数据协议；空态不过度占空间 |
| 最近笔记 | 现有最近笔记分组 | 保留当前记录方式与展开能力 |
| 底部账号区 | 账号菜单、设置 | 保留账户 / 统计 / 外观等现有入口；本地模式继续遵循当前账号语义 |

256px 是 Mimir 布局建议，来源是语雀本轮约 259px 侧栏的比例，不是宣称的官方固定值。导航行按 36px 外层节奏规划，UI 文字 14px，选中底候选 `#eff0f0`，选中文字保持墨黑。

折叠时保留约 52px 的紧凑入口，保障现有折叠偏好可迁移；窄屏侧栏用可关闭的覆盖方式打开。选择入口后返回内容，键盘焦点回到触发按钮；未保存保护继续生效。窄屏不强行同时展示目录、正文和大纲。

## 2. 知识库页面

主内容按「知识库信息 → 工具行 → 文件夹与文档」排布。

- **知识库信息**：名称候选 28px，描述保持清楚但次要；数量、库 ID 作为辅助信息。库 ID 保留复制能力，视觉退后。
- **工具行**：保留一枚绿色主操作「添加文档」，新建文件 / 文件夹为中性次操作，右侧保留列表 / 卡片切换。
- **列表**：文件夹优先，文档名称为视觉中心；类型、处理状态、更新时间形成稳定列关系。摘要和路径降为辅助信息；长名称优先获得空间。
- **卡片**：减少内层装饰与边框重量，沿用相同信息优先级，保留原视图能力。
- **异常与空态**：加载、无文档、处理失败、上传中各有现有真实动作；颜色与图标共同表达，不靠彩色小徽标填满页面。

保留用户已有列表 / 卡片偏好；本轮不主动更换默认视图。现有「全部文档」已退役，`scope=all` 进入首个知识库的行为继续有效。拖放上传和新增内容的当前目录归属不改变。

## 3. 文档页面

形成「左目录、中央正文、右大纲 / 问 AI」的内容工作区。

- 文档头部保留返回库、标题、问 AI、更多操作；排版减少边界和重复信息，建立清楚的标题层级。
- 中央正文沿用 760px 宽度起点，阅读字号独立为约 15px，行高约 1.8–2.0；正文左右留白随可用空间变化。
- 标题在页头承担文档身份；正文中的 H1 / H2 / H3 按内容语义保持层级，不为视觉效果再复制一遍标题。
- 右侧大纲用灰色文字、缩进与当前标识表达层级；问 AI 打开时优先给对话空间，按现有面板机制处理大纲与聊天的可用宽度。
- 当前笔记直接编辑的行为保留；本次不新增阅读 / 编辑模式切换，不为模仿只读截图而隐藏真实编辑入口。
- 文件类内容维持各格式的画布与工具能力；Office 工具区、缩略图、菜单跟随新主题，用户原件内容颜色保持原义。

问 AI 的全局与文档范围、引用定位、关闭返回、保存反馈和未保存保护继续保持。

## 4. 设置、Chat 与其他基础界面

设置作为第三张代表稿，用于验证表单、分组、开关、错误提示和次要操作是否能形成同一套视觉语言。现有设置分区及平台可见性不变。

Chat 保留主对话与文档侧栏两个场景，统一白灰底、中性文字和绿色发送 / 停止按钮；来源引用、失败重试、运行状态保持可辨。收集、搜索、创建知识库等弹窗沿用同一字体、6px 控件圆角和清楚焦点状态。

## 5. 色彩与排版起点

| 角色 | 方案起点 | 依据 |
| --- | --- | --- |
| 内容表面 | `#ffffff` | 语雀本次实测 |
| 辅助背景 | `#f7f8f8` | Mimir 建议，代替冷灰蓝层次 |
| 导航选中 | `#eff0f0` + 墨黑 + 600–700 字重 | 语雀本次采样 |
| 品牌绿 | `#00b96b` | 语雀主按钮采样；不直接套普通白字按钮 |
| 白字主按钮 | `#00834d` 候选 | Mimir 校准建议，白字对比约 4.82:1 |
| 链接 / 强调文字 | `#007a45` 候选 | Mimir 校准建议 |
| 主 / 次 / 元信息文字 | `#262626` / `#595959` / `#6b6b6b` | 第一项采样，后两项为建议；元信息从初稿 `#737373` 加深以覆盖选中灰底对比度 |
| 基础控件圆角 | 6px | 语雀采样 |
| UI / 阅读正文 | 14px / 15px 起步 | 独立角色，避免一起放大工具条 |

深色采用中性灰阶与独立绿色校准，是 Mimir 的适配设计。缺少语雀深色实测，不宣称深色像素级复刻。键盘焦点、禁用、hover、pressed 和语义状态作为完整状态表一起定义。

## 6. 代表稿与验证顺序

1. **知识库稿**：验证统一导航、绿色主操作、文档信息层级和列表 / 卡片外观。
2. **文档稿**：验证正文留白、标题、目录、大纲与编辑工具区的关系。
3. **设置稿**：验证通用表单、分组和按钮体系。
4. 同一方案补深色和窄屏关键状态，随后再形成最终实施摘要。

三张代表稿采用同一套主题，是一个整体改版交付；本任务按阶段推进，不拆成可各自放行的独立皮肤任务。获得视觉和最终实施方案确认后，才开始产品代码改动。

2026-10-17 三张浅色宽屏代表稿已获用户认可；补齐三张深色与四张390px窄屏稿。生成来源、完整索引与评审边界见 `drafts/README.md`，浅深角色 / 状态 / 窄屏契约见 `research/appearance-responsive-contract.md`，最终实施摘要见 `final-review.md`。这些图片为静态规划产物，当前继续保持 planning，等待对最终摘要的后续明确批准。

## 7. 验收方向

- 用户能从侧栏找到全部现有常用入口，展开态不出现两列重复全局导航。
- 知识库、文档、设置在色彩、字体、圆角和状态上明显属于同一套系统。
- 目录当前项与普通项可识别；文件处理状态、错误、AI 引用可理解。
- 原有搜索、收集、文件上传、编辑保存、对话与平台功能继续可达。
- 浅深外观与窄屏无裁切、横向溢出、焦点丢失或无法关闭的覆盖层。
- 设计规范与实施代码同步，保持现有质量门，不以删掉行为 / 可读性检查实现换色。
