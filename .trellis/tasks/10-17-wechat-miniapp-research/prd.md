# 微信小程序端产品调研与范围规划

## 目标

为自用的固定域名 Mimir 服务提供微信小程序端，完成“找资料、带引用提问、核对原文、修改笔记和收集链接”的移动使用闭环。当前阶段交付调研、产品 / 技术规划及高保真交互原型，不启动产品实现。

## 背景与已确认边界

- 2026-10-17 用户同意创建任务并进入调研规划；当前授权不包含产品实现。
- 用户最初提出知识库检索问答、内容预览、有限编辑，随后通过本会话逐项收敛，具体行为见下文要求。
- Mimir 当前定位为单用户自托管的个人知识库（`.trellis/spec/project/product.md:3`）。2026-10-18 用户确认目前主要服务自己，并会部署具有稳定域名的服务端；首版按自用、固定实例直连收敛。
- 稳定域名不等于上线条件已验证；HTTPS、合法域名配置、实际 AppID 主体和发布路径仍需技术验证。首版不引入任意实例接入网关或统一多用户托管。
- 工作区已有大量未提交改动，本任务只写自己的规划及研究资料。
- 2026-10-18 的范围决定依次为：编辑 B 档、接受微信原件查看器、收集 B 档、AI A 档、加入当前文档问答。要求 R2–R6 为这些决定的行为定义。

## 首版要求

### R1：连接与账号

- 连接一个固定域名的服务端，使用现有 Mimir 所有者身份；登录失效可重新认证，退出后停止访问该账号的缓存内容。
- 账号、知识库、笔记、资料和历史与电脑端使用同一份数据。模型配置沿用服务端，手机无需填写模型密钥。
- 登录交互提案为现有邮箱 / 用户名和密码；不强制绑定微信身份，具体技术方案见 design.md，由最终方案审阅一并确认。

### R2：找资料与问答

- 浏览已有知识库、子目录、文档和标签；按全库或指定知识库搜索。目录是归属、标签是横向组织，沿用现行数据模型。
- 明确区分“搜索资料”和“向 AI 提问”；支持带引用回答、追问、会话历史，以及主动将回答存为笔记并选择目标库。
- 阅读文档时可以“问这篇”：只依据该文档已提取且可检索的正文，长文也需检索相关段落，不能只读取开头 1200 字。无相关内容或无文字层时如实说明。
- 范围不可静默扩大。会话保持创建时的范围；切换范围新开会话，避免旧会话上下文混入别的库 / 文档。
- AI 首版只检索回答；不提供选区改写、精简、扩写或 Agent 自动修改文档。

### R3：阅读与引用核对

- Markdown 笔记、网页 / 公众号 / GitHub 已入库正文在小程序内阅读，代码、表格和图片尽可能提供明确可读的表示；暂不支持的高级块保留原文并提示，不把无法渲染等同为空文档。
- 引用先显示实际命中片段和上下文，允许进入文档。正文变化导致定位失效时，保留历史片段并提示来源已变化。
- PDF、Word、Excel、PPT 通过鉴权下载后使用微信文档查看器打开原件。接受离开当前阅读页、版式由查看器决定和不能保证跳到引用对应页的边界。
- 没有提取正文、扫描件或原件预览失败时，分别说明状态，保留已有信息及可行的重试 / 打开方式。

### R4：手动有限编辑

- 修改单篇文档的标题、标签，移动到已有目录；新建、追加笔记并修改已有 Markdown 笔记正文。
- 正文编辑交互提案为 Markdown 源文输入与预览切换、显式保存；该方案在最终审阅中确认，不引入 HTML 往返转换。
- 保留草稿并显示保存状态；手机旧草稿不能静默覆盖电脑已经保存的新版本，冲突时保留草稿，允许重新读取或另存笔记。
- 网页 / 公众号 / GitHub 资料和 Office 提取正文不提供正文覆写；文件原件与解析正文不因元信息修改而变化。
- 保存后另一端能读到相同内容，后续检索使用更新后的索引。

### R5：链接收集

- 用户粘贴网页或公众号链接，选择已有目标知识库 / 目录后入库；复用现有抓取能力，不扩大为自动读取微信内容。
- 明确显示处理中、成功、部分成功或失败；抓取失败保留链接和目标位置，给出原因与手动重试方式。不承诺所有公众号文章或防盗链图片可获取。
- 网络不确定时先查询操作结果，不能自动重复创建资料。

### R6：移动可靠性与数据保护

- 支持流式回答；中文跨块、返回前台、弱网、过期登录、空库、无命中和模型未配置均有可理解的状态。
- 手机到服务端可达而模型不可用时可只检索；手机离线不承诺服务端检索。草稿在网络失败时保留。
- 前后台切换后可重新读取会话和操作结果，完成与中断要区分；不承诺锁屏后仍持续生成。
- 重复点击 / 网络重试不能意外重复提问、新建笔记、追加、保存回答或导入链接。

## 首版范围外

- 微信会话文件上传、拍照 / OCR、离线全文检索与完整离线库同步。
- Office / PDF 原件编辑、完整富文本往返、AI 辅助改写或自主 Agent 写入。
- 多用户 / 租户、公开分享、任意自托管实例接入网关、模型与索引维护设置。
- 批量删除 / 移动、删除知识库、复杂目录管理；单篇修改和移入已有目录以外的管理操作留在电脑端。

## 实施前的交互原型评审

2026-10-18 用户要求先看高保真原型和交互，尚未批准产品实现。新增任务内独立的 [交互原型](prototype/README.md)，沿用 Mimir 现行品牌及视觉规范，演示问答 / 搜索、知识库浏览、引用阅读、当前文档问答、Markdown 编辑、保存冲突、链接收集、原件查看边界与中断恢复。

原型使用明确标记的示例资料及本地模拟结果，不请求生产接口，不代表真实鉴权、检索、并发保护、抓取或微信原生文件能力已实现。验收为主流程可点击走通、重要异常可查看、iPhone / Android 预览布局和键盘交互可审阅；其结果不能代替 AC1–AC10 的产品验收。用户看过原型后再收敛交互，并重新确认完整方案。

用户对第一版反馈：“交互感觉和我们现在的紧凑，简单的设计不太一样”。原型修订必须遵循现行设计规范的全局紧凑密度：移除宣传式大标题、重复介绍、装饰图标与重复范围操作，把列表、工具栏和相关动作靠近；正文维持独立阅读行距，触控区域不随视觉压缩。评审场景入口收为外部辅助选择器，不能抢占产品体验。该反馈调整呈现与操作层级，不删已确认功能，也不构成正式产品实施批准。

### 原型 v3 的细化确认

2026-10-18 用户批准参考研究提出的下一稿方向：继续会话置于示例前；编号引用直接核对对应片段，全部来源保留列表；阅读页突出“问这篇”，编辑为轻操作，整理进入次要菜单；追加只输入新内容并显示目标笔记。维持独立 Markdown 编辑、草稿和冲突处理，不扩大首版功能。具体实现与浏览器验证仅作为交互评审证据。

## 产品验收标准

以下为实施后需要验证的条件，本轮没有运行这些产品测试。

| 编号 | 可观察结果 | 对应要求 |
|---|---|---|
| AC1 | 非调试模式连接固定 HTTPS 域名；现有账号可登录；未登录、过期或已撤销凭证不能读取私有正文、历史和文件 | R1、R6 |
| AC2 | 选定知识库的搜索、回答、引用均不混入其他库；切换范围另开会话，历史仍能恢复原范围 | R2 |
| AC3 | 长文尾部放置唯一事实，“问这篇”可以引用该段；在其他文档放置冲突答案也不串入，无命中不扩大范围 | R2 |
| AC4 | 点击来源可核对真实片段；正文改变 / 删除时有提示；PDF / Office 打开原件后可返回，不宣称原件页定位 | R3 |
| AC5 | 编辑含中文、emoji、代码、表格、双链及高级块的笔记，未改部分保持原文；无操作保存不转换或丢失内容 | R4 |
| AC6 | 电脑保存新版本后手机再保存旧草稿，收到冲突提示且草稿保留；重新读取 / 另存可完成，另一端可核对结果 | R4 |
| AC7 | 标题 / 标签 / 目录更新不改正文和原件；非笔记正文写入在服务端被拒绝；答案存笔记确实归入选定库 | R2、R4 |
| AC8 | 普通网页和可访问公众号链接入库可阅读、可搜索；抓取失败保留输入；重复同一操作不会产生额外资料 | R5 |
| AC9 | iOS / Android 真机的中文流式、键盘、长文滚动、图片和原件打开可用；切后台、断网后返回有正确状态，不自动重复生成或写入 | R3、R6 |
| AC10 | 模型未配置 / 超时可看到原文检索出路；无命中不伪造来源，手机无法连接服务时不伪装为本地搜索成功 | R2、R6 |
