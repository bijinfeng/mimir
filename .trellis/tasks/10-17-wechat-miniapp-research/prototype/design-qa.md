日期：2026-10-18。当前版本：v2 紧凑版。对象：浏览器高保真可点击原型。任务仍为 planning，正式小程序实施尚未批准；本记录不代替 PRD 产品验收或用户对设计的认可。

v2 以 Mimir 现行 `.trellis/spec/project/design.md` §0.3–0.4 与 `apps/web/DESIGN.md` 的紧凑、简单工作台为视觉权威；本地 [AGENTS.md](AGENTS.md) 已记录本次反馈。密度调整集中在重复信息、工具和列表，保留正文可读性及触控面积。本轮按 Impeccable documenter 的扫描原则核对既有系统，没有重新选择品牌方向，没有修改全局 `DESIGN.md`、`.impeccable/design.json` 或生产组件。

## v1 流程检查与 v2 保留的行为

以下是 v1 集中修复后的业务流程记录，保留用于说明原型可演示范围；旧截图不代表 v2 当前密度。v2 独立评审对草稿、回答、范围与返回做了指定源码回归核对，本轮没有宣称把以下每条全部重新做过浏览器验收。

| 业务流程 | 既有验证事实及当前保留边界 |
| --- | --- |
| 完整回答沉淀 | 回读含引言、标题、完整三步与全部当前引用来源；复制 / 保存共用 `answerMarkdown`。历史 `saved-answer.png` 只截到来源区域，全部来源由源码和当时的滚动检查确认。保存仍仅在本页内存。 |
| 新建草稿身份 | 新建 → 保留 → 恢复 → 保存创建独立 id，不覆盖原笔记；旧独立审阅实际确认新旧笔记同时存在。历史证据 `new-draft-restored.png`。 |
| 跨文档草稿保护 | 保留草稿后编辑别篇 / 再次新建，会回到原草稿并提示先保存或放弃；追加沿用现有草稿。历史 `draft-protection.png`；v2 指定源码回归确认守卫仍在。 |
| 草稿目标库 | `draftTarget` 与其他表单的 `target` 分离；回答存笔记、收集或整理的位置不会改写新建 / 另存草稿目标。 |
| 范围与返回 | 中断入口同步 `scope` / `answerScope`；搜索 / 范围变化清理旧回答，空范围有空态；单库返回知识库列表，阅读返回来源页，编辑离开有草稿保护。v2 指定源码回归确认。 |
| 冲突选项 | 继续编辑、保留并重读、另存新笔记均有路径；不把旧草稿静默写回原笔记。历史 `conflict.png` 与当前 `compact-conflict.png` 分别记录两版视觉。 |
| 链接收集 | 曾实际演示 URL 校验、位置选择、模拟等待、成功后查看、失败保留 URL 后重试；历史 `capture-error.png`、`capture-success.png`。没有调用抓取接口。 |
| Viewer / 中断 / 登录 | 原件页明确是示意并有返回；中断保留部分回答及主动重问；规定账号可演示登录 / 退出。历史 `viewer.png`、`interrupted.png`、`login.png`。账号为 `admin@example.com` / `12345678`（或 `admin`），没有真实认证 / 文件打开。 |

v1 的四项问题（草稿身份 / 覆盖、回答完整性、范围一致性、单库返回）曾修复并由旧 [reviewer.md](verification/reviewer.md) 有限复核关闭。用户随后否定其密度，因此不把旧 ship 视为设计已获认可。

## 原型限制与正式验收分界

- 所有应用数据与状态在刷新后还原；草稿、历史、保存、整理及收集结果只在组件内存中模拟，没有跨刷新或跨设备持久化。
- 草稿只有一个内存槽位。正式产品仍需按 instance / owner / documentId 隔离，验证多文档恢复、退出清理、版本基线与失败保护；原型“先处理原草稿”的阻挡不能替代这些合同。
- 回答、来源、流式展示、冲突及抓取均为预设或定时模拟。没有调用模型、Mimir 真实 API、微信登录、抓取或文件打开接口；不能据此推断检索质量、真实 SSE、幂等、并发版本或索引更新已通过。
- Markdown 预览只覆盖标题、段落、引用、列表与任务列表；表格、代码、双链及高级块、源文无改动往返仍按 PRD 验证。
- 微信开发工具、iOS / Android 真机、中文键盘、前后台 / 弱网恢复、下载鉴权、原件打开、AppID / 固定域名与发布审核均未验证。浏览器手机模板不能代替这些验收。
- 当前交付供用户评审交互。反馈收敛后仍需更新完整 PRD、技术设计与实施计划，并取得正式实施批准。
