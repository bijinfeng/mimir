# 紧凑版独立评审（2026-10-18）

## 1. 评审目标与依据

用户反馈：“交互感觉和我们现在的紧凑，简单的设计不太一样”。本轮据此重新验收，没有继承旧 `reviewer.md` 的 ship 结论。对象为 planning 阶段的交互 mock，评审结果只用于原型复核，不等于启动生产实现。

主依据是 `.trellis/spec/project/design.md` §0.1/0.3/0.4、§4/5、§8，以及 `apps/web/DESIGN.md` 的工作台密度、阅读节奏、平整表面规则。实际产品视觉对照为归档任务的 `final-mobile-note-light.png` 与 `polish-library-light-mobile.png`；旧原型对照为本目录 `home.png`、`library.png`。采用独立人工视觉判断，并仅对指定行为路径补读源码；未新增外部产品研究、未使用主浏览器、未修改生产代码。

## 2. 产品与旧原型的具体差异

旧 home 将书本装饰、两行口号、副文案放在提问入口之前，并在正文与输入区重复放置范围；旧 library 在原生页头下再放大标题和口号，库行带大图标底块、描述、数量与过大的垂直间距。桌面评审外壳又增加英雄标题和十条编号说明，形成与手机同等抢眼的第二层内容。

现有产品的方向是紧凑头部与工具区，名称、状态及动作靠近，正文独立保留舒适阅读空间。新版按这个方向删掉口号和装饰，提问页留下小标题、两条快捷问题、历史入口和一个可操作范围位置；库列表压为名称与数量两行，最近资料也在首屏内。评审工具已收为左上角小 Select 与外观按钮，十个场景仍在 Select 内可达。

新版没有用缩小正文换密度：连续阅读和源文编辑仍保留 15px 与宽松行距；主变化发生在工具、列表、标题重复和说明层级。阅读页的文档标题、段落、列表和引用成为主体，方向已回到 Mimir 的白灰工作面、中性当前位置和绿色主操作。

## 4. 指定源码回归核对

仅阅读 `src/Prototype.tsx` 与本轮相关 CSS，未扩大行为扫描。

- 单草稿保护：保留草稿后再编辑其他文档或新建时，先返回草稿所属文档并提示处理草稿，避免覆盖现有草稿。
- 新建身份：新笔记保存生成独立 id，内容写入 `draft`，归属取 `draftTarget`；保存后切到新 id 与目标库，不覆盖旧文档。
- 完整回答保存：复制与存为笔记共用 `answerMarkdown`，其中包含引言、全部步骤、引用编号和参考来源；保存不是只截取回答开头。
- 范围一致：`evidence` 由当前回答的范围及文档 id 过滤；空范围在 JSX 中先显示“这个范围内没有可用资料”，不会显示 fallback 计算的回答文本。更换范围会清空回答并开始新对话。没有将未渲染的 fallback 计算列作缺陷。
- 返回：`read()` 记录来源页，阅读返回该来源；原件查看返回阅读；编辑离开在 dirty 时进入保留/继续/放弃三选项。
- 紧凑与可触控：图标、范围和发送按钮保留 44px，建议行至少 48px，库/文档行至少 64px；源文使用 `field-sizing: content`，常态最小 240px、键盘下 160px，短文输入才按需回位，避免强制把长文滚回开头。

以上是 mock 路径的源码核对，不宣称真实服务或微信真机已验证。真实后端与微信环境不属于本轮缺陷项。
