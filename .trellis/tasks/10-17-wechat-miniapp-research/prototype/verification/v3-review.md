# 原型 v3 浏览器验证

日期：2026-10-18。主会话通过 Codex 内置浏览器操作 http://127.0.0.1:4391/；iPhone / Pixel 10 为模板模拟，未使用真实微信客户端或真实 API。

## 实际操作结果

- 首页：“继续上次会话”位于两个示例问题之前，工具行固定，三项主导航与输入区可见。证据 `v3-home.png`。
- 编号引用：全库回答点击 2，仅显示网页来源 2 的标题、身份与片段；点击“全部来源”出现来源 1 / 2，点击 1 仅显示笔记来源 1。证据 `v3-citation-1.png`、`v3-citation-2.png`、`v3-citations-all.png`。
- 原文与返回：来源 2 打开网页资料，阅读页标明正文只读且无编辑按钮；返回回答前后真实滚动容器 scrollTop 均为 44。来源 1 可进入笔记阅读。证据 `v3-web-readonly.png`、`v3-reading.png`。
- 轻量追加：文档操作 → 追加内容，显示目标笔记与知识库，无标题 / 标签 / 目录表单；输入补记后键盘上方可见取消与保存追加。取消 → 保留草稿并离开 → 阅读页恢复草稿，重新进入追加且内容保持；保存后正文包含原文及新增补记，标题与标签保留。证据 `v3-append-keyboard.png`。
- 编辑回归：追加保存后进入完整编辑，源文包含原文和补记；预览 / 源文切换可用，无修改时保存禁用，取消回阅读。
- 单篇范围：阅读“问这篇”后输入区显示该标题，生成回答的编号引用仅含此篇，不混入另一网页。证据 `v3-pixel-citation.png`。
- 品牌资源：回答 img 的 complete=true 且 naturalWidth>0；资源改为从同一 SVG 内联导入。

## 首轮发现与修复复核

深色正文最初被受保护模板的全局 p 颜色 / 字号覆盖。应用自有 CSS 已明确正文主题色与排版；Pixel 深色阅读的 computed style 实测为 `rgb(236,238,239)`、15px、27px，图中正文与目标操作完整。证据 `v3-dark-reading.png`。没有修改受保护运行时。

独立代码审阅与最终结论见 [v3-code-review.md](v3-code-review.md)。原型只用于交互评审，草稿 / 保存 / 冲突在内存中模拟，不证明真实索引、版本锁、发布或真机能力。

## 最终确认

- 引用快照：恢复“个人知识管理”的示例会话 → 引用 1 打开笔记 → 文档信息将其移至“技术笔记” → 返回回答 → 引用 1 仍为同一笔记与旧片段；再打开原文显示新库路径。`v3-source-after-move.png`。不会把新库的资料混入旧回答。
- 冲突回归：Pixel 的保存冲突场景另存成功，阅读标题为“（草稿副本）”且保留手机补记；深色冲突说明实测为主题警告色 `rgb(243,196,109)`。证据 `v3-conflict.png`、`v3-dark-conflict.png`。
- 最终 `npm run build` 通过 28 文件 runtime 完整性、TypeScript、Vite；原型无独立 lint 脚本。任务上下文 validate 与任务差异空白检查通过。未运行生产 pnpm check 或真实微信测试，因为本轮未改生产工程。
- `overview.png` 从四张实拍裁出手机主体组成，已实际打开核对。浏览器最终恢复 iPhone / 浅色 / 开始提问，测试内存变更已随 reload 清空。

结论：可交付用户评审 v3 交互。没有本轮待修问题；此结论不等于用户认可设计或正式小程序实现批准。
