# AI对话与生成交互精修

## 目标与背景

第七模块交付主对话与文档侧栏全部交互的独立HTML当前/提案对比。2026-10-19用户先要求「完全去掉，使用 AG-UI 协议和 assistant-ui 支持的交互，不要自定义」，随后明确「对话的渲染我是全盘采用的 assistant-ui 官方组件，不要有定义的组件和样式覆盖」。最终范围是完整Thread、Composer、消息、Markdown/代码、真实思考/工具、附件、动作和错误均采用官方原件及默认CSS；v2的局部替换与主题适配不再满足要求。应用导航等宿主保留既有规范，具体新版获用户认可前不改产品代码。

## 最新反馈与待确认边界

2026-10-19，用户反馈「但是输入框里的模型和思考强度选择还有知识库范围都是需要的」。确认三项功能及输入框内的位置都是必要需求；v3移到Thread外不满足该位置要求，不能视为获批。官方固定版本提供ModelSelector与Effort，但完整Thread没有Composer工具栏插槽。待确认仅Composer工具栏允许最小业务组合这一边界；消息渲染、官方基础件和默认样式仍不覆盖。此决定明确前不生成声称全盘未改Thread的v4、不改产品。证据见research/composer-controls-contract.md。

## 需求与范围

- R1 按 packages/chat 与 renderer 宿主实际源码，保留71组379来源状态及稳定ID/锚点。删除的现行入口仍在current列和映射中可追溯，proposed明确标记removed，不能以“全覆盖”强行重新显示。
- R2 覆盖主对话、新建/历史、范围/模型/强度、队列、流式消息/真实模型思考/工具/引用/媒体、停止/失败/重试、笔记保存、Agent中断/截图交接。范围以源码和本次明确删除要求为准；新增业务仅限用户已同意规划的R11标准聊天附件。
- R3 每适用切片覆盖浅深、窄屏、键盘、hover/focus/pressed/disabled/loading/empty/error/success/cancel/recovery。原生与接口边界单列，映射数量不冒充GUI实测。
- R4 独立HTML以同场景/内容/逻辑尺寸比较，提供完整导航、状态切换和可操作恢复路径；当前列来自源码与真实基线。
- R5 对话内直接使用固定官方Thread及完整依赖、默认主题和样式；不再沿用Mimir对话气泡、输入框、字号/颜色/间距覆盖。应用导航与文档宿主仍保留已批准规范。WeKnora固定版本证据仅判断知识库/Agent业务合同，不作为对话自绘模板。
- R6 冻结v1和v2的HTML/源码/版本/哈希不覆盖；新修订只创建prototype/v3，另记版本与审批。独立复核全量来源分类、官方原件/默认样式、代表浏览器路径；本版认可前不实施。
- R7 原有缺口来源继续留证：代码复制失败、零内容断流恢复、历史标准重试、图片适配/错误、部分草稿/回退互斥。对话内表现以官方原件为准，不为复刻v2修改官方复制/图片/开合状态机；必需业务恢复及草稿守卫保留在对话外宿主，差异逐项明确，不能声称旧提案已全部实施。
- R8 proposed的所有主/侧栏、实时/历史、运行/完成/失败/停止场景完全移除自定义mimir.trace展示及分词/召回/计数日志；不显示“思考N轮、调用M次工具”，不另造替代过程条。未来产品实施同时停止本轮自定义trace发送与消费；旧历史trace保持数据兼容但不渲染，不做破坏性数据库迁移。
- R9 完整渲染链全盘官方：直接使用固定官方Thread及其原件闭包，不传自定义components override、不注册自定义消息/part/data/tool UI、不手工组合摘录替代完整Thread。真实reasoning/tool-call来自相应消息，禁止trace转换。保留来源/许可/默认主题；不改官方源码、CSS选择器、主题变量、字体、间距、颜色，不加覆盖/伪元素/!important。只允许模块解析、依赖及真实运行时/IO adapter接线；本地SDK小版本差异与必要最小升级留证。

- R10 官方没有内置的Mimir能力（引用定位、模型/范围/强度、队列取回、保存笔记、文档执行桥、截图/未保存守卫等）只通过真实数据/能力/宿主IO接线；确需业务UI时位于官方Thread外的应用宿主区，并显式标注非官方。不能把自定义slot或移走后仍在官方输入/消息内的控件称作全盘官方，也不能静默删数据/动作或放宽执行安全。

- R11 用户已选择「一并规划聊天附件能力（推荐）」。标准AttachmentAdapter负责真实附件数据/能力接线，官方附件组件与默认样式不改；上传、准备/解析、发送/移除、失败/取消/重试、格式/大小/数量限制、排队/历史/生命周期都需进入新稿。聊天附件不自动永久导入知识库；格式和保留策略建议在独立子任务中明确并随具体HTML审批，不能直接复用KB ingest产生隐性落库。

- R12 三项控制须在输入框内可见并保留原有能力和守卫；R9/R10关于将它们移到Thread外的定位不再满足最新需求。仅Composer组合的具体例外仍待用户决定，不将拟议例外当成已批准。

## 业务边界

本轮只修改任务资产和新HTML，当前只做方案与HTML，无产品代码、API/存储、鉴权、模型/Agent执行或Office工具栏改动；未来附件API/存储/模型接线由10-19-chat-attachments子任务独立规划验证；不删除引用、保存、范围、队列、截图和未保存守卫等现有业务能力。本次不是全项目协议迁移或产品依赖升级，不删除旧会话数据。真实工具执行、原生能力和全仓质量门留待新版认可后实施验收，不推送。

## 验收

- AC1 R1–R3：全部实际交互入口/删除项都有来源与可定位状态，失败、取消、恢复路径明确。
- AC2 R4：当前/提案同内容同尺寸，可切换主题/尺寸，代表完整路径通过GUI抽验；无真实请求与存储。
- AC3 R5/R9：外部证据固定版本，官方组件有可验证来源、许可、适配说明；运行时数据不虚构，兼容性结论有具体证据。
- AC4 R6：v1/v2均完整保留，v3单独冻结，检查/来源映射/预览齐全；未获本具体新版认可不task.py start。
- AC5 R7：每项旧提案差异明确归入官方默认行为或对话外宿主恢复；图片/复制等未由官方实现的行为不伪造已解决。实际产品回归待实施。
- AC6 R8/R9：所有proposed对话用完整未改官方Thread，无自定义trace或自绘消息组件/样式覆盖；旧记录不合成假reasoning/tool-call；current保留现行事实。

- AC7 R10：71/379来源状态逐项标为official / host-external / removed / boundary（可组合），有具体来源、实际呈现与能力限制；不能将源状态数量当成全量GUI验收，也不假称官方具备未提供的功能。

- AC8 R11：官方附件从选择到可发送/移除/取消/错误恢复完整呈现，模拟与真实能力边界明确；附件子任务有独立PRD/设计/计划/上下文、显式依赖和格式/限制/寿命验收，产品实施仍待具体新版认可。
