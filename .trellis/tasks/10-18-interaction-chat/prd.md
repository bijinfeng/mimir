# AI对话与生成交互精修（v5规划）

## 目标与背景

主对话和文档侧栏统一回到Mimir已批准的白灰工作面、中性导航与绿色操作设计。2026-10-19用户要求「assistant-ui 还是和我们的样式风格不太一致，使用 tantack ai react + 自定义组件替换 assistan-ui 吧，但是风格可以换，交互需要一模一样，单开个交互细节页面，把 AG-UI 协议对应的每一种组件每一个交互都要展示出来」。按官方包名`@tanstack/ai-react`研究和规划。此要求替代此前全盘官方组件/禁止样式自定义及仅Composer有限扩展的方向；v4作为交互对照，v1–v4完整保留，不再作为新稿视觉约束。具体v5 HTML认可前不修改产品代码。

## 已确认事实

- TanStack AI React负责状态/流，不提供完整视觉组件库；AG-UI定义事件、消息和运行语义，不规定每个事件有一个可见组件。独立详情页须给出完整事件到界面/无界面处理的对应，不能造出协议没有的“官方组件”。
- 仓库服务端已使用TanStack AI，客户端仍使用assistant-ui/react-ag-ui及AG-UI client。版本、请求体、历史、队列、文档工具中断/续轮存在兼容工作，不因换包视为自动兼容。
- 模型为全局chat/reasoning两条只读绑定；标准/深入为deepReasoning角色路由；范围为全部文档或最近20篇中的单篇；文档侧栏有效标准。模型显示名不是每请求固定provider/model ID。
- 标准聊天附件已获准纳入规划，在子任务10-19-chat-attachments单独约定临时资源、解析、发送与寿命，不能将KB永久导入当聊天附件。

## 需求与范围

- R1 覆盖主对话及文档侧栏、历史/生成/失败/停止、引用/保存/媒体、Agent/截图/宿主交接全部实际入口。维持原71组379来源态及24新增附件态的稳定ID与来源，不删除无法还原的项来声称完成。
- R2 每个场景呈现当前与提案同内容、同尺寸对比；current按源码及实测基线重建，不冒称实拍。具体效果另存v5，v1–v4不覆盖。
- R3 逐组件保留v4交互合同：默认/hover/focus/pressed/disabled/loading/empty/error/success；键盘、IME、展开/收起、焦点返回、提交/取消/恢复、滚动与贴底、断流/部分内容/历史与主侧栏差异。视觉变化不能改变操作或引入布局抖动。
- R4 交付两个独立HTML入口：完整场景对比review.html；交互细节interactions.html。两页可互相导航，详情可搜索/分类/深链，每项有可操作演示、事件/数据输入、可见变化与终态、错误与恢复，明确模拟和真实能力边界。
- R5 以`@tanstack/ai-react`与兼容客户端接收流及管理消息，消息/Markdown/代码/思考/工具/附件/动作/错误/输入改为自有组件并使用项目设计规范。新稿执行路径不再依赖assistant-ui，不做仅改名称的静态展示。
- R6 以冻结v4交互为对照建立逐项parity清单，所有映射有实现/演示定位和验证状态；官方源码仅作为只读行为证据，不将移除官方组件视作可静默删功能的理由。
- R7 原缺口及v4差异继续追溯：零内容错误、复制/导出失败、图片适配/损坏、历史重试、部分草稿/回退互斥。逐项明确v4行为、拟保留行为与产品实际能力，不能以假回调声称真实重试/导出/执行成功。
- R8 自定义mimir.trace及分词/召回/轮次计数展示仍完全删除，不造替代过程条。真实reasoning与tool events依协议展示，不由trace合成；旧历史数据非破坏性兼容。
- R9 AG-UI全事件清单基于固定schema和官方证据；运行/步骤、文本/思考、工具调用/结果、消息/状态同步、活动、原始/自定义及中断/恢复按实际版本逐一列出。纯同步事件展示界面影响；不可见/未知类型明确处理策略。TanStack扩展与Mimir业务事件另列，不能混称标准事件。
- R10 模型/强度/范围/容量、队列取回、引用定位、存笔记、文档执行、截图和未保存守卫保持现有合同。所有新发送入口在附件准备/异步初始化前冻结范围/角色/附件/Agent目标；队列各项独立，停止/失败只归还首项，已执行工具续传只重送缓存。
- R11 聊天临时附件选择、准备、失败/移除重选、预览、发送/取消、格式/容量/寿命、队列/历史均在新稿保留；上传/解析/模型/存储须单独实现，不因自有UI放松Agent/只检索/视觉/专用截图限制。
- R12 模型/思考强度/范围在输入框内；主/侧栏、未配置/同名/长名、加载/失败/空/替换/清除有完整状态。菜单、焦点和发送联动保持，不能新增会话级模型选择或知识库多选。
- R13 详情页区分“产品已有/本轮附件拟议/协议能力演示/待真实服务验证”。协议可演示的工具审批、活动/状态等不自动扩大Mimir产品能力；未知事件不破坏已生成消息。不得凭标注unsupported跳过v4已有交互。

## 验收标准

- AC1 R1/R2/R6：71/379及24态逐项保留current/source/boundary/稳定ID，覆盖清单与HTML匹配；v5 parity清单逐项可追溯，无未披露的交互删减。
- AC2 R3/R4：两个独立HTML有完整导航和可操作路径，代表路径GUI验收；浅深/窄屏、键盘焦点、取消恢复与hover几何验证。统计数量不冒充全量GUI测试。
- AC3 R5/R9：真实固定TanStack依赖接收合法本地流，源码/许可/版本/导入闭包可核对；AG-UI全事件枚举覆盖，事件序列及非法/未知处理有证据，客户端不执行assistant-ui。
- AC4 R2：产品、产品manifest/lock与v1–v4hash保护；v5单独冻结，具体认可前不task.py start。
- AC5 R7/R10：快照/队列/停止/失败/工具缓存续传、历史与宿主守卫有可见路径与验证，真实服务边界明确。
- AC6 R8：所有proposed无mimir.trace、自绘伪思考轮次或伪工具统计；canonical reasoning/tool独立演示。
- AC7 R9/R13：每个标准事件和扩展都有准确分类、详情深链/交互/终态/恢复/非UI或不支持理由；普通使用页面不混入调试数据，技术细节仅位于专用详情页。
- AC8 R11：附件子任务与父任务最新技术方向和HTML一致；AGUI引用/canonical附件ID、限额/生命周期真实能力留待实施，不用模拟声称产品可用。
- AC9 R12：三项控制在输入框内共用同一状态；主/侧栏限制、只读绑定、单篇/全部及发送冻结准确，且不遮挡附件/发送停止。

## 本轮范围外与后续

本轮仅研究、迁移方案及HTML审批；不改产品依赖、不连接真实上传/模型/Agent写原件，不新增Mimir工具审批/多人等产品能力。正式迁移的API/AGUI往返、资源/鉴权/寿命、Office/Agent、原生picker/剪贴板/IME/读屏/Electron与全仓质量门在具体v5认可后实施并验收。v4的官方组件方向已被最新需求替代，其审批不转授v5实施。
