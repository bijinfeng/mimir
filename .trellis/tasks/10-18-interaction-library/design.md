# 知识库浏览与管理 · 对比稿设计

状态：planning，独立 HTML 方案；产品实施待本版认可。

## 视觉与结构

沿用已认可的语雀方向及当前知识库身份区、工具条、文档区结构。知识库名称/描述/ID在进入子目录后保持不变，位置只由文档区面包屑表达。保留列表/卡片两种视图及浅深主题，不新增首页仪表盘、排序筛选或批量管理。

提案重点：统一列表的列对齐、文件夹/文档密度和稳定动作占位；让卡片信息层级更清楚；长路径可折叠并展开完整路径；统一子目录表单与危险确认的等待、错误及取消恢复。输入边框1px，焦点使用中性边框与轻量轮廓，图标文字 flex 居中，hover不得改变盒子尺寸。

## 现有能力与提案边界

- 文档列表当前覆盖目录全部后代，接口最多100条且无total/分页。两列使用相同数据，不画无限列表，不把目录条目解释为仅直接子文档。提案明确当前目录及其下级，展示来源路径。
- 列表文档当前只有打开入口；卡片有按类型可用的更多动作。提案将既有卡片动作补入列表，明确标为“新增前端入口”，不增加新的服务端能力。
- 目录重命名走已有move接口，仅修改同父级名称；不增加自由移动目录的拖动或选择器。
- 删除目录服务端将文档folder清空为null。提案须如实说明“保留文档、清空目录归属”，不得承诺留在当前知识库根；无新增回收站或重新归库界面。文件删除原件不可恢复，笔记服务端有回收文件但无产品一键恢复。网页/公众号/GitHub资料的当前确认文案与实际删除语义不一致，提案单独说明资料记录移除及无产品一键恢复，不承诺文件原件删除或笔记回收。
- 缺失子目录识别、空标签提示、表单单飞与等待锁定属于拟修复前端缺口；与当前状态分别呈现。
- 知识库创建/编辑复用模块2统一名称+描述弹窗，无图标选择。收集/导入复用模块4；打开/编辑与未保存守卫复用模块3合同。此处用静态模拟明确衔接，不能替代对应产品验收。

## 独立原型架构

源码盘点稳定ID → scenes.json → 明确view与interaction path → coverage.json一对一映射。原型不导入产品组件，不请求业务接口、不读写真实产品数据。两侧相同虚构样例、内容、尺寸和初始状态；当前侧以源码及verification/baseline截图为依据。界面之外的评审工具负责模拟请求完成/失败、离线与外部变更，不混入产品控件。

审阅壳提供分类、场景搜索、当前/提案/并排、浅深、桌面/390px/低高度、200%文字及减少动效。宽屏并排时每侧保持独立等宽容器；窄屏切单侧或上下对照，保持可操作。所有覆盖项直接定位；边界场景须显示真实限制和关联交接，不能以同一泛化提示替代。

所有异步操作使用显式评审结果控件，不用计时器冒充真实进度。表单失败保留草稿、忙时防重复与禁关闭、Escape与取消回焦；菜单不触发父级打开。原生文件选择/拖入/下载/剪贴板/读屏/Electron只描述边界，HTML模拟不等于宿主通过。

## 验证与冻结

构建单文件review.html，完整性脚本检查ID唯一性、覆盖映射、无产品导入/外部资源/业务请求。独立检查对照源码及基线；主会话批量抽验桌面浅深、390px、低高度、表单失败重试、菜单键盘回焦与hover几何。验证实际范围与未测边界独立记录。冻结版本与SHA256，精确批准后才task.py start；任何实质方案变化重新出稿。

## 图标修订边界

仅改变提案侧文件/资料图标，不改变当前侧、文件夹图标、行为与列表布局。保留v1快照；文件类型依然以名称后缀/来源表达，不只依赖颜色。评审壳提供两套候选选择及图标对比视图，选择不属于产品功能、不写真实偏好。沿用本地SVG、固定尺寸和语义映射；单文件HTML无需联网。研究与HTML更新后重新冻结待认可，不启动产品实施。
