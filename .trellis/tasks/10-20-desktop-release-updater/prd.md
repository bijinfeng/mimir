# GitHub Actions 桌面端构建分发与自动更新

## Goal

让使用者下载 GitHub Actions 构建的 mimir 安装包，并在桌面客户端获得后续版本更新；维护者不再逐台机器手工构建和上传。

## Background and Confirmed Decisions

- 用户要求通过 GitHub Actions 打包、分发和更新客户端；2026-10-20 同意创建任务并进入规划。
- 用户明确要求将 `bijinfeng/mimir` 改为公开仓库，已执行成功；匿名 GitHub API 返回 HTTP 200、`private=false`。安装包与更新信息直接使用本仓库 Releases。
- 用户确认首版支持 macOS arm64（Apple Silicon）、macOS x64（Intel）、Windows x64 和 Linux x64。
- 用户要求进一步设计更新交互，并已选择“轻提示，点击后查看详情并决定重启”，不自动打开详情窗口。
- 用户确认暂时没有 macOS Developer ID 证书和公证凭据。当前仅 ad-hoc 签名；不得宣称 macOS 自动安装更新已可用。
- 现有客户端为 Electron 44、electron-builder 26、版本 `0.1.0`；根 `desktop:build` 构建服务端和桌面三段产物、部署生产依赖并打包。尚无发布工作流、更新器或正式签名配置，仓库尚无 Release，Actions Secrets/Variables 名称清单为空。
- 现有构建配置只有 macOS DMG、Linux AppImage；Windows 尚未实机验证。CI push 分支写为 main，实际默认分支 master。
- 本地模式使用自带 renderer/preload；连接服务器模式加载远端页面且不安装 preload。更新功能须属于原生载体，覆盖两种使用方式及首启选择页。
- 已检索过去的“自动更新”会话，仅命中本次任务，没有可复用历史决定。技术参考证据见 `research/distribution-evidence.md`。

## Requirements

### R1 构建和版本

GitHub Actions 覆盖四个已确认系统/架构；安装包能启动本地知识库，不仅生成空壳。应用显示版本、安装包版本、更新元数据及 Release 版本一致。

### R2 分发

通过公开仓库 `bijinfeng/mimir` Releases 分发。建议使用 `vX.Y.Z` tag 发布稳定版，手动触发仅构建测试产物；tag 发布须在所有目标构建和产物校验成功后一次性对外可见，不向用户暴露不完整的更新版本。此触发约定待最终方案评审确认。

### R3 更新体验

用户已选轻提示：更新准备好时不自动弹模态框、打开详情窗口或抢焦点。建议打包应用启动后及每 6 小时检查稳定版，Windows NSIS 和 Linux AppImage 默认后台下载且允许关闭自动下载。标题栏/关于页（本地）与系统菜单（所有模式）均可主动打开同一个本地更新详情窗口；关闭提示或窗口不取消下载，稍后仍可找到更新。普通退出不自动安装。详细状态、文案、键盘和交互以 `ux.md` 为唯一归属，整体方案待最终评审。

### R4 macOS 无证书边界

首版构建两种架构的 ad-hoc 签名测试包，提供检查新版和打开官方下载页的手动更新入口，清楚说明是测试包及系统可能阻止打开。代码与工作流预留 Developer ID 签名和公证接入；配置齐备且跨版本验证通过后才能启用 macOS 自动下载安装。证书申请、购买及绕过系统保护不属于本任务。

### R5 更新信任边界

客户端不携带 GitHub PAT、发布凭据或签名私钥。更新来源固定为官方公开仓库；远端页面不能设置来源、调用下载/安装或传入任意外部 URL。开发态和非受支持安装形式不执行真实安装。首版只接收稳定版且禁止自动降级。Windows 没有签名证书时可提供未签名 NSIS 包，须说明系统信誉提示；不冒充已通过 Authenticode 验证。

### R6 数据和退出

安装更新沿用现有 appId、userData、使用方式配置及本地资料。重启前必须经过当前编辑内容的保存/离开保护，之后才关闭本地宿主和数据库并安装。保存失败、迟到响应或窗口关闭被拒绝均不能放行。能代为保存时提供真实保存动作，无句柄时引导返回工具栏；旧云端不能证明保存能力时需明确由用户先保存并确认，不能声称已自动保护全部内容。宿主关闭失败或超时中止安装，不强行覆盖正在运行的宿主。

### R8 更新交互完整性

更新窗口明确区分检查、下载、准备、可安装、保存被阻止和失败，提供真实版本/进度/发布说明和下一步；普通用户不需要理解证书、数据库或校验算法。当前状态与可执行动作始终一致，重复点击不创建重复操作。浅深主题、窄窗口、键盘、读屏、同版本提示去重和通知禁用均纳入验收。更新 UI 不依赖服务器可达，远端页面不获得安装权限。

### R7 运维与交付

记录构建/发布操作、所需 Secrets、证书配置方法、各平台限制和验证证据。没有真实运行的跨平台构建、安装和升级不得声称已通过。首个更新器版本需用户手动安装，以后才可更新；首版尚无上一个可自动升级的客户端。

### R9 fnOS 原生包同版本分发

2026-10-20 用户新增：提供 fnOS 原生构建流水线，和客户端一并发布。沿用现有 fnOS 已确认的 Linux x86_64/Node22 `.fpk` 方案；同一稳定 tag 对应桌面四目标与 fnOS 包，全部构建/校验成功后统一公开。fnOS 包版本与 Release 一致，可匿名下载；不将 `.fpk` 加入 Electron 自动安装路径。fnOS 实机安装和升级验证须按实际设备证据登记。

## Acceptance Criteria

- [ ] AC1（R1）：四个平台构建产物齐备，版本一致；错误 tag/版本在构建发布前失败，原生依赖与目标系统/架构匹配。
- [ ] AC2（R2）：普通使用者可匿名下载匹配系统的包；元数据不相互覆盖，发布失败时不会出现新的可用更新版本。
- [ ] AC3（R3）：覆盖无更新、发现更新、真实下载进度、校验/准备、稍后安装、确认重启、失败重试及重复操作；自动下载完成不弹模态框、不抢焦点，同版提示去重，关闭详情窗口后状态和下载保留；三个载体页面场景都有原生菜单入口。
- [x] AC4（R4）：无证书 macOS 构建能提供手动下载入口，不能尝试自动安装；正式签名模式缺少必需配置时清楚失败，不静默退回测试包冒充正式包。
- [x] AC5（R5）：无客户端发布凭据、无远端页面更新 IPC、无任意 URL 更新源；开发态和不受支持的安装形式不调用安装器；稳定版不自动接受预发布或降级。
- [ ] AC6（R6）：安装调用晚于保存保护放行及宿主关闭完成；保存失败/迟到保存/新改动/关闭被拒绝/关闭超时不安装，重复重启请求只执行一次；真实升级后原模式配置和本地资料可访问。
- [x] AC8（R8）：按 `ux.md` 的状态矩阵完成真实组件浅深/窄宽与交互验证；旧云端不支持保存能力时不虚构自动保存；远端网页无更新安装权限。
- [ ] AC7（R7）：`pnpm check` 和相关构建通过，文档和实际证据完整；模拟测试、macOS 本机验证、GitHub runner 验证和真实跨版本升级分别记录。

- [ ] AC9（R9）：原生 Linux x86_64 runner 生成并校验真实 `.fpk`，与客户端四目标同 Release 统一发布；fnOS 构建失败、缺包、错版本或资产篡改阻止发布。记录固定打包工具版本、匿名下载及实际验证边界。

## Out of Scope

- 浏览器网页、服务器 Docker、fnOS 安装包自动更新，本地与服务器之间的数据同步或迁移。
- 自建更新服务器、额外分发仓库、灰度发布、beta 通道、强制更新或自动降级。
- 购买/申请证书，绕过 Gatekeeper/SmartScreen；重新设计共享工作区或给云端网页注入桌面桥；允许按现有保存契约补齐通用窗口离开保护。
- 本轮未经另行授权推送代码/tag、实际发布安装包或配置用户凭据。
