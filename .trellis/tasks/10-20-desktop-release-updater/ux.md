# 桌面更新交互方案

状态：已批准实施并完成组件评审。2026-10-20 用户已确认“轻提示，点击后查看详情并决定重启”。此前“下载完成自动弹出系统对话框”的建议作废。本文是本任务交互的唯一详细归属；PRD 只保留要求和验收映射。

## 场景与设计原则

使用者正在写笔记、编辑 Office 文件、检索资料或等待回答。更新的成功标准是用户知道发生了什么、能自主安排下载与重启、不会丢掉正在编辑的内容。Operate 模式，沿用现有紧凑工作台、系统字体、白灰/深灰表面和绿色主操作，不引入新的视觉风格。

证据：现有 TitleBar/AboutPage/ClientSection、UnsavedProvider/UnsavedGuard 与项目设计规范；已查看 2026-10-19 的 main-light-final 实际工作区截图，作为既有视觉参考，不冒充当前更新界面截图。Obsidian 只作工作区连续性与更新概念参考，不凭空声称其当前弹窗或按钮布局；WeKnora 版本核对沿用本任务 research，未发现能直接移植的 Electron 更新交互。

## 已选提醒策略

- 后台检查、下载、准备完成均不自动弹模态框，不切换页面，不抢键盘焦点。
- 本地工作区标题栏出现低强调文字入口：下载中显示“更新下载中”，准备完成显示“可重启更新”。不使用闪烁红点，不按每个百分点播报或改窗口标题。
- 原生应用菜单在所有模式始终提供“软件更新…”入口，下载完成时改为“软件更新… · 可安装”；云端模式用这一原生入口，不给远端网页注入桌面桥。
- 更新准备完成时只发一次可关闭的非模态轻提示，提供“查看更新”。不含直接安装按钮，避免误触。原生桌面通知可用于云端模式；即使通知被系统禁用，菜单中的持久状态仍在。
- 同一版本已关闭/已处理的提示跨重启去重；仍保留持久入口，新版本才再次提醒。自动检查失败不 toast 连发，手动检查始终给出可见结果。
- 不自动打开更新详情窗口；只有用户点击轻提示、标题栏入口、关于页按钮或应用菜单后才打开。

## 一个更新详情窗口，多处入口

更新详情是客户端自带的独立本地窗口，启动不依赖知识库宿主或远端服务器。已有窗口时只聚焦它，不重复创建；关闭窗口不会取消后台下载，也不会退出客户端。

入口：应用菜单“软件更新…”为共用入口；本地标题栏的动态状态入口；本地“关于 mimir”页展示当前版本及“检查更新”按钮。三个入口展示同一主进程状态，不能各自创建检查/下载任务。首启选择页通过系统菜单使用相同窗口，不增加第一次使用的负担。

窗口的信息顺序：

1. “软件更新”标题；当前版本为次级信息，不占大卡片。
2. 状态标题，例如“新版本已准备好”或“正在下载 mimir 0.1.1”；新旧版本关系清楚，示例版本仅为设计占位。
3. 状态说明/真实下载进度，错误就地出现。更新日志只呈现当前 Release 的真实内容；没有日志时不编造亮点。完整说明在固定官方 Release 链接打开。
4. 轻量分隔后的偏好“自动下载更新”（Windows/Linux，建议默认开启）；自动检查始终可手动触发。关闭偏好不影响已下载的版本，下载中关闭则作用于后续版本，需明确说明。
5. 底部动作行，一次只有一个明确的主操作。关闭窗口与“稍后”均不丢弃已下载更新；非模态内容不能使用遮罩挡住主文档。

不在窗口中展示 GitHub Token、证书术语、SHA-512、SQL、资源路径等实现信息；需要用户理解的 macOS 手动更新限制与 Windows 系统提示写成普通语言。

| 状态 | 标题/正文 | 主操作 | 次操作与行为 |
| --- | --- | --- | --- |
| 尚未检查 | 当前版本 0.1.0 | 检查更新 | 显示真实上次检查时间，没有记录就不展示 |
| 检查中 | 正在检查更新… | 检查中（不可重复点） | 可关闭窗口，不显示假进度；长时间无响应给出网络提示 |

| 下载中 | 正在下载 mimir 0.1.1 | 下载中（状态） | 已知总量显示 42% · 84 MB / 200 MB；总量未知只显示已下载量，不伪造百分比 |
| 下载后的校验/准备 | 正在准备更新… | 准备中（不可安装） | 100% 下载不代表已可安装；关闭窗口仍继续准备 |
| 可以安装 | 新版本已准备好；重启后将使用 mimir 0.1.1 | 重启并安装 | 稍后；普通退出不会安装，不承诺下次开机自动安装 |
| 重启准备 | 正在准备重启… | 准备中（不可重复点） | 保存/关闭保护完成前不运行安装器；不显示假剩余秒数 |
| 保存被阻止 | 当前内容还没保存，暂未重启 | 返回文档 | 有真实保存能力时可提供保存并重启；否则引导回工具栏保存，不显示不可用的承诺 |
| 保存失败 | 保存没有完成，尚未重启 | 重试保存（具备能力时） | 返回文档；保留下载结果，不丢弃内容 |
| 检查/下载失败 | 暂时无法检查更新 / 下载未完成 | 重试 | 保留已知目标版本，给出检查网络的简短提示；不要暴露堆栈 |
| 文件校验失败 | 更新文件未能通过检查，尚未安装 | 重新下载 | 不提供强制安装；不得把已损坏缓存当成 ready |
| 安装位置不可写等 | 当前安装方式需要手动更新 | 打开官方下载页 | 说明需替换的应用，不把权限错误归咎于用户 |
| macOS 测试包发现新版 | mimir 0.1.1 可用；此测试版需要手动更新 | 下载 macOS 版 | 选择本机架构的官方资产；打开浏览器不是下载完成，不显示“已准备好” |
| 暂无发布版本 | 目前还没有可用的发布版本 | 再次检查 | 查看发布记录；与“已是最新”分开，不显示原始 404 |
| 开发态 | 开发版本不执行自动更新 | 查看发布记录 | 不提供安装按钮，不假造已是最新 |
| 升级后首次启动 | 已更新至 mimir 0.1.1 | 查看更新说明 | 可关闭的一次性轻提示；仅在实际运行版本变化后展示 |

## 下载与安装的控制权

建议默认自动检查并后台下载，允许关闭自动下载。下载前不抢焦点，下载完成不倒计时、不强制重启、不把普通退出变成隐式安装。用户点击“稍后”后，状态入口仍可找到下载结果；下次启动先重新确认已缓存包与当前有效元数据，不直接声称 ready。

不在首版添加“跳过版本”、beta 通道、安装倒计时或频繁提醒。重试可以重新下载；没有真正断点续传证据时不出现“继续下载”字样。新版本替代旧下载时由控制器统一处理，不保留多个相互冲突的“可安装”版本。

## 保存与重启的单一安全流程

用户点击“重启并安装”本身已是确认，不再叠一个泛泛的“确定吗”弹窗。接下来执行一次准备离开的动作，并对当前真实状态给出反馈：

1. 主工作区无未保存改动、无进行中的写入：继续进入宿主关闭，再调用安装器。
2. 有未保存内容：主窗口已有 UnsavedGuard 接管，返回原文档上下文；有保存能力时提供“继续编辑 / 丢弃并重启 / 保存并重启”。默认焦点为继续编辑，不默认丢弃。自动保存内容不提供伪造的“丢弃”按钮。
3. 当前编辑器不提供可调用保存句柄（现有 Office 原件场景）：只允许返回文档自行保存或明确放弃手动编辑改动，不能画一个没有保存能力的“保存并重启”。具体丢弃能力按原有 guard 契约判断。
4. 保存中：显示“正在保存当前改动…”，等待实际完成；失败保留原内容和下载结果。保存期间继续编辑时重新判断脏状态，不拿旧快照的成功响应放行。
5. renderer 确认保存后，还要通过窗口 beforeunload/关闭拦截；页面加载中、保存能力未知或校验失效时不自动判为可重启。这个准备阶段结束前不关闭宿主。
6. 旧服务器页面无法证明支持保存握手：不注入 preload、不读取远端内部变量，不声称自动保存成功；回到主窗口并明确要求用户先保存，再显式确认重启。存在 beforeunload 阻止时必须尊重，不提供“强制更新”绕过选项。
7. HTTP/数据库关闭失败或超时：安装停止；显示“暂时无法完成重启，更新尚未安装”。若宿主已部分关闭，提示重新启动客户端恢复，不伪装成可以继续编辑的正常工作区。

用户主动确认重启会中断仍在运行的 AI 回答/传输。详情在重启动作旁以简短文字说明；若能够可靠获取进行中任务则呈现真实具体任务，不编造已检测全部任务，也不把停止回答当作错误。跨应用窗口的保存握手必须由客户端发起并绑定一次性 request/窗口/document generation，页面不能独立触发安装。

## macOS 的诚实降级

macOS 保留同样的窗口、版本与更新说明层级，主动作改为“下载 macOS 版”。说明：“此测试版需要手动更新。下载后退出 mimir，再替换应用；系统可能阻止打开。”不在常态窗口中解释 Developer ID、证书或公证 API；不引导绕过系统保护。下载页面打开后继续保留“发现新版”，不能误变成“下载完成/可重启安装”。正式签名支持就绪后仍遵守轻提示及用户确认重启。

## 可访问性与尺寸

- 状态和操作均有文字，不靠颜色、动画或图标区分；进度真实且支持总量未知。
- 使用现有 antd 按钮、开关与反馈语义；键盘 Tab 顺序随内容层级，Esc 关闭详情窗口/回到安全状态，保存中不允许 Esc 隐式丢弃。
- 新窗口打开时聚焦标题或首个可操作项，关闭后焦点回到触发入口；后台下载不改变编辑器焦点。屏幕阅读器播报状态阶段，不每 1% 打断阅读。
- 沿用项目系统字体、紧凑行距、6px 控件圆角及主题 token。状态文字和错误在浅/深主题都可读。主操作绿色，错误只给实际错误区域。
- 窗口可调整尺寸，窄宽时按钮换行、更新说明滚动，主操作保持可见；放大文字不隐藏“稍后/返回文档”。

## 实现验收与证据

- 标题栏、关于页、独立更新窗口采用实际组件生成状态样例；实现阶段归档同内容/主题/尺寸的真实组件 HTML 前后对比，保留原有比较稿。新窗口没有旧版时明确标为新增状态，不能编造前版。
- 浅/深、长版本号、长发布说明、窗口缩窄、总量未知、连续重试、关闭重开、通知禁用、点击稍后、离线重连均有覆盖。
- 保存 guard 覆盖手动/自动保存、有/无句柄、保存失败、保存中再编辑、旧响应、新窗口/新文档、beforeunload 取消及旧云端能力未知。
- 轻提示采用用户已选方案，原生通知/菜单及本地组件分别留截图和实测记录；模拟界面不冒充真实安装证据。

## 已批准的实施范围

用户已选轻提示；其余整体建议为：标题栏/菜单常驻入口 + 独立本地更新详情窗口 + 默认自动检查/下载但可关闭下载 + 保存保护后用户确认重启。用户随后已明确“开始吧”，本轮按以上范围实施。
