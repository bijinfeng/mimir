# 试用 Pele 渲染 Mermaid 图表

## 目标

在 Mimir 现有文档中实际试用 Pele，验证图表可读性与兼容性，并保留恢复到现有 Mermaid 的能力。用户于 2026-10-20 在可行性评估后要求“先试用 Pele”，随后同意“创建任务并推进接入”。

## 已确认事实

- `packages/renderer/src/editor/diagram-render.ts:112` 集中处理 Mermaid / WaveDrom；当前 Mermaid 锁定解析版本为 11.17.2，动态导入，返回净化后的 SVG。
- `packages/renderer/src/editor/diagram-code-block.ts:47` 将 SVG 放入隔离的图片，图表源码仍属于原有 codeBlock；编辑防抖、迟到结果保护与 Markdown 序列化已存在。
- Pele 支持 Mermaid 语法，但布局与主题不保证一致。前序 1.7.0 评估中，12 个基础样例在 Node 环境生成 SVG；尚未完成浏览器视觉、真实文档与性能验证。详见 [调研证据](research/pele-evaluation.md)。
- 项目的 pnpm 最小发布时间策略拒绝了刚发布的 1.7.0，安装失败且依赖文件无变化；试用选择 1.6.0，不增加策略豁免。

## 范围与要求

- R1：现有文档的 Mermaid 图表优先用 Pele 1.6.0 渲染；采用动态加载，避免提前加载全部图表引擎。
- R2：Pele 加载、解析或渲染失败时，尝试原有 Mermaid。两者都失败时保留可恢复的错误提示与源码。
- R3：继续使用既有 SVG 净化、外部资源移除和图片隔离；不因引擎替换放开链接、图片或 HTML 标签。
- R4：保持图表源码编辑、保存重开、撤销、只读显示，以及 WaveDrom 与普通代码块行为。
- R5：保留相同样例、主题和尺寸下的真实组件前后 HTML 渲染对比，并记录覆盖清单及验证结果；旧对比归档不覆盖。

## 不在本轮范围

- 不移除原 Mermaid 依赖，不新增用户设置或引擎选择界面。
- 不接入聊天回答图表，不增加缩放、内联 SVG 或新的响应式布局行为。
- 不承诺与 Mermaid 像素一致；不把语法通过误记为主题/布局兼容。CSS 变量主题穿透图片的问题不通过放宽隔离解决。

## 验收条件

- A1（R1、R2）：真实 Pele 能绘制流程图、长中文、时序、类、ER、状态、甘特、思维导图、饼图、子图与常见配置样例；针对 Pele 失败的可控测试证明原 Mermaid 回退有效，双方失败仍显示错误。
- A2（R3）：事件属性、脚本、外部 URL 和 foreignObject 不进入最终 SVG；Pele 禁止图表自身链接与图片，回退仍经过同一个净化入口。
- A3（R4）：现有图表行为测试与 Markdown 保存/重开、幂等测试通过；编辑态可改源码，只读态隐藏成功渲染的源码；错误修复后恢复预览。
- A4（R5）：在真实浏览器查看浅/深主题及宽/窄尺寸对比，检查文本、连线、裁切、溢出与错误恢复；归档 HTML、覆盖表及实际验证记录。
- A5：`pnpm check` 通过，检查本轮差异后仅提交相关实现、测试、规范及验收记录，不推送。

## 关键决策与风险

- 试用采用 Pele 优先、Mermaid 失败回退；回退无法识别成功渲染后的布局和配置差异，因此视觉验收独立执行。
- 保持现有 SVG 图片隔离与配色行为边界，本轮不为主题升级扩大改动。
- 1.7.0 新增中文/日文标签按字符换行修复；本轮 1.6.0 的长标签必须实际查看，升级等待符合仓库策略。
- 保留两个引擎期间不能宣称总体安装体积已减少；性能收益没有实测前不写入结论。
- 这是局部渲染入口试用，采用轻量 PRD；执行与检查上下文分别由 `implement.jsonl` / `check.jsonl` 指定。
