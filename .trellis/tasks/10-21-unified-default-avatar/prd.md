# 统一用户默认头像

## 目标

用户要求所有未设置头像的用户使用同一个经过设计的默认图案，不再从用户名或邮箱取首字母。采用现有绿色主题中的圆润中性人像，使用户头像与应用渡鸦标识区分清楚。

## 背景与证据

- 用户截图为侧栏 admin 的字母 A 头像。renderer 的 `components/nav/AccountRow.tsx` 有两处用户名首字母回退，`components/settings/AccountSection.tsx` 有一处。共享 renderer 覆盖网页、桌面及 fnOS 托管的网页入口。
- 初始基线：小程序工作树 `pages/account/index.tsx` 的首字母头像随并行资料卡改动尚未提交，旧HEAD没有头像；因此曾准备HEAD兼容的32px最小接入。此策略仅保留为历史记录。
- 最终基线：并行工作已提交为 `2991795` / `c06f843`，HEAD已包含48px View资料卡。最终保留该View、辅助语义与布局，只把initial计算/子节点替换为统一本地图；account页可直接按当前HEAD差异提交，不再使用旧commit-ready override。
- renderer 有自定义头像上传、裁切和上传预览，继续保留。miniapp session DTO 没有 image 字段，不因此扩展 API。

## 需求

- R1：统一同一中性头像图案，与用户名、邮箱、语言及首字母无关。圆润人像、淡绿底和深绿前景；明暗主题均清晰，保持现有头像尺寸与账号布局。
- R2：覆盖侧栏、账号菜单、资料设置、小程序账号入口，所有使用默认头像的用户一致。
- R3：自定义头像及本地上传预览优先；空地址或图片加载失败时回退统一图案。保持辅助功能与上传交互。
- R4：图形在小尺寸仍清楚，复用一个矢量来源，微信使用受支持的本地图片，不用 SVG DOM。
- R5：按相同内容、主题、尺寸保存真实组件前后 HTML/PNG 对比、覆盖表及验证结果。
- R6：只提交本任务差异，保留并行小程序迁移；不更改登录、账户、API 或页面布局。

## 验收

- AC1：各默认头像入口不再显示用户名首字母；不同姓名展示同图形。
- AC2：上传图片、上传预览及图片失败回退行为正确；命名与装饰图像语义保留。
- AC3：明暗、侧栏小尺寸、菜单、设置和小程序原生图片资源有真实验证，前后对比可打开。
- AC4：相关测试、类型和构建通过，原 pnpm check 通过；不能降低断言、超时或安全规则。
- AC5：只提交头像代码、必要测试/资源、规范及本任务记录；记录 commit，不推送或发布。

## 范围外

账户业务、上传/裁切流程重做、随机头像、按名字生成图案、品牌渡鸦替换、miniapp image 字段/API 扩展、并行 NutUI/H5 迁移。
