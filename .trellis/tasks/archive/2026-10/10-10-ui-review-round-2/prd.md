# 第二轮 UI 审查

## Goal

审查整站视觉改版合并后的实际界面，找出影响收集、阅读、编辑、搜索、对话及设置体验的剩余问题，给出有当前截图证据和明确优先级的修复建议。

## Background

- `master` 已包含 `codex/ui-ux-audit` 与 `codex/visual-redesign`。上一轮审查记录在 `.trellis/tasks/archive/2026-10/10-10-ui-ux-audit/audit.md`；整站改版目标记录在 `.trellis/tasks/archive/2026-10/10-10-visual-redesign/prd.md`。
- 用户要求“继续下一轮的 UI 审查”。本轮以改版后运行中的实际产品为对象；旧截图只用于确定复查范围，不作为本轮问题的直接证据。

## Requirements

- R1：实测网页端主要路径：登录、全局导航、知识库、文档阅读与编辑、搜索、对话、收集入口、设置及关键浮层。覆盖能在现有测试数据中到达的状态。
- R2：检查宽屏与窄屏、浅色与深色的布局、层级、文案、反馈与可访问性风险；至少复查上一轮指出的搜索、对话、知识库主操作、收集表单与设置层级。
- R3：每个结论必须绑定本轮截图及可复现步骤；区分确认的问题、视觉风险和无法覆盖的状态。
- R4：形成按影响排序的改进清单，并记录正常表现与证据边界。审查本身不修改产品代码。

## Acceptance Criteria

- [x] 本轮有顺序编号的有效页面截图，覆盖主要用户路径；截图与简短步骤说明保存在任务目录。
- [x] 报告逐步列出页面健康度，具体说明问题、影响、复现方式与优先级。
- [x] 宽窄窗口与浅深主题至少对核心工作区、设置和一个浮层完成实测；未覆盖的场景明确列出。
- [x] 报告将截图可见的可访问性风险与需要键盘或辅助技术验证的推断分开。
- [x] 最终回复内展示本轮关键截图，并给出完整报告位置。

## Out of Scope

- 直接修复或重设计产品界面。
- 真实收费模型调用、外部抓取、上传私人文件、生产数据更改。
- 将截图审查表述为完整的无障碍合规认证。
