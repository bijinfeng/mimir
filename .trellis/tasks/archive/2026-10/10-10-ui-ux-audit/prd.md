# 页面交互、视觉与文案审计优化

## Goal

让 mimir 的收集、查找、阅读、问答和设置更顺手、更好看；让界面文案像成熟产品一样简洁、准确，以内容和操作为主，不让解释性文字抢占页面。

## Background

- mimir 是单用户个人知识库，核心闭环是收集、整理、检索、使用、沉淀；网页和桌面端共用 packages/renderer。现行产品与视觉契约分别在 .trellis/spec/project/product.md 和 .trellis/spec/project/design.md。
- 2026-10-10 在隔离的本地 SQLite 数据目录中走查了登录、知识库、文档、搜索、对话、收集及设置全部九个网页分区；知识库检查了 1152、900、760、600 像素，设置检查了 760 像素。原始截图与逐步发现保存在 audit/ 和 audit.md。
- `.trellis/spec/project/design.md` §8.15 已要求不复述控件、不描述本页、不在主界面讲架构与实现理由；当前页面有回归。用户进一步要求从商业化产品角度精简各页面不合适和多余的措辞。
- 审计仅覆盖默认示例文档和无模型配置状态；桌面端、真实文件上传、外部网页抓取、有模型回答、屏幕阅读器尚未实测。

## Requirements

- R1：修正搜索面板中“按 Enter 提问”和“Enter 打开”的相互矛盾提示；键盘与鼠标操作应有一致且可预期的结果。多个命中可来自同一文档，结果标识需唯一，选中命中应帮助用户找到对应片段，而不只是打开文档顶部。证据：audit/04-search.jpg，packages/renderer/src/components/CommandPalette.tsx:352、:388、:529、:541；搜索命中契约已有片段起止偏移（packages/shared/src/search.ts:33）。
- R2：改善无模型时检索回答的呈现，让用户能先读到清楚的状态说明、再辨认检索到的原文及来源；避免正文与引用卡重复堆砌、Markdown 片段变成难读的密集文本。证据：audit/06-chat-answer.jpg，apps/server/src/services/assistant-stream.ts:246、apps/server/src/services/assistant.ts:286。
- R3：整理知识库顶部操作的层级与窄窗口换行，让“添加文档”等主操作在 600–900 像素宽度仍容易找到；保持卡片/列表、文件夹、文档的现有能力。证据：audit/11-library-900.jpg、audit/13-library-600.jpg，packages/renderer/src/components/library/LibraryView.tsx:433。
- R4：让收集链接输入有明确可访问名称，保留来源识别、目标知识库和失败反馈。证据：audit/10-capture.jpg，packages/renderer/src/components/CaptureDialog.tsx:334。
- R5：逐一审查当前可见的登录、侧栏与知识库、文档、搜索、对话、收集、设置全部九个网页分区，并代码审查桌面客户端专属分区的标题、按钮、占位、帮助、空态、状态、错误和成功反馈。删除重复状态、产品理念、实现理由、内部路径和无助于决策的长说明；改为简短、自然、动作明确的中文。`audit.md` 的“文案改写清单”是实施基线；运行时生成的服务端配置描述也要检查，不只改 JSX 静态字符串。文档阅读助手的完整使用指南按用户最新要求保留。保留主题 token、深浅色与浏览器/桌面共用边界。
- R6：保持设置的九分区、可分享的 `?section=` 和窄屏下拉；普通使用者先看到可操作设置与结果，插件注册表的 `seam`、源码路径等调试信息收进技术详情，不能再占据默认信息层。保留服务端注册表为数据来源，不新增假开关。依据 `.trellis/spec/project/architecture.md` §7.7、`design.md` §8.15；证据 `audit/14`–`21`。
- R7：修复设置页最影响观感的信息密度：模型未配置时突出添加动作并收起不可用角色行；存储选项把名称、选择和状态合成一行，测试动作靠近当前选择；零调用时不绘制全年空格热力图；外观说明与控件同组，账号登出收进账号面板的独立操作区。保留未知用量、切换存储不迁移文件等必要信息。证据与取舍见 `research/visual-audit.md`。

## Copy Rules

- 每处文字应帮助用户完成当前动作、理解状态或判断后果；没有这三种作用就删。按钮写动作，空态给下一步，错误说明失败和可执行的恢复动作；同一事实只出现一次。
- 保留有决策价值的事实：切换存储不会迁移已有数据；退订不删已收文章；重建索引不能恢复抓取件、对话和设置；完整备份需要数据库、内容文件与密钥；模型测试会产生真实调用；统计中的未知用量不能当作零；本地/云端切换不会迁移数据。
- 技术细节只在配置字段需要它才能填写、故障排查需要它才能继续、或用户主动展开“技术详情”时出现；不得改变产品真实能力或给出虚假承诺。

## Acceptance Criteria

- [x] 搜索有命中与无命中时，屏幕提示和 Enter 实际行为一致；鼠标有明确的“打开结果”和“提问”入口；同一文档多处命中不会触发重复 key 警告，选中结果能定位到对应片段。
- [x] 无模型检索回答在示例问题中无需阅读重复的长段落即可辨认“未调用模型”、命中原文及其引用；点击引用仍能跳到来源。
- [x] 知识库页在 1152、900、760、600 像素宽度无横向滚动，主操作不会被次要操作挤到难以发现的位置。
- [x] 收集链接输入在键盘与辅助技术下能被识别为链接输入；已有识别、校验与抓取流程仍可用。
- [x] 改动后的核心页面在浅色和深色外观中保持可读，浏览器与桌面共用组件不分叉。
- [x] 模型、存储、统计的空态和设置布局在浅色/深色、宽/窄窗口下有清楚的主次关系，不出现大片无意义空白或重复状态块。
- [x] 已走查范围内的文案完成逐屏清理，`audit.md` 中高优先级旧文案均已处理；文档阅读助手的完整使用指南保留，设置默认视图不出现 `seam:`、源码文件路径、`DATA_DIR` 等内部术语，必要的风险和备份信息仍容易找到。
- [x] 相关行为检查、类型检查及项目规定质量门禁通过，并完成实测页面复查。

## Out of Scope

- 改变内容存储、检索算法、模型供应商配置或 Office 编辑能力。
- 手机专用界面；产品契约明确移动端另行设计。
- 全量屏幕阅读器认证、真实外部抓取、有收费模型账号下的全面端到端测试；实施时验证可控制的路径，并记录未覆盖部分。
