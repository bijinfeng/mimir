# UI 审查问题修复 F1–F19

## Goal

逐项消除 [审查报告](../10-10-ui-interaction-audit/audit.md) F1–F19 记录的交互缺陷与高频笔记流程断点，使鼠标、键盘与窄窗口下的行为可信且连续。F20–F22 由独立的 Markdown 头部任务实现；用户要求该页头部、工具栏、内容区域三个区域不变。

## Scope and acceptance

| ID | 必须达到的可观察结果 |
| --- | --- |
| F1 | “丢弃改动”不会留下刚输入的内容；自动保存和离开确认不再给出互相矛盾的选择。覆盖保存完成与保存中的竞态。 |
| F2 | 编辑器提示在 macOS 显示实际生效的 ⌘ 组合，在 Windows/Linux 显示 Ctrl 组合。 |
| F3 | 路由切换、Esc 和外点击都能关闭账号菜单与主题子菜单，焦点回到合理位置。 |
| F4 | RSS 地址在客户端得到具体、字段旁的格式错误；服务器错误仍说明可修正原因。 |
| F5 | 账号名称和 S3 表单未保存草稿在切换分区／折叠后保留，或在明确丢弃前提示。 |
| F6 | 供应商表单提交错误时聚焦首个错误，字段标记 `aria-invalid` 并关联错误文本。 |
| F7 | 关闭重命名、文档问 AI、窄屏导航和知识库收集弹窗后，焦点返回触发入口或当前视图主入口。 |
| F8 | 600px 侧栏打开时背景不可点击、不可 Tab 进入；关闭时焦点恢复。 |
| F9 | 无 hover 的窄屏／触屏卡片仍有可见的主要操作或“更多”入口。 |
| F10 | 文档问 AI 的范围文案准确说明默认是当前文档且用户可调整。 |
| F11 | “已收录”计数与未删除文档一致，回收站条目不计入；现有检索结果不回归。 |
| F12 | 六个 S3 输入和路径风格开关有程序化可访问名称。 |
| F13 | 新建笔记后可直接键入标题或正文，不需先点编辑区。 |
| F14 | 编辑页中能从持续可见的现有导航区域切换最近打开的笔记，并看清当前笔记位置；不改动头部／工具栏／内容区域三块结构。 |
| F15 | 全局搜索空查询列出最近打开的笔记，可用方向键与 Enter 打开。 |
| F16 | 全局命令入口支持当前笔记重命名、移动、返回知识库等常用操作，未匹配命令时不会误导为 AI 提问。 |
| F17 | 在笔记中可用 `[[` 或工具栏“链接”查找已有笔记并插入内部链接；链接可从正文打开，返回后能找回编辑位置。 |
| F18 | 文件列表显示目录归属，子目录标题／面包屑明确当前位置；移动成功有可见反馈和可撤销路径。 |
| F19 | 删除笔记文案准确区分移入回收站与永久删除，不同时说“不可撤销”。 |

## Constraints

- 保留现有文档、设置和会话数据；测试只用隔离审查环境与可逆样本。现有用户信息不可被自动重置。
- 维护浏览器与桌面端共用的 renderer 行为；真实触屏验证如设备不可用，要明确用模拟与代码检查的边界。
- 不引入未配置模型调用、外部抓取或付费请求。菜单、搜索与互链要遵循现有可访问性及主题 token。
- 对 F14–F18 以满足任务流程的最小完整能力实现，不以占位按钮或纯文案替代。
