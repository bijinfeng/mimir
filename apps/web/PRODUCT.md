# mimir Web Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

在浏览器中管理个人笔记和资料的单个使用者。使用者登录自己的 mimir 实例，从不同设备访问同一份服务器知识库。

## Product Purpose

让使用者收集资料、写笔记、整理与检索知识，并通过带原文引用的 AI 问答重新使用已保存的内容。成功意味着资料容易入库、需要时找得到、回答可以核对来源，并且原件与知识数据由使用者掌控。

## Positioning

mimir 是单用户、自托管的个人知识库。浏览器端直接连接使用者部署的服务，围绕“收集 → 整理 → 检索 → 使用 → 沉淀”的闭环组织笔记、资料和带引用的问答，而不是公开展示网站。

## Operating Context

- 使用者通过浏览器访问自部署的 mimir 服务并登录；服务器保存知识库数据。浏览器端没有桌面客户端的本机离线模式。
- 知识库是内容主容器；使用者在其中创建笔记、上传文件、收集网页资料，借助文件夹、标签和搜索整理与查找内容。
- 阅读和编辑内容、查看原件、检索知识库及带引用的 AI 对话都在同一工作区完成。AI 问答依赖所配置模型的可用性。
- `apps/web` 是浏览器入口与构建壳；主要界面和业务代码在 `packages/renderer`，与桌面端本地模式共用。

## Capabilities and Constraints

- Markdown 笔记可编辑；上传文件保留原件，支持的格式可预览、提取正文供检索，并在已实现的范围内编辑。
- 知识库问答提供指向真实原文位置的引用；检索结果应帮助使用者找到已经保存的内容。
- 浏览器端使用服务器账号和数据，不将浏览器缓存当作独立的离线知识库。
- 产品面向单个使用者，不提供团队权限、公开发布、完整任务管理或知识图谱可视化。
- 产品边界和用户可见行为的现行契约以仓库的 `.trellis/spec/project/product.md` 为准；此文件是浏览器端设计工作的简明上下文。

## Brand Commitments

- 产品名称为 `mimir`。
- 使用仓库已有的品牌标识与图标；浏览器端和桌面端共享主工作区的产品身份。

## Evidence on Hand

- 用户于 2026-10-15 确认了浏览器端是登录后的自部署个人知识库，不含桌面端本机离线模式，也不是公开展示网站。
- 产品契约：`.trellis/spec/project/product.md`，尤其是 §1、§2、§4 和 §5。
- 浏览器入口：`apps/web/src/index.tsx`；共享工作区：`packages/renderer/src/main.tsx` 与 `packages/renderer/src/routes/`。
- 浏览器壳规则：`.trellis/spec/web/frontend/conventions.md`；品牌图标：`apps/web/public/favicon.svg`。

## Product Principles

1. 降低资料收集和笔记写作的阻力，让内容真正进入知识库。
2. 让保存的内容容易找回、引用和核对，支持从资料到结论再到笔记的闭环。
3. 让用户始终明白内容属于自己的服务器知识库，避免暗示存在独立的浏览器离线副本。
4. 保持浏览器与桌面端共享工作区的行为一致，只在平台能力确有差异时区别处理。
