# mimir 交互原型

单文件静态原型，双击 `index.html` 打开。无构建、无依赖、不联网。

顶部深色控制条是原型专用的，不属于产品 UI。
布局与编辑器已定（三栏 + 所见即所得），控制条上只剩「故障演示」用来触发异常状态。

## 已确定的决定

- **布局 A（三栏）**：左导航 / 中列表 / 右内容
- **会话优先导航**：新对话 + 会话历史（按日期分组）排在文档入口之前
- **树 + 标签并存**：树管归属（唯一位置），标签管横切（可多个）

## 会话优先带来的结构变化

不只是把「新对话」挪到最上面，中间栏的语义也跟着变了——它变成**上下文相关**的：

| 模式 | 中间栏 | 右栏 |
|---|---|---|
| 对话 | 本次引用了哪些文档 | 对话（含可折叠的检索过程） |
| 文档 | 文档列表 | 阅读 / 编辑 |

这个设计的理由：会话优先意味着「问答」是主场景，那么**「它读了什么」就应该和「我有什么」一样可见**。
引用不再是回答下面的一行小字，而是占据整列。

## 借鉴自 WeKnora 的三处

1. **检索过程可折叠**（AI 回答上方）：思考 N 轮 · 调用 M 次工具 · 耗时 Xs，展开是逐步记录。
   个人知识库里这条比在企业里更重要——AI 说「没找到」时你能分辨是没存过还是分词没匹配上。
2. **文档底部列出「来源」和「被引用」**：让双链是双向的。
3. **区分「手动编辑」和「AI 整理」**：标注内容是人写的还是机器生成的。

| 操作 | 看什么 |
|---|---|

| 左导航点收件箱/标签/目录 | 切到文档模式 |

## 本轮改动

1. **AI 两个入口拆开**：主视图 = 全局问答；侧栏 = 就当前这篇文档提问，不离开阅读位置
2. **补上「存成笔记」**：AI 回答下方有动作条，存下的笔记保留引用来源
3. **新对话的中间栏不再空着**：直接列待整理收件箱——启动新对话最典型的动机
   就是「我刚收了几篇东西，想问问」
4. **新增设置页**（左导航底部），六个分区
5. **插件注册表可视化**：设置 / 插件，按接缝分组

## 设置页与插件架构的关系

设置页不是一堆散落的表单，而是**插件注册表的人类可读视图**：
每一行「可配置的东西」都对应一个注册进接缝的实现。

```
接缝 seam        实现 plugin
──────────────────────────────────────────────
capturer    →  粘贴链接 / RSS / 公众号 / GitHub / Star 同步 / 浏览器扩展
parser      →  Markdown / HTML 正文提取 / PDF / Word
leg         →  关键词(jieba) / 子串兜底(pg_trgm) / 向量(M1) / 重排序(M1)
provider    →  DeepSeek / 通义 / 智谱 / Ollama
```

加一个新来源＝新增一个文件并注册，不需要改动检索、存储或界面代码。
`src/search/legs.ts` 已经是这个模式（两条 leg 共用一个形状）。

## 本轮补齐：从「只有成功路径」到覆盖一整天

### 1. 保存状态与未保存保护

工具条常驻「正在保存… / 已保存 / 保存失败 · 点此重试」。正文可直接编辑，
输入即触发保存周期。

离开未保存的内容会被拦截，给三个选项而不是两个：
**继续编辑 / 丢弃改动 / 保存并离开**。

「保存并离开」在保存失败时**不会放行**——否则用户以为存上了，实际上丢了。

### 2. 模型侧失败路径

四类失败各自回答三个问题：这次花钱了吗、内容丢了吗、换个做法有没有用。

| 失败 | 出路 |
|---|---|
| 额度用尽 | 改用别的模型 · 去充值 · 只看检索结果 |
| 请求超时 | 重试 · 缩小到当前文档 · 拆成小问题 |
| 回答被截断 | 继续生成 · 只要结论 · 输出到笔记里继续写 |
| 网络不可达 | 只用检索不调模型 · 重试 · 改用本地模型 |

统一给一个「重试」等于把判断推回给用户。

### 3. 文档大纲

右侧锚点导航，滚动联动高亮，标题数 ≥ 2 才出现——
两段话的笔记不需要目录，常驻只是白占 200px。

## 怎么试这三条

顶部控制条多了「故障演示」一组：

- **保存失败** → 在正文里敲几个字，看指示器变红；再点别的文档，看拦截框
- **额度用尽 / 超时 / 被截断 / 离线** → 往当前对话注入对应的失败状态
- 正文里能直接打字，改完看大纲是否还在正确位置

## 删掉了 AI 侧栏

侧栏存在的理由是「不离开阅读位置就能问」，但这个诉求被两头夹掉了：

- **问某一段** → 内联工具条的「就这段提问」，锚定选中内容，比侧栏精确
- **问整篇** → 主视图对话 + 范围选「当前文档」

侧栏范围比内联宽、比主视图窄，两边都不如。删掉换来 392px 屏幕和一个不用维护的面。

删除后补了三件事，否则「问当前文档」会比以前更难：

1. **文档工具条「问 AI」** → 带这篇的上下文进主视图，范围自动锁到当前文档
2. **内联「就这段提问」** → 同上，并把选中的话作为引用预填进输入框
3. **「返回对话」** → 从对话点引用跳去文档后，文档顶部出现返回入口。
   没有它，用户会以为对话没了。

## 已定方案

- **布局**：三栏。左导航（会话优先 + 知识库 + 目录 + 标签）/ 中列表 / 右内容
- **编辑器**：所见即所得。不做源码模式，不做双模式切换
- 另一套布局与源码视图的代码已从原型删除，不留死代码

## 所见即所得的一个已知性质

Tiptap **不是无损的，但是幂等的**。实测（`apps/web/src/editor/drift.test.ts`）：

```
输入      | 1 | 2 |
首次保存  | 1   | 2   |     会被整理成编辑器的规范形
之后每次  | 1   | 2   |     不再变化
```

意义：

- **可以**作为唯一编辑器 —— 内容不会逐次劣化
- **不要**用别的工具（Obsidian / VS Code）改同一批文件 ——
  两边各有一套规范形，来回改会产生大量无意义的 diff

正文、标题、列表、代码块、引用、链接往返均逐字节一致；
表格是唯一会被重排的结构，属于 Markdown 表格排版的正常行为。
